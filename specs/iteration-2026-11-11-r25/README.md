# R2.5 · 模型分层：事件触发收敛 + NPC 系统重构

用户 2026-11-11 裁决：**先把「配置 / 实例 / 事实」三层梳理清楚再编码**，因为「现在的事件和 npc 有很多混杂在一起」。本迭代是**规格轮**（W3），只产出需求与设计，不改实现代码。

## 用户原始裁决

1. **事件模型**：轮次槽位唯一；触发二分为立即触发（不入队、下一轮触发，模板协议层限制仅一个）与延时触发（按时间窗开始入队、出队时判定、排序 = 开始 asc ＞ 结束 asc（空视为最大）＞ 入队序）；模板可写固定时间段或相对时间；退役「x 轮后触发」；立即触发仅 `action_trigger` / `chain`；`schedule` 初始化即入队；`pool` 保持最后触发且只能产出延时事件；**延时事件丢失导致的断链，必须在链状态判定时检查时间队列**。
2. **NPC 系统**：投影与生命周期解耦（开局已死亡的重要角色也能上屏）；生命周期 `spawn → alive → dead` 决策生成/行动跳过/事件触发/参战，**默认判活、模板不写**，且不与业务语义耦合（失联也是 dead）；年龄由出生时间动态计算，**三种时间模型默认都要支持**；关系不止好感度，还有亲属/朋友/师徒/自定义，亲属与师承由「记录双亲 / 师父」推导。

# 需求：表现层（叙事追加 / 本轮收获 / 样式体系）

> 写法沿用 EARS。每条需求都有编号、验收标准、追溯（设计 / 任务）。编号一旦发布不重排；
> 本轮不做的整条标 `DEFERRED`，保留原文。

## 0. 术语

| 术语 | 含义 |
|---|---|
| **叙事段** | 一回合对应的玩家可见正文（一段或几段散文），按 `turnIndex` 追加进叙事流。 |
| **本轮收获** | 一回合内**实际发生**的效果清单（属性增减 / 补正得失 / 技能习得 / 物品与装备变动）。 |
| **效果摘要** | 由定义（技能 / 物品 / 装备 / 补正）**派生**的展示用条目，不是结算结果。 |
| **样式** | 一组受控的视觉参数（颜色 / 加粗 / 背景 / 预设动画），模板只能引用 id 或白名单值。 |
| **固定效果** | 无「数值增减」形态的控制类效果（如「无法行动」`cannot_act`）。 |

## 1. 叙事区（R-NAR）

### R-NAR-01 每回合追加叙事段（ACTIVE）

**当**一回合完成结算（自由行动 / 事件选项 / 转盘确认 / 战斗结束 / 物品使用）时，
**系统应当**向叙事流追加**恰好一条**该回合的叙事段，并保留此前所有回合的段落。

验收：

1. 连续推进 3 回合后，带 `fromTurn=0` 的叙事读回包含 3 条叙事段，`turnIndex` 严格递增。
2. 叙事段文本优先级：LLM 产出的正文 > 模板合成的正文；两者都没有时**不写空段**。
3. 没有 LLM（mock / 模板）时仍然产出叙事段（内容取自事件/行动本身，不是占位符）。
4. 叙事段**不得**包含 `hidden` 事实或越窗引用（沿用写侧窗口校验）。
5. 开局 `commit` 产生的那条「世界已建立」不计入回合叙事段（第 0 轮由开局面板承担）。

### R-NAR-02 流式呈现统一（ACTIVE）

**当**一条叙事段进入叙事流时，**系统应当**用同一种逐字呈现方式展示它，
**无论**该段来自 LLM 流式输出还是模板兜底文本。

验收：

1. 有 LLM：SSE 草稿逐字出现，收尾后正式段**不重复打字**（沿用既有 `instantTurn` 规则）。
2. 无 LLM：正式段以同样的节奏逐字出现（客户端本地假流式），**不得**整段瞬现。
3. 「AI 书写中…」标签只在真的有 LLM 请求在飞时出现；模板段不显示该标签。
4. 两种来源的正文样式（字号 / 行距 / 段落间距）一致。

## 2. 本轮收获（R-GAIN）

### R-GAIN-01 收获卡替换「命运落定」（ACTIVE）

**系统应当**把转盘落定位置的结算卡改为「本轮收获」，
**当且仅当**该回合产生了可列出的增量时展示。

验收：

1. 自由行动、正常事件、转盘、战斗、物品使用回合结束都能出现该卡（不限于转盘）。
2. 该回合没有任何增量（例如纯等待）时不出现该卡，改为既有「世界平静地流转着」提示。
3. 卡片标题为「本轮收获」；不再出现「命运落定」字样（转盘动画内的措辞不受影响）。
4. 刷新页面后该卡消失（一次性呈现，不写进权威状态）。

### R-GAIN-02 收获条目的分类与正负号（ACTIVE）

**系统应当**按类别列出增量，并对数值增减显式标注 `+` / `-`。

验收：

1. 类别固定为：属性、补正、技能、物品、装备（本轮不含关系 / 旗标）。
2. 属性条目形如 `咒力 +2`、`生命 -15`；正负分色（增益 / 减益两种视觉）。
3. 补正条目区分**获得 / 失去**，并带层数（如 `术式·十种影法术 ×1`、`重伤 -1`）。
4. 技能 / 物品 / 装备条目只列名称与数量变化（`获得` / `失去` / `装备` / `卸下`）。
5. 同一类别内不重复：同一条属性多段变化合并为一个净值。

### R-GAIN-03 收获条目可交互（ACTIVE）

**当**玩家点击收获里的技能 / 物品 / 装备 / 补正条目时，**系统应当**展示该实体的详情
（与 R-DETAIL 系列同一套详情面）。

验收：

1. 可点条目有明确的点击态（hover / active），可键盘聚焦并回车打开。
2. 详情内容与「个人」页签里的同类详情一致（同一组件、同一数据来源）。
3. 关闭详情后回到原位置，不丢失本轮收获卡片。

## 3. 详情展示（R-DETAIL）

### R-DETAIL-01 装备详情显示效果（ACTIVE）

**系统应当**在装备详情中展示其效果：静态补正（属性 / 战斗面）与动态补正**规则描述**。

验收：

1. 固定值补正如 `咒力 +4`；按比例补正如 `咒力 +3（随咒力成长，20%/点）`。
2. 战斗面效果（命中 / 伤害 / 减伤）与仿真面效果分开分组。
3. 动态补正**不展示**具体计算结果（随上下文变化），只描述规则与取值依据。

### R-DETAIL-02 消耗品详情显示效果（ACTIVE）

**系统应当**在消耗品详情中展示其效果（治疗 / 伤害 / 施加补正 / 移除补正 / 恢复资源）。

验收：

1. 每条效果一行，带数值或公式的人话表达。
2. 施加补正时链接到补正名称（可点开补正详情）。
3. 材料 / 关键物品没有效果时不显示「效果」分组（不留空标题）。

### R-DETAIL-03 技能详情显示效果（ACTIVE）

**系统应当**在技能详情中展示：消耗、目标、命中判定、伤害 / 治疗公式、施加补正、
消耗补正、冷却。

验收：

1. 战斗技能与通用技能用同一套分组，缺项不显示。
2. 公式以人话表达（`1.2 × 咒力` 而非 DSL 原文）。
3. 施加的补正可点开其详情。

### R-DETAIL-04 补正详情显示效果（ACTIVE）

**系统应当**在补正详情中展示：层数、持续时间 / 移除条件、仿真面效果、战斗面效果、
控制语义、来源说明（description）。

验收：

1. 仿真面属性补正逐条列出（`咒力 +4`）。
2. 战斗面列出控制 / 伤害 / 命中 / 每回合效果。
3. `untilCured` 显示为「持续到被移除」，`turns` 显示剩余回合。

### R-DETAIL-05 补正详情为毛玻璃浮层（ACTIVE）

**当**玩家点击任意补正（个人页签 / 收获卡 / 事件区）时，**系统应当**以毛玻璃效果
（背景模糊 + 半透明）的浮层展示 R-DETAIL-04 的内容。

验收：

1. 浮层覆盖当前页，背景可见但模糊；点击遮罩 / 关闭按钮 / Esc 关闭。
2. 浮层内文字对比度满足深色主题可读（不因模糊导致糊字）。
3. 同一时刻只开一个补正浮层。

## 4. 样式体系（R-STYLE）

### R-STYLE-01 模板声明样式并可渲染（ACTIVE）

**系统应当**允许模板在补正 / 技能 / 物品 / 装备上声明 `style`（样式 id），
并由前端按解析后的样式渲染其名称（列表、详情、收获卡、战斗面板一致）。

验收：

1. 同一实体在任意出现面（个人页签、收获卡、事件区、战斗面板）呈现同一套样式。
2. 未声明样式时回退到现有默认样式（零视觉回归）。
3. 样式不影响任何判定与结算。

### R-STYLE-02 引擎预设样式（ACTIVE）

**系统应当**内置一组预设样式，模板只需声明 id（如 `style: rainbow`），
不要求模板自己写颜色值。

验收：

1. 至少提供：`rainbow`（流动彩虹）、`gold`、`silver`、`bronze`、`crimson`、`azure`、`jade`。
2. 预设的 CSS 由前端/组件库提供，模板侧只出现 id。
3. 未知 id 在加载期报错（拒绝静默回退），错误信息包含实体 id 与字段路径。

### R-STYLE-03 品质 → 样式映射（ACTIVE）

**系统应当**允许模板声明「品质 → 样式」映射（如最高品质 `mythic` → `rainbow`），
使所有该品质的实体自动获得该样式。

验收：

1. 映射写在展示域（`ui.yaml`），不进语义指纹，改样式不让旧档拒载。
2. 实体自身声明了 `style` 时以自身为准；否则按 `quality` 查映射；都没有则默认样式。
3. 补正 / 技能此前没有 `quality` 字段，本轮补齐（可选字段）。

### R-STYLE-04 自定义样式的最小词汇（ACTIVE）

**系统应当**允许模板在不写任意 CSS 的前提下自定义样式，词汇限于：
`color`、`background`、`bold`、`animation`（预设动画 id）。

验收：

1. `color` / `background` 只接受 `#rgb` / `#rrggbb` / `#rrggbbaa` 或引擎颜色 token。
2. `animation` 只接受预设枚举（如 `rainbow-flow` / `pulse` / `none`）。
3. 任何含 `;`、`{}`、`url(`、`expression` 的值在加载期拒载。
4. 模板自定义样式同样只影响展示。

### R-STYLE-05 样式的可访问性兜底（ACTIVE）

**当**玩家开启「减少动效」时，**系统应当**停用样式里的动画，但保留颜色 / 加粗。

验收：

1. `prefers-reduced-motion: reduce` 下动画全部静止。
2. 文字颜色与背景对比度不因动画停用而变化。

## 5. 固定效果（R-FX）

### R-FX-01 固定效果下划线（ACTIVE）

**当**效果列表里出现控制类固定效果（`cannot_act` / `cannot_use_skills` / `cannot_use_items` /
`cannot_attack` / `cannot_flee` / `forced_target_self`）时，**系统应当**以下划线呈现其文案
（如「无法行动」），与数值型效果区分。

验收：

1. 数值型效果不加下划线；固定效果加下划线（`text-decoration: underline`，可用点线）。
2. 下划线元素可聚焦并有 `title` / `aria-label` 说明其含义。
3. 同一控制语义的中文文案在引擎侧统一维护（不散落在各前端）。

## 7. DEFERRED（登记不实现）

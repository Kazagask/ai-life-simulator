## 0. 四个决定

### 决定一：线是纵切，不是平行宇宙

六条线共享同一条时间轴。`主线` 决定「现在几点、世界发生了什么」，`角色线` 决定「你和这个人之间欠了什么」。
两条线在**门事件**处交汇，而不是各自复制一份 2018 年。

这样做的原因很实际：6 条线 × 每条 3 个分支 × 12 年，如果做成平行时间线，事件量会指数爆炸；
做成纵切，同一幕可以同时服务主线与角色线，只是**判定读的 flag 不同**。

> 设计判断：分支树只存在于**每条线的幕内**；线与线之间用 flag 门 + 机会成本，不用复制剧情。

### 决定二：救人要付账

每一次改写 canon，都写一条 `debt.*`。这个债不是数值惩罚，是**后面某一段剧情变贵**：

| 你救下 | 立刻得到 | 后面要还的账 |
| --- | --- | --- |
| 天内理子 | 夏油崩得慢；理子长线开启 | **canon 链断在第一环**：星浆体仍存在 ⇒ 天元不必咒灵化（§6.0）；盘星教改追杀她；2017 羂索多一枚筹码 |
| 夏油杰（拦下） | 百鬼夜行不发生；夏油可成为同伴 | 羂索另找古代术师宿主 ⇒ 涩谷没有「伪夏油」，但狱门疆仍会被用；夏油本人有二次崩坏风险 |
| 灰原雄 | 夏油多一个锚 | 灰原活到 2018，大概率死在涩谷；玩家要为他负责 |
| 五条悟（不被封印） | 2018 难度骤降 | 羂索改打天元、提前开死灭回游；五条在场会让所有角色线失去张力 ⇒ 必须用「被支开 / 结界隔绝」限制 |
| 虎杖悠仁（不死刑） | 主线继续 | 宿傩契约的利息；高层敌意转嫁到玩家 |
| 伏黑惠（不被夺舍） | 新宿好打很多 | 宿傩换容器（虎杖）⇒ 更糟 |

这张表是「没有完美路线」的保证。任何一条线的「最优解」，都要在另一条线上付账。

### 决定三：约束加在状态上，不加在文案上

分三层看，只用前两层：

| 层 | 管什么 | 手段 | 可靠性 | 本设计 |
| --- | --- | --- | --- | --- |
| **状态层** | 能不能选 | flag / `trigger.conditions` / `visibleWhen` | 确定，写死在模板里 | ✅ 主手段 |
| **事实层** | 它知道什么 | 一句**自然语言**场景简报（时间 + 在场者） | 高，成本三行 | ✅ 辅助 |
| **文本层** | 写得对不对 | 关键词/语义审查、judge 模型 | 低，误杀高 | ❌ 不做 |

不做文本层，理由不是懒得做，是**它判不准**：ban「天元同化」，模型写「拒绝天元同化」——
这句话恰恰是正确的，却被共现规则杀掉；要真判语义就得再起一个 judge 模型对抗，
延迟和成本翻倍，judge 自己也会错。

而 LLM 的输出本来就不进权威状态（R2.7：`generateNarrative` 只做叙事装饰，模板兜底），
所以「写飞了」的最坏后果是**一段坏文案**，不是**世界被改坏**。
坏文案可以重生成/忽略，世界坏了要回档——两者的修复成本差两个数量级。

### 决定四：性格改「讲法」，不改「结果」

古代线的三条执念（审判 / 热情 / 求败）不是技能，是**三种性格**。它改三件事：

1. 旁白语气（给 LLM 的一句话设定）；
2. 态度选项开合（`visibleWhen: temper`）；
3. 同一个结局被理解的方式（同一句话，三种人读出三种意思）。

它**不改**判定、数值、事件顺序。

理由：人生模拟器问的是「你成了什么人」，不是「你有多强」。性格若能改判定，它就变成第二套 build；
性格若只体现在数值上，玩家看不出自己已经变了。所以性格只许改**看法**——
转盘定结果、选项定立场、性格定你站在哪个立场上看。

## 1. 素材、口径与边界

### 1.1 用了什么、怎么用

| 类别 | 来源 | 用法 | 不做什么 |
| --- | --- | --- | --- |
| 设定/百科 | 萌娘百科、维基、官方公式书 | 校对年龄、术式名、领域名、组织关系、日期 | 不把百科的「趣闻」当正史 |
| 原作 | 怀玉·玉折、0 卷、本篇（涩谷/死灭/新宿） | 事件顺序、因果、角色动机 | 不逐格复刻分镜与台词 |
| 作者访谈 | 芥见下下访谈、公式书 Q&A | 校准角色语气与「作者想说什么」 | 不编造引文；拿不准就不写 |
| 同人 | 番茄同人作品 | 只做**读者期待校准**（哪些留白已被写烂、哪些方向没人碰） | 不采用同人设定、不抄句子 |

> 版权边界：本设计只产出**结构、因果、状态机、留白约束**，不产出可发表的正文；
> 实施阶段由模板写手/LLM 重新写词，不复用原作台词。

### 1.2 三级事实

这是后面所有「留白」和「校验」的基础。三类事实的权限完全不同：

| 级别 | 定义 | 例子 | 谁能改 |
| --- | --- | --- | --- |
| **硬事实** | 原作钉死、改了就 OOC 到无法解释 | 理子 14 岁、廉直女学院初二；五条 2006 是二年生；甚尔无咒力；宿傩是虎杖体内的受肉 | 只有**玩家重大分支 + 明确代价**能改（如救理子） |
| **倾向** | 原作性格与行为逻辑，可被玩家的长期介入改变 | 夏油「保护非术师」的信念会裂；五条用「最强」隔离自己；虎杖把自己当零件 | 玩家可以推，但要花回合、要付代价 |
| **留白** | 原作没写、也不影响骨架 | 理子隐居时叫什么名字；灰原出任务前吃什么；日车当律师时输过哪场官司 | LLM 自由填；需要跨幕一致的少数几处由模板写死（§7.6） |

### 1.3 三处主动偏离（并说明为什么）

1. **玩家是同班同学。** 原作没有这个人。因此所有 canon 事件都要给玩家一个「在场理由」：
   同行、后勤、被支开、事后赶到。设计上不允许「玩家恰好路过」这种廉价安排。
2. **允许救理子/拦夏油。** 原作不可能。代价是：天元线、羂索线、2017/2018 都会变得更贵。
3. **死灭回游用蒙太奇。** 原作 19 天 × 10 结界，如果连续 40 回合打同一个结界，人生模拟的节奏会死。
   改成「殖民地蒙太奇」：每个结界 1-2 个 beat，规则用广播卡片推进。

> 明确不做：时间穿越。古代线是**咒物记忆 / 受肉闪回**，不是玩家回到平安时代。
> 这与 R3「时间穿越」的既有 DEFERRED 裁决不冲突（ADR-0005 的 seam 仍留着）。

> 口径小问题：当前模板写「2019 年初，你二十七岁」，但 `startYear: 2006` + 4755 天 = 2019-01，
> 2006 年 16 岁的人到 2019 是 28-29。建议统一成「二十八岁」或不写死年龄。见 §9。

### 2.2 九年空白怎么过

2007 秋到 2016 冬是 9 年，原作几乎是空白。这里不能硬写 300 个日常，用三层：

1. **年度蒙太奇**（8-10 beat）：每年 1 个 20-40 字的镜头 + 1 个选择，推进关系与 flag。
   例：2010「理子考大学」，2012「五条开始带学生」，2014「盘星教在某地扩张」。
2. **角色线插曲**（每人 2-3 个）：只在对应角色线开启时出现，给专属承诺。
3. **池事件**（20-30 个）：低概率日常，负责「这一年不是空白」的体感。

蒙太奇不是「跳过时间」，是**用最小的回合数换最大的因果**。每个 beat 必须至少改一个 flag，
否则删掉——这条要写进验收。

### 2.3 世界方向（phase）

`phase` 不是新增状态字段，是从 flags + 时间派生出来的只读值（见 §7.2）：

```
P0 opening → P1 hidden_inventory → P2 aftermath → P3 fracture
→ P4 interlude → P5 zero → P6 main → P7 culling → P8 finale
```

每个 phase 有：
- `allowedCasters`：这一幕允许出场的人（防「2017 出现虎杖」）；
- `publicKnowledge`：社会对咒术的认知程度（涩谷后公开化）；
- `powerCeiling`：这一幕能出现的咒灵/术师上限（防 LLM 造特级）。

## 3. 故事骨架

### 3.1 一条主脊：唯一的证人

原作里，五条被封印、夏油死了、理子死了、灰原死了、日车死了、虎杖被通缉。
**只有玩家从 2006 活到 2019。**

所以这条主脊不是「打败宿傩」，是：**你记得所有人**。
结局的差异不在于「谁赢了」，而在于「你还记得谁、你为谁付过账、你最后站在哪」。

> 设计判断：这条主脊让「玩家不是主角」变成优势，而不是缺陷。
> 玩家不需要比五条强，玩家只需要**在场**。

### 3.2 拓扑

```
时间 ─▶

2006 ──── L1 怀玉 ─────────────────────────────┐
          │  ├─ 理子死（canon）                 │
          │  ├─ 理子活 ──→ 理子长线（2007-2018）│
          │  └─ 理子同化 ──────────────────────┤
2007 ──── L2 玉折 ─────────────────────────────┤
          │  ├─ 夏油走（canon）──→ L3           │
          │  ├─ 夏油留 ─────────→ L3'          │
          │  └─ 夏油死 ─────────→ L3''         │
2008-16 ── 年度蒙太奇（角色线并行生长）─────────┤
2017 ──── L3 0 卷 ─────────────────────────────┤
2018 ──── L4 高专线 ─┬─ 涩谷 ── 死灭 ──────────┤
          L5 咒灵线 ──┤                        │
          L6 古代线 ──┴─ 死灭回游 ─────────────┤
2019 ──────────────────────────── 收束（结局族）┘
```

### 3.3 线、分支、链：三者别混

| 概念 | 是什么 | 现行语法 | 参与调度？ |
| --- | --- | --- | --- |
| **线（line）** | 叙事归属：这一幕属于哪条线、第几幕、给谁看 | **只做 `eventId` 命名约定**（`ev-hv-05`），不是协议字段（§8.1） | 否，只读 |
| **分支（branch）** | 一段剧情的多节点，展开成普通事件 | `branch:` + `goto` + `after` + `as`（SPEC §2.5） | 是 |
| **链（chain）** | 延迟队列的调度器 | `chains:`（startEventId + steps） | 是，**只做调度** |

> 不要把 `chains` 当叙事线用。它是「过一会儿演下一幕」的队列，
> 拿它承载「这条线现在到第几幕」，就是 SPEC §4.9 明确禁止的「投影时间队列」。

### 3.4 机会成本：时间是唯一稀缺资源

这是整个设计的核心循环，也是「不能全都要」的机制：

| 2007 夏，你有 3 个回合 | 去了这里 | 就错过 |
| --- | --- | --- |
| 去村庄找夏油 | L2 主线推进，可能拦下他 | 灰原的最后一个任务（他死时你不在） |
| 陪灰原出任务 | 可能救下灰原（`debtHaibara`） | 夏油独自面对村庄，崩得更快 |
| 陪理子隐居 | 理子线推进，她的信任 +1 | 夏油和灰原都失去你的介入 |

实现方式：每个幕有 `window`（时间窗）+ `timeCost`，错过写 `missedEvents`，
并在后面的角色线里读 `missed` 计数（「你那年没来」）。**不需要新机制**，现有 `window` / `timeCost` / `missWhen` 就够。

> 设计判断：分支的乐趣不在「选哪个」，在「选完之后真的失去了另一个」。
> 所以每个线的高潮幕都要和其它线的高潮幕**撞在同一周**。

### 3.5 推进靠转盘，选项是例外

**默认推进方式是加权转盘（`settle: random`），不是选项。** 选项多了会变成视觉小说；
转盘把「努力」和「运气」分开——**选项定方向，转盘定结果**。

只在这两种情况下给选项：

1. **态度题**：需要玩家凭自己的感觉表态——救不救、说不说、跟谁走、认不认这个身份。
   这类没有正确答案，只有「你是什么人」；
2. **关键岔口**：阵营、叛逃、生死、以及会写 `debt.*` 的改写。**每幕最多一个**。

其余全部 roll。同一条线里，玩家大概每 2-3 幕才点一次选择，中间靠转盘推进。

| 用转盘 | 用选项 |
| --- | --- |
| 战斗结果、伤势、被谁发现、赶上没赶上、术式觉醒没觉醒 | 救不救理子 / 拦不拦夏油 / 站高专还是站诅咒师 |
| 日常幕的「这周发生了什么」 | 「你要不要说出你知道的未来」 |
| 稀有奖励（隐藏线、稀有物品、额外回合） | 最终归属（谁活下来不能 roll 决定） |
| **日车审判：抽到什么罪**（§5.7.1） | **日车审判：你怎么辩解** |

> 同一幕里两种混用的样板是日车审判：**抽罪 roll（世界的事实）、辩解选项（玩家的意图）**。
> 这不是「一半一半」，是分工——凡是「玩家不能决定、但必须承受」的东西，一律 roll。

三条硬事实（2026-11-19 读 schema，别写错）：

- 转盘扇区只有 `weight` + `weightBy`（`WheelSegmentSchema`），**权重只能被属性调制，不能被 flag 调制**。
  要「随世界进度改概率」，就**拆成两个事件**，各自用 `trigger.conditions` 分流、各带一套权重；
- `weightBy` 的系数可正可负，所以「幸运低 ⇒ 灾祸概率高」是天然支持的（负系数）；
- 开局 roll 支持静态 `weight`，schema 现在**拒载 `weightBy`**（ADR-001 D-4）。但 D-4 的理由是
  「开局期**世界属性**未实例化、补正与最终面板算不出来」——它挡的是属性，**不挡开局参数**：
  `origin` / `technique` / `talent` 都是前面节点已经 roll 定、本会话内确定的值，没有「面板还没算出来」的问题。
  所以「按开局结果给后续权重」是可做的，代价是加一个 `weightByParam`（按 param 解析，enum 用值映射表）。
  **结论改口：不是「做不到」，是「还没做」**——现已做完，见 **ADR-001 D7**（§10 待办 #6），不再单开 ADR。

**奖励也走 roll**：救不救得下、觉醒不觉醒、能不能开隐藏线，都是低权重扇区（1%-8%）。
玩家 build 的属性把好事概率抬起来——这才是「成长」的兑现方式，而不是单纯加伤害数字。
「完美时间线」不是不存在，是**要 roll 到那个扇区**；重开比读档更符合人生模拟器的语气。

**开局也走 roll**：身份（origin）、生得术式、初始关系、初始资源全部由加权转盘决定，
玩家不满意只能重开，不能挑。这是「人生」而不是「选人界面」。

> 例外要能收尾：若一次 roll 直接进「结局」（如诅咒师线撞上五条），当场结算，不留半截。

## 4. 六条线

### 4.0 六条线 = 六种「你有多大权力」

不是六个平行宇宙，是同一段历史上的六种站位。**站位决定难度，而难度必须有补偿**，
否则要么变成观光，要么变成受刑。

| 走法 | 在哪 | 权力来源 | 起点 | 曲线 | 收束 / 补偿 |
| --- | --- | --- | --- | --- | --- |
| **原作线** | L1 / L2 / L4，不介入 | 无——你只是同学 | 偏高 | 恒定偏高 | 只能边缘救人；关键选项根本不出现 |
| **高专线** | L1 / L2 / L4，介入 | 术式 + 身份 + 同伴 | 中 | 随实力**下降** | 敌人 `levelScale` 按时段上调，强了也不轻松 |
| **五条线** | L4，预知 | 知道剧本 | 极低 | 前低后**骤高** | 天意大手：因果收束 + 预知失效 |
| **诅咒师线** | L3 诅咒师侧 → L4/L5 | 与五条 / 乙骨为敌 | 极高 | 前高后中 | 前期可能当场结局；涩谷 / 死灭结旧账 |
| **咒灵线** | L5 | 非人视角 | 中高 | 平推 | 决战分线**必须前期埋因**（L5 表） |
| **古代线** | L6 | 千年记忆 | 高 | 蒙太奇 | 三条执念 → 主角性格（L6），战场在**仙台** |

**原作线：难度偏高，因为你没有杠杆。** 不给「恰好路过」的便利；能做的只有提前报警、
替人挡一下、事后收尸。这条线的奖励是**信息**（`truthBits`），不是战力。

**高专线：介入换难度下降，但有下限。** 敌人 `levelScale` 与数量随 `phase` 上调；
成长兑现为「同样的仗更省资源」，不是「无伤通关」。

**五条线：预知必须补偿。** 知道剧本意味着前期几乎无风险，玩家会连着跳过三四个坑。补偿两件事：

1. **天意大手**：某些 canon 事件不受玩家影响，到点强制发生（`trigger` 无条件、`missWhen` 空），
   且发生时敌人按「玩家已预知」加码；
2. **预知失效**：写入 `foreknowledgeLost`（羂索察觉、世界线偏移、有人不信你）后，
   所有「跳坑」选项关闭。

没有这两条，这条线就是作弊模式。

**诅咒师线：前期极高，允许直接结局。** 对手是五条 / 乙骨，正面撞上就该死——
给「当场结算」的 bad end（`earlyDeath`），不硬撑。旧账在涩谷 / 死灭结：
早年杀过的人、卖过的情报，变成具体的因果事件（`debt.*` 落地）。

**咒灵线：决战分线必须前期埋因。** 不允许在最后一幕才让玩家选边，见 L5 的因果表。

#### 4.0.1 死灭回游的结界锁（按站位，2026-11-19 已裁）

**站位决定你能进哪个结界**，这一条同时决定了「谁能成为关系线、谁只能是广播」：

| 站位 | 落在哪 | 能自选吗 | 迁移 | 会真正碰到谁 |
| --- | --- | --- | --- | --- |
| **原作线** | 跟着原作走（东京第一 → 东京第二 → 仙台 → 新宿，顺序实施前按原作核） | 不能 | 由原作事件带走，不花钱 | 日车（第一）、秤与鹿紫云（第二）、乙骨（仙台）——**但只能看，不能改** |
| **高专线** | **自由选择**落点 | 能 | 随时可去任一结界（`playerColony`） | 自选结界里的人；这线是唯一能把「W 见证」升级成「R 关系」的 |
| **五条线** | 涩谷 → **跳过死灭整段** | — | — | 谁也不碰：五条由天意大手强制封印（`gojoSealed` 不可改），19 天用一句蒙太奇带过，直接进「解封 / 新宿」段 |
| **诅咒师线** | **锁东京第一** | 不能 | 无 | **日车（必遇）**：审判剧情作为前置挂在 L3 末尾，你可能被审、可能被判死（`earlyDeath`） |
| **古代线** | **锁仙台** | 不能 | 门槛 100 分、扣 50 分、**一次单向**、不可回 | 乙骨、石流龙、乌鹭、黒沐死；日车 / 秤 / 鹿紫云只闻广播 |
| **咒灵线** | 不涉及（L5 在涩谷收束） | — | — | — |

三条注意：

1. **迁移不是传送门**：门槛 100 分（不够买不了）、执行扣 50 分、只能一次、单向、不可回。
   它是「押上半个身家换一条路」，不是「随便逛」。
2. **五条线跳过的代价**：跳过期间拿不到分数、拿不到死灭的情报与关系，
   解封后要补课——这就是「预知前期太爽」的第二次收费（第一次是天意大手）。
3. **诅咒师线锁东京第一的收益**：日车从「广播里的传闻」变成**必须面对的审判者**，
   而且审判的罪名来自 L3 的旧账（`debt.*`）——因果闭环在这里第一次兑现。

### L6 古代线 + 死灭回游（蒙太奇，12 beat）

**命题**：一千年了，人类还是同一套解法。

**形态**：不是穿越，是**咒物记忆 / 受肉闪回**。玩家触碰手指、咒物、结界核心时，闪回 3-5 个古代片段。
每个片段 1 个 beat、1 个选择，产出 `truthBits`（关于羂索/天元/宿傩的情报）。

**三条执念＝主角的三种性格底调**：不是给技能，是给**性格**——同一条时间轴、同一批事件，
性格不同，旁白语气不同、能选的态度不同、结局被理解的方式也不同。

| 执念 | 出处 | 缝给主角的性格 | 剧情展开上怎么体现 |
| --- | --- | --- | --- |

| **求败** | 鹿紫云一（一世求败） | 只对更强的人有兴趣：对弱者的苦难迟钝 | 旁白变淡；强者登场时多出「迎上去」；弱者求助的选项会减少甚至不出现 |

三者的共同点：**都让人变得不像普通人**——这正是古代线的代价。不缝，你就是个普通的同学；
缝了，你在 2018 年看涩谷的眼神会像看一场审判 / 一场庆典 / 一场淘汰赛。

实现三步，全是现有能力，不加协议：

1. A4 选「共鸣」⇒ 写字符串旗标 `temper` = `judgement` / `zeal` / `defiance`（三选一；也可以不选）；

3. 叙事 prompt 里加**一句**语气设定（「你是一个把一切都当审判的人」）——这句话本身就是「剧情展开方式」。

> 中途也能改，但要付代价（`temperChanged` + 一次大事件），否则「换个性格」就成了免费洗点。

## 5. 关系线（玩家 × 角色）

> **先答一个口径问题**：这一节不是「原作的个人线」。
> 原作弧是**基线**——不管玩家做不做什么，夏油都会在 2007 年夏天走到那个村口。
> 玩家的存在只改变「他走到那儿时，身边有没有人」。
> 所以这里写的是**关系线**：玩家 ↔ 该角色（有时还要第三个人在场才成立），反复结算的那点东西。

### 5.0 两类线与字段口径

**线型不是人的属性，是「站位 × 人」的属性**——同一个人，高专线里能救，原作线里只能看着。

| 型 | 判据 | 权限 | 出现在 |
| --- | --- | --- | --- |
| **R 关系线** | 同场、反复接触，**且站位给你杠杆** | 关系值 + 开口关门 + 改他**一个**分岔 | 高专线全开；诅咒师线的日车；古代线的仙台组 |
| **R₀ 只读关系线** | 同场，但站位不给你杠杆（你是同学，不是当事人） | **只能动关系值**；分岔选项根本不出现 | 原作线全体 |
| **W 见证线** | 不同结界 / 不同时代 | 只插手**一次**，不改他的结局 | 见下表「只闻广播」列 |

按站位分（§4.0.1 的结界锁直接推出这张表）：

| 站位 | 能成 R 的人 | 只闻广播 / 只能看（W） |
| --- | --- | --- |
| 原作线 | —— （全体降为 R₀：能接触、不能改；万在东京第一→仙台，可同场） | 日车、秤、鹿紫云 |
| **高专线** | 五条、夏油、理子、虎杖、乙骨、伏黑、胀相、灰原、日车、秤、鹿紫云（自选结界） | 万（她只去仙台等宿傩）、九十九 |
| 五条线 | 五条、伏黑、虎杖、硝子（涩谷段；死灭段整体跳过） | 死灭里所有人 |
| 诅咒师线 | 日车（**强制**）、虎杖（对手位） | 秤、鹿紫云、乙骨、万 |
| 古代线 | 乙骨、石流龙、乌鹭、黒沐死、**万（仙台，可 R）** | 日车、秤、鹿紫云 |
| 咒灵线 | ——（L5 在涩谷收束） | —— |

每小节那七行依次读作：

| 字段 | 属于 | 玩家能改什么 |
| --- | --- | --- |
| 命题 / 欲望 / 恐惧 | 基线（原作弧） | 不能改；能改的是「他有没有把这件事说出来」 |
| **状态机** | **基线状态机**（原作者阶段） | 只能改他**跳过 / 滞留在哪一段**，不能改阶段本身 |
| **介入点** | **关系 beat** | 线的主体，每个 beat 一次结算 |
| 结局 | 分岔表 | 基线出口永远存在，玩家开的是**加法**出口 |
| 禁写 / 留白 | 状态层 / 文案层 | 见 §7 口径 |

> 与 §7 一致：**「禁写」= 模板不提供那个选项**，不是「写完再拒」；
> **「留白」= 模型可以自己编、且不影响判定**，不是等它回填的空槽。

### 5.0.1 十三条线：参与人 / 关系边 / 在争什么

关系边 `kind` 只能用闭集（`mentor disciple friend rival enemy colleague` **+ `lover`**），值域 -100..100（`RelationEdgeSchema`）。
`lover` 是 2026-11-19 用户裁决新增的对称社会边（**不需要 ADR**，已在 `SocialKindSchema` 落地）：
不进 `KinshipKind`、不参与称谓推导，强度仍走 `value`——`lover` + `value: 20` 是冷淡的恋人。
起点值是开局写入的 `player ↔ npc` 边，之后由事件 `adjustRelation` 改；**边方向写作 `npc → player`**
（`五条 mentor -10` 读作「他是你的老师，且他不打算跟你亲近」）。

### 5.1 五条悟

- **命题**：「最强」是自由，还是隔离。
- **欲望**：培养出能并肩、甚至能杀死自己的人。
- **恐惧**：再一次「来不及」。
- **状态机**：`student → awakened（理子死/甚尔战）→ teacher（2007 后）→ sealed（涩谷）→ freed/dead`
- **介入点**：
  1. 2006 冲绳之夜：他第一次把人当「同伴」而不是「任务」；
  2. 2007 新宿：他杀不杀夏油，取决于玩家给没给他另一个选项；
  3. 2012 任教：玩家可以劝他「别把学生当武器」，也可以劝他「继续」；
  4. 2018 涩谷：玩家能不能提前拆狱门疆。
- **结局**：战死（canon）/ 存活但失去六眼 / 成为「怪物」 / 退休教书 / 被玩家杀死（黑化分支）。
- **禁写**：五条在 2006 就理解「弱者」；五条对玩家的感情写成恋爱（除非玩家主动且长期投入）；五条在封印中还能行动。
- **留白**：他私下的住处；他给夏油留的那句话；他记不记得每个死去的学生的名字。

### 5.2 夏油杰

- **命题**：保护不值得的人，还是净化不值得的世界。
- **欲望**：术师不再被非术师消耗。
- **恐惧**：自己的善意是徒劳。
- **状态机**：`trusting → doubting（理子死/灰原死）→ cracking（村庄）→ defected（杀父母）→ dead/puppet`
- **介入点**：
  1. 2006 盘星教鼓掌：玩家站在他旁边还是拉他走；
  2. 2007 灰原葬礼：玩家说不说「这不是你的错」；
  3. 2007 村庄：玩家先救人还是先找他；

#### 5.7.1 审判三拍：**抽罪用转盘，辩解用选项**

分工不是「两种都用一点」，是各有各的职责：

| 拍 | 载体 | 为什么必须是它 |
| --- | --- | --- |
| **1 抽罪** | **转盘** | 抽到什么**不是玩家的意图，是世界的事实**。日车自己也不知道审判者会读出什么。用选项给玩家挑罪名，就等于让被告自己选罪状——那是作弊 |
| **2 辩解** | **选项**（≤4） | 说什么话**就是玩家的意图**。认罪 / 否认 / 反问 / 沉默，这四种态度必须由玩家选 |
| **3 判决** | 选项的 `effects` + `endings.yaml` 条件 | 判决结果不是一个新选项，是前两拍的**结账**：分数、刑期、可能死 |

**为什么抽罪用转盘还顺带解决两件事**：① 确定性——同一 seed 同一罪状，回放可复现（内核不引入新随机源）；
② 重开有新鲜感——换 seed 换罪状，玩家不能背题。

第 1 拍（转盘，4 段；`infamy` 是 0..2 的 ladder，系数必须按这个量级给）：

```yaml
- id: ev-cg-jr-02
  title: 审判者的声音
  trigger: { source: chain, conditions: [{ flag: higurumaCourt, eq: true }] }
  settle:
    random:
      wheel:
        segments:
          - label: 轻罪 · 一次隐瞒
            weight: 40
            weightBy: { infamy: -15 }        # 恶名 2 ⇒ 40-30=10
            effects: [{ type: setFlag, id: crimeTier, value: 1 }]
            nextEventId: ev-cg-jr-03-t1
          - label: 中罪 · 见死不救
            weight: 30
            weightBy: { infamy: -5 }
            effects: [{ type: setFlag, id: crimeTier, value: 2 }]
            nextEventId: ev-cg-jr-03-t2
          - label: 重罪 · 杀过人
            weight: 18
            weightBy: { infamy: 10 }
            effects: [{ type: setFlag, id: crimeTier, value: 3 }]
            nextEventId: ev-cg-jr-03-t3
          - label: 极刑 · 无可辩解
            weight: 4
            weightBy: { infamy: 18 }         # 恶名 2 ⇒ 4+36=40，与轻罪段同权
            effects: [{ type: setFlag, id: crimeTier, value: 4 }]
            nextEventId: ev-cg-jr-03-t4
```

> **系数校准的坑**：`weightBy` 乘的是**属性有效值本身**，不是百分比（最终权重 = `max(0, weight + Σ 属性×系数)`）。
> `infamy` 是 0/1/2 的三档 ladder，所以系数得是 10~18 这种量级；照百分比直觉写 `0.6` 等于永远不起作用。
> 这条是模板作者最容易写错、且**不会报错**的地方。

第 2 拍（辩解，**4 个版本**，由上面每个扇区的 `nextEventId` 分开）：

| 版本 | 罪名 | 辩解选项 | 能开什么门 |
| --- | --- | --- | --- |
| `t1` 轻罪 | 隐瞒 / 见死不救 | 认罪 / 否认 / 反问「你审我之前审过谁」 | 轻罚，全都能过 |
| `t2` 中罪 | 见死不救致死 | 认罪 / 否认 / 沉默 | 否认成立与否看 `virtue`，不看嘴硬 |
| `t3` 重罪 | 杀过人 | 认罪 / 否认 / 反问 | 认罪 ⇒ 重罚但活；否认 ⇒ 罚更重 |
| `t4` 极刑 | 无可辩解 | 认罪 / 反问（需 `higurumaDoubt`）/ 沉默 | **认罪或沉默 ⇒ 死**；反问是唯一活路 |

四个版本不是「写四遍文案」，是四种**选项集**：`t4` 里根本没有「否认」，因为那条路在这个罪名下不存在
——这就是 §7「门开在选项上」的直接用法。

第 3 拍（判决）：**不新建事件**。每个辩解选项的 `effects` 里写三件事：
`setFlag plea` / `adjustFlag cgPoint`（分数）/ 必要时 `setFlag verdictDeath, value: true`。
死刑由 `endings.yaml` 的一条条件接管（`verdictDeath: true`），模板正文只写「宣判」那一幕。

> 为什么不做一个「判决事件读 `crimeTier` + `plea` 再分流」：`nextEventId` 是**静态**的，
> 读两个旗标再分四路，要么写 16 个判决事件，要么给引擎加条件跳转——前者是垃圾，后者是协议改动。
> 把判决写进辩解选项的 `effects`，是这个引擎里唯一不需要新机制的走法。
> 代价：文案上「宣判」只能写在一处，四个版本共用——**认了这个代价**。

站位差异（§4.0.1）只改两处：**诅咒师线** `infamy` 高 ⇒ 极刑段自然变重、`courtRole = accused`，
被判死是真实威胁；**高专线**可以选 `courtRole = witness`（旁听席），抽罪抽的是别人的罪，
玩家的辩解影响的是**别人的命**——同一条线两种道德重量。

## 6. 理子的长线

> 用户点名要「好好做」。这一节单独展开，因为她是唯一一个「被救之后还要活十二年」的人。
>
> **参与人（关系线 R，`friend` 起点 0）**：玩家 · 黑井美里（全程，她是理子真正的「家」）·
> 五条/夏油（2006 与 2018 两个端点）· 天元（2015 后）· 羂索（2017 后）。
> **黑井不是背景板**：玩家和理子的每一次进展，都要经过黑井点头——她有权把玩家挡在门外。

### 6.0 为什么「救她」比「她过得好」重要：一条 canon 因果

原作给了一条硬链条，正好是这条线的世界级赌注（出处：九十九由基条目转述的天元设定）：

```
理子被甚尔枪杀
  → 同化失败
  → 天元的系统「判不出星浆体已死」
  → 星浆体不再产生
  → 天元「进化成类似咒灵的存在」不可避免
```

反过来说，**只要理子活着，这条链就断在第一环**：系统判定正常，星浆体还在，天元就还有合法的同化对象。
所以救她的回报不是「一个女孩活下来」，是**2018 年的结界、涩谷的条件、羂索手里的牌全部改写**。
这也是本作里唯一一个「玩家救一个人 ⇒ 世界换了走向」的杠杆，其他线都是「你陪谁走过」。
（代价见 §6.3：她活着，羂索就多一枚筹码，天元也会来找她。）

### 6.1 2006 的三种出口

| 出口 | 触发 | 她之后是谁 | 长线开不开 |
| --- | --- | --- | --- |
| `shot` | canon | 死者；天元的星浆体失败 | 不开（只有回忆） |
| `saved` | 玩家干预成功 | 逃亡者；黑井带她隐居 | **开** |
| `merged` | 她自己选择同化 | 天元的一部分 | 半开（天元线） |

### 6.2 2007-2016 的四个 beat

| 年 | beat | 玩家选择 | 产出 |
| --- | --- | --- | --- |
| 2007 | 黑井带她搬到冲绳/北海道 | 常去看 / 只寄钱 / 断联 | `rikoTrust` |
| 2009 | 她想去普通高中 | 支持 / 反对 / 让她自己选 | `rikoNormal` |
| 2012 | 盘星教余党找到她 | 挡 / 转移 / 教她术式 | `rikoTraining` |
| 2015 | 天元结界开始不稳，高专来找 | 交人 / 藏 / 谈判 | `rikoRecalled` |

### 6.3 2017/2018 的回归方式

- **2017 百鬼夜行**：羂索知道「星浆体还活着」⇒ 她成为筹码。玩家可以选择把她带到高专（安全但暴露）
  或藏在民间（安全但孤立）。
- **2018 涩谷/天元**：天元需要「同化」或「替代」。理子可以：
  - 自愿同化（稳定结界，玩家失去她）；
  - 与天元共存（需要 `tengenTrust` + 玩家说服）；
  - 拒绝（结界崩坏，2018 更糟）；
  - 被羂索利用（她成为「伪天元」）。

### 6.4 六个结局

| 结局 | 条件 | 情绪落点 |
| --- | --- | --- |
| `assimilated` | 自愿同化 | 她终于自己做了决定；玩家失去她 |
| `ordinary` | 拒绝一切，隐姓埋名 | 她活着，但世界更糟；玩家保护她到 2019 |
| `sorcerer` | 接受训练，上战场 | 她成为术师；可能战死 |
| `puppet` | 被羂索控制 | 她成为「伪天元」；玩家必须亲手终结 |
| `coexist` | 与天元共存 | 需要天元信任 + 玩家说服；最难 |
| `died` | 无论怎么救还是死 | 玩家获得「见证」结局 |

> 设计判断：理子长线的张力不是「她会不会死」，是「谁有权决定她的命」。
> 所以每个 beat 的选择都应该是「替她决定 / 让她决定 / 什么都不做」，而不是「好感度 +1」。

## 7. 世界走向怎么约束 LLM

### 7.1 三个问题先问清楚

1. **这个约束在防「世界被改坏」，还是防「文案难看」？** 只有前者值得上机制。
2. **能不能让它在结构上不可能，而不是在文本上被拒？** 能——门开在选项上（§7.3）。
3. **拦不住的怎么办？** 承认拦不住，把代价压到「一段可重生成的文案」（§7.7）。

模型不是不知道「夏油 2006 还没黑化」，是**生成戏剧冲突时会优先满足冲突**。
你写「注意时间线」，它在长上下文里丢掉；你写「不要写盘星教」，它换个词照样写。
所以叮嘱没用；但**审查也没用**——它只是把「写得不像」变成「被拒一次之后照样写得不像」，
中间还多一次误杀正确句子的机会。真正的杠杆只有一个：**别让这条路存在。**

### 7.2 事实层：一句自然语言简报，不投旗标

关键认识：**这一幕能开，说明 `trigger.conditions` 已经判过 flag 了。**
再把 `getoGone = true`、`npc-geto = alive` 塞进 prompt 是重复劳动，
还会把模型的注意力从「写这场戏」拉到「读一张表」。

要注入的不是状态，是**这一场的在场信息**，写成自然语言，三行：

```
[本场 · 只读；不要复述以上内容，也不要引入与它冲突的设定]
时间：2018-10-31 22:00
在场：虎杖悠仁（在世）、伏黑惠（在世）；你（高专二年级）
```

三个来源，全部已有字段：

| 行 | 来源 |
| --- | --- |
| 时间 | `state.time` |
| 在场 | 本 event 的 `actors` / `mentions` + 各自 `lifecycle.state` |
| 你 | `state.player` 的 name / age / 当前身份属性 |

**角色处在什么状态，由这一幕的正文交代**（「五条在狱门疆里」写在模板的 `text` 里），
不由简报交代——世界知识属于模板，不属于 prompt 拼装层。

放在 `apps/server/src/narrative/brief.ts`（服务端 LLM 层），**不进 `packages/shared`**：
放 shared 就得为一部作品写死 `geto.stance` 的派生，和被拒的 `lines:` 是同一个错。

### 7.3 状态层：门开在选项上

「夏油还没黑化，模型却写成盘星教教主」这个事故，正确的防线不是事后审查，是**事前不存在这条路**：

- 盘星教的选项/事件，`visibleWhen` 只在 `getoGone` 为真时出现；
- 夏油在 `getoGone` 之前的一切戏，只能走「高专教师 / 同伴」那一支——同一事件的 `branch` 里根本没有叛逃节点；
- 死了的角色不能当 `actors` / `mentions`：`entity_dead`（现有引用校验，校验的是 ID，不是语义）；
- 时间没到的角色不能登场：`appearsFrom` / `not_yet`（现有）。

这套的收益是**穷尽性**：模型能写的东西全部是模板允许的选项，它没有「凭空生成一个事件」的入口
（`#26 自由文本行动` 至今 DEFERRED）。§7.5 的事故大多数在这一层就已经不可能发生。

代价：模板作者要多写 `visibleWhen`。这是**确定的成本**，换**确定的边界**——比反复调提示词划算。

### 7.4 简报的三条纪律

1. **只给在场者与时间**，不给旗标、不给立场阶梯、不给「他最近在想什么」；
2. **不写禁令**，末尾一句「不要引入与它冲突的设定」足够；
3. **不超过五行**——长上下文里，越长越容易被忽略。

不引入 `premises` 自检、不引入候选分支提审：那是给「LLM 生成事件」准备的，
而那个能力（`#26`）还没上线，现在建就是空转。

### 7.5 六个事故：谁拦得住、谁拦不住

诚实版。左列是要防的事故，右列是**真正生效的那一层**：

| 事故 | 拦法 | 层 | 拦得住吗 |
| --- | --- | --- | --- |
| 夏油没黑化，却生成「盘星教教主」 | 盘星教事件/选项 `visibleWhen: getoGone` | 状态 | 选项层面 100%；他在**无关场景的散文里**硬提一句，拦不住 |
| 理子已死，却登场 | `entity_dead`：`actors` / `mentions` 撞死亡名单 | 状态 | 100%（这是 ID 校验，不是语义） |
| 五条被封印，却赶来救场 | 救援事件 `visibleWhen: !gojoSealed`；本幕正文写明「他在狱门疆里」 | 状态 | 选项层面 100%；散文写「远处传来五条的声音」可能漏 |
| 2017 写虎杖入学 | `appearsFrom` / `not_yet` | 状态 | 100% |
| 让五条在 2006 杀死夏油 | 该 `branch` 里没有这个节点 | 状态 | 100%（选项不存在） |
| LLM 造特级咒灵带领域 | 无自由生成入口 | 状态 | 100%；`#26` 上线后需重估 |

> 表里「拦不住」的只剩一种：**散文里的世界知识错误**——不是角色登场、不是选项，只是叙述提了一句不该提的事。
> 代价是读者出戏一次；修法是重生成，或直接换模板文本。
> 为它建一套审查器（词表 + 共现 + 修复循环）不划算，而且换来的误杀比漏网更烦人。

### 7.6 留白：默认不落盘，要一致的写死在模板里

留白不需要「填洞机制」。分两类处理：

- **一次性的**（这顿饭吃什么、那天下没下雨）：LLM 当场编，不持久化；下一幕不一致也无所谓。
- **要跨幕一致的**（理子的化名、她怎么称呼玩家、黑井现在做什么）：**模板写死**，
  首次进入时 `setFlag` 一个字符串值，之后每幕当事实注入。LLM 只读，不改。

后者用 `flags` 存，命名空间 `blank.*`，全模板控制在 2-3 个键：

```
blank.riko.alias   = "天内美咲"
blank.riko.callYou = "学长"
```

好处：零 schema 改动；坏处：flags 会变脏——所以每个键都必须有读点，
`flag-never-read` 体检把 `blank.*` 排除。

> 为什么不让 LLM 回写：它一旦能写 `blank.*`，就等于能写状态，
> R2.7 的「LLM 不进权威状态」边界立刻破。一致性由模板保证，不由模型自觉保证。

### 7.7 明确不做

| 不做 | 为什么 |
| --- | --- |
| `capsule`（allowed/bannedMotifs、must/mustNot） | 语义判定不可靠；每幕编一份词表的维护成本远大于收益（收益只是文案质量） |
| 关键词 / 共现 lint | 误杀正确句子（「拒绝天元同化」）；改写绕得过（「一个收钱的宗教团体」） |
| `premises` 声明自检 | 是给「LLM 生成事件」准备的；`#26` 未上线，现在建是空转 |
| judge 模型对抗 | 延迟与成本翻倍，judge 自己也会错；不如模板兜底 |

## 8. 落地：语法与工作量

### 8.0 先核对语法事实（2026-11-19 读代码）

| 事实 | 位置 | 对设计的影响 |
| --- | --- | --- |
| `WorldTemplateV2Schema` 是 `.strict()` | `packages/shared/src/schema/world.ts` | 顶层加 `lines:` 会被**拒载**，不是「多写一个键」 |
| `EventBase` 是 `.strict()`，只有 id/title/narrative/trigger/actors/mentions/npcs | `packages/shared/src/schema/event.ts` | 事件上直接加 `line:`/`act:` 会被拒载 |
| 模板侧 `TemplateBranchEventSchema` 也是 `.strict()`（id/title/trigger/branch） | `apps/server/src/templates.ts` | `line`/`act` 必须由加载器接住，不能透传给 schema |
| `branch` 在**加载期**展开，运行时无感知 | 同上 `expandTemplateEvents` | `line`/`act` 最好在展开时抽成**侧表**，不进事件 |
| `branch` 节点字段是 `text` 不是 `narrative`；`title` ≤40、`text` ≤600、options ≤4、effects ≤8、nodes ≤12 | 同上 | 一幕超过 12 节点要拆成多个事件；长旁白要切块 |
| `advanceBy.value` 是 `TimeAmount`（`{value,unit}`），不是 `"3d"` | `packages/shared/src/schema/common.ts:394` | 蒙太奇推进时间必须写对象；`goto.after` 才吃字符串 |
| 转盘扇区只有 `weight` + `weightBy`，没有条件权重 | `packages/shared/src/schema/event.ts:121` | 权重只能被**属性**抬降；要按 flag 改概率 ⇒ 拆成两个事件、各自 `trigger.conditions` 分流 |
| 扇区自带 `effects` + `nextEventId` | 同上 | 一个转盘就能直接换幕，不必套一层选项 |
| 开局 roll 支持静态 `weight`，**拒载 `weightBy`** | `packages/shared/src/schema/opening.ts:284-295`（`refine` 直接拒） | 拒的理由是「世界属性未实例化」，**不挡开局参数**；要按 `origin`/`talent` 调权重用 `weightByParam`（**已落：ADR-001 D7**） |

> 结论：`lines` **不该进模板**。这不是「多写一个键」的工程量问题——`.strict()` 恰好提醒了一件事：
> 一部作品的目录结构不该长进内核 schema。§8.1 改成命名约定。

### 8.1 「线」用 eventId 命名约定表示，不加协议

先回答四个问题（顺序就是判断顺序）：

| 问题 | 回答 |
| --- | --- |
| **消费链路在哪？** | 只有 `inspect`（按线分组看、体检断链）和模板作者自己。`/admin` 的图与搜索本来不需要线 |
| **前端展示吗？** | 不。`apps/web` 没有章节标题位（查过：只有事件 `title` + 正文）；要加也是展示已有字段 |
| **世界通用吗？** | 不。「怀玉 / 玉折 / 死灭回游」是 JJK 专名；写进 `WorldTemplateV2Schema` 等于为一作改内核 |
| **能用现有能力替代吗？** | 能。`buildLine(orch, eventId)` 已能沿 `nextEventId` 走完整条支线；「线」只是**一组 eventId 的前缀** |

约定（写模板时遵守，运行时零感知）：

```
ev-hv-05   L1 怀玉 第 5 幕      ev-jr-04   L5 咒灵 第 4 幕
ev-gy-03   L2 玉折 第 3 幕      ev-cg-02   L6 古代/死灭 第 2 幕
ev-zr-06   L3 0 卷 第 6 幕      ev-rk-03   R  理子长线 第 3 幕
ev-hs-07   L4 高专 第 7 幕
```

- 一幕超过 12 节点要拆时加字母：`ev-hv-05a` / `ev-hv-05b`，字母序即演出序；
- 短角色线（1-2 拍）不占前缀：它跑在所属世界线的事件里，用 `as: npc-xxx` 分支承载（§8.2）；
- **长角色线**单独占前缀：理子线跨四条世界线、六个幕，用 `ev-rk-01..06`（§6）——
  否则「她的 2009」在 L1/L3/L4 里都无处安放。这不是特例，是「一段事件只属于一条线」的直接后果；
- **线与线的交汇**不靠声明，靠 flag：L4 的事件拍 `gojoSealed`，L5 的事件在 `trigger.conditions` 里读它。

工具侧只加一处（属 CLI，不是协议）：`inspect tpl --line hv` 接受**前缀**，
等价于按前缀筛子图再交给 `buildLine`；传精确 id（`ev-hv-05`）时行为不变。

线元数据（名字、跨度、cast）只写在本文档 §4 / §5 的表格里，不进模板——
它是给人看的，不是给引擎看的。将来真需要「你走完了哪几条线」，
用普通 flag 记一笔（`line.hv.done`）即可，仍然是现有能力。

### 8.2 `branch` / `as` 的写法（三段示例）

**多场景 + 跳转**：

```yaml
- id: ev-hv-05
  trigger: { source: chain, conditions: [] }
  branch:
    - node: gate
      title: 薨星宫前
      text: 甚尔站在台阶下，手里没有咒具。
      options:
        - text: 跟五条上楼
          goto: fight
        - text: 护着理子去本殿
          goto: honden
    - node: fight
      title: 五条 vs 甚尔
      text: 楼上的动静像地震。
      options:
        - text: 上去帮忙
          goto: { node: honden, after: "10m" }
        - text: 守在这里
          goto: honden
    - node: honden
      title: 本殿
      options:
        - text: 挡在她身前
          effects: [{ type: setFlag, id: hvGuard, value: true }]
        - text: 拉她走
          goto: { node: escape, after: "1m" }
    - node: escape
      title: 侧门
      text: 你拉着她往侧门跑，身后没有脚步声。
      options:
        - text: 继续跑
          nextEventId: ev-hv-06
```

**角色视角变体（`as`）**：

```yaml
- id: ev-rk-03
  trigger: { source: schedule, conditions: [{ flag: rikoHidden, eq: true }] }
  branch:
    - node: talk
      title: 普通高中
      text: 她把志愿表折成很小的一块。
      options: [{ text: 问她想去哪, goto: ask }]
    - node: talk
      as: npc-riko
      title: 普通高中（理子视角）
      text: 笔尖在「升学」那一栏停了很久。
      options: [{ text: 写下去, goto: ask }]
    - node: talk
      title: 普通高中（兜底）
      text: 她把志愿表推到你面前。
      options: [{ text: 接过来, goto: ask }]
```

> 注意：`as` 变体必须有一份**无 `as` 的兜底**；`nextEventId` 不重算条件，
> 所以「幕 6 只在理子活着时出现」要写在幕 5 选项的 `visibleWhen`，不能写在幕 6 的 `trigger.conditions`。

**蒙太奇（`goto.after` + `timeCost`）**：

```yaml
- id: ev-cg-01
  trigger: { source: schedule, conditions: [{ flag: cgJoined, eq: true }] }
  branch:
    - node: broadcast
      title: 规则广播
      text: 十个帐同时亮起。十九天。
      options:
        - text: 记下规则
          effects:
            - { type: setFlag, id: cgRules, value: true }
            - { type: advanceBy, value: { value: 3, unit: day } }
          goto: { node: colony, after: "0m" }
        - text: 先找出口
          effects: [{ type: advanceBy, value: { value: 3, unit: day } }]
          goto: { node: colony, after: "0m" }
```

### 8.5 验收口径

- `pnpm inspect check`：`error 0`；
- 新增体检规则**只加一条**：`sink-event`（事件没有出边，也不通向结局/结束）——
  它顺手取代了原计划的「线没有出口」；「某一幕没有入口」已由现有 `orphan-chain-event` 覆盖；
- `inspect tpl --line hv` 能按前缀列出整条线并按 eventId 排序；
- 状态门负例：§7.5 前四行的四个 fixture，在**选项层面就不出现**（不是「出现后被拒」）；
- 6 seed playthrough：不卡死、不出现「线断在中间」；
- 文案检查：蒙太奇 beat 每个至少改一个 flag；
- **转盘优先**：每一幕至少一个 `random` 结算；同一幕的选项 ≤ 1；
  每个转盘至少一个权重 ≥10% 的坏结果（否则没有张力），
  至少一个奖励扇区带 `weightBy`（否则 build 没有回报）。

## 11. 台词锚点（只出锚点，不写剧本）

台词不进模板的「禁用词表」，而是**钉在 beat 上的一次性资源**：全作约 20 处，
每人一句，每条世界线 ≤3 处，且必须落在分岔点前后。台账在 `lore-registers.md` §10。

### 11.1 引法按线型分三档

| 线型 | 怎么引 | 例 |
| --- | --- | --- |
| **R₀ 原作线**（能看不能改） | 可以用**全句**，因为结果与原来一致 | 五条：「会赢的」 |
| **R 关系线**（能改他一个分岔） | 只给**半句**，下半句由玩家的选择补 | 五条：「会赢」——然后看向玩家 |
| **W 见证线 / 其他站位**（结果不同） | 只作**转述或旁听**，不让他说完整句 | 「他说了句什么，周围的人都没笑」 |

理由：原句自带结论。结果一旦改变，原句就变成谎话；而玩家记得原句，会立刻察觉世界在撒谎。

### 11.2 母题：一句话五次，每次换人

原作把「绝对的强者，由此而生的孤独，要教会你爱的人是——」当成母题用了五次（万 → 宿傩独白 →
旁白 → 劣势独白 → 走马灯）。这个用法本身就是**反堆砌**的样板：同一句出现五次，每次含义都变，
靠的是场合不同，不是复读。本作照抄结构、换掉关系：

| # | 谁说 | 在哪 | 含义变成 |
| --- | --- | --- | --- |
| 1 | 万 | L6 C7 / A4 闪回 | 「你没人爱」（万自以为看懂了宿傩） |
| 2 | 宿傩（独白） | 原作线·宿傩战前 | 「他们不懂，也不需要懂」 |
| 3 | 旁白 | 石流龙笑着去挑战、被一击杀死 | 「教会他爱的人是死亡」——反讽 |
| 4 | 玩家（半句） | 若与宿傩同场，可选说 / 不说 | 「要教会你爱的人是——」说到这里停住，正是玩家自己的位置 |
| 5 | 结局回响 | 一切结束后的一行 | 「到最后也没人教会他」 |

> 这一条不需要任何新机制：五次都是同一个 `eventId` 前缀下的文本，
> 第 4 次做成一个态度选项（说 / 沉默），只改 `temper` 与文案，不改判定。

### 11.4 三条不写

1. **不写社区梗**（2.5 条、腰斩、灭火器、坐杀摇摆舞）——判据：这句话是角色会说的，还是读者会说的（`lore-registers.md` §10.4）。
2. **不给理子写金句。** 她全作最好的台词是「我想活下去」这种普通人的话；一旦给她写出宿命感，这条线就废了。
3. **不在玩家角色身上堆名台词。** 玩家是同学/同事，不是第二个五条；他能说的最好的一句是「我在」。

# 迭代：JJK 剧情线重做（2026-11-19）

## 状态

**设计稿，不含剧本正文，不改模板。** 等 `iteration-2026-11-19-attribute-types` 收口后，按本文分波实施。

## 一句话

把现在「一条十二年主线 + 95 个事件」的写法，重做成「一条主脊 + 6 条世界线 + 13 条关系线」：
多场景用 `branch`/`goto` 展开，角色视角用 `as` 分派，线用 `eventId` 前缀标识（不加协议），
**推进靠加权转盘、选项只留态度题与关键岔口**，LLM 的自由度靠选项门收窄而不是文本审查。

## 为什么现在做

- 现行 `events.yaml` 仍是平铺事件 + `nextEventId` 的旧写法，95 个事件里真正的多场景分支很少；
  2026-11-18 落地的 `branch` / `as` 几乎没用上（`chains` 至今是空数组）。
- 十二年的体量用「一个事件一件事」硬堆，必然写成流水账；必须引入**线**与**蒙太奇**两层压缩。
- LLM 叙事层已接通，但没有任何「世界走到哪、角色是什么立场」的硬约束，
  一旦放开写，容易出现「夏油还没黑化就当了盘星教教主」这类事故。

## 本设计的边界

- **不做**：新引擎机制、新存档字段、新 schemaVersion、新模板协议。所有约束落在模板 + 既有 flag + 纯函数派生上。
- **不做**：把原作剧情逐格复刻。这是人生模拟器，玩家是同学/同事，不是摄像机。
- **不做**：LLM 输出审查（词表 / 共现 / premises 自检 / judge 模型）。写偏了只影响文案，不影响世界。
- **不做**：最终战（宿傩）的战斗机制与数值——只钉强度目标，交给专门的战斗与数值设计师（§10）。
- **口径**：§5 写的是**关系线**（玩家 × 角色），不是原作个人弧；原作弧只作基线，玩家改的是「他在那一步身边有没有人」。
  线型随**站位**变化（§5.0）：高专线全开、原作线只剩只读、不同结界的降为见证线（只插手一次、不改结局）。
- **已裁（不需 ADR）**：关系 `kind` 新增 `lover`（对称社会边，不进亲属称谓推导，强度走 `value`）。
- **口径**：`lore-registers.md` 里标 ⛔ 的术式是转盘原创，**原作角色一律不许用**；玩家自定义才允许。
- **已核（2026-11-19，查过百科/公式书转述/官方动画大纲）**：三处结界归属（东京第一 / 东京第二 / 仙台各自有谁，含**万在仙台**）、
  里梅术式「冰凝咒法」、乌鹭「天空/宇守罗弹」、万里锁特级、神武解效果与复制品、落花情（原误作「落花之晴」）等 10 项，
  见 `lore-registers.md` §9.1；真正原作没写的只剩 6 项（§9.2）——**不许编，只能绕**。
- **待裁决**：玩家阵营轴、理子「完全平凡」结局、蒙太奇失败惩罚、新增人物名单。见 §9。
- **台词口径**：原句只给「原本那一刻」（原作线可用全句、关系线只给半句、见证线只转述）；
  社区梗（2.5 条 / 腰斩 / 灭火器 / 坐杀摇摆舞）一律不进模板；**核不到原句就转述，不编引号**。

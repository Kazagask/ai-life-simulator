## 2. 「契约支持不支持」——三问三答

| 想做的事 | 契约 | 结论 |
| --- | --- | --- |
| 抽到某术式 ⇒ 给对应领域 | `option.goto` 可以按扇区分流 | ✅ **支持**，写法是「一术式一领域节点」，编译期展开 |
| 按「情况」改权重 | 选项**没有** `conditions`；开局 roll **拒载** `weightBy`（ADR-001 D-4，理由是**世界属性**未实例化） | ⚠️ **属性不行，参数行**。权重只读**已 roll 定的开局参数**（`origin`/`talent`/`technique`）就绕开了 D-4 的理由，需加 `weightByParam` + 一条短 ADR（见文末 §5） |
| 按「情况」改领域**池**（不是权重） | 同上，选项无 `conditions` | ❌ 仍不支持。要么权重调制，要么拆节点用 `goto` 分流 |
| 先抽「会几样」，再抽那么多次 | DAG 无循环、无计数（`goto` 回跳 = 死循环，`done` 只在无后继时置真） | ❌ **不支持**。等价实现：**每格可能落空**，三格合计 0–3 样 |

> 也就是说：**「按术式」现在就能写；「按开局结果调权重」要加 20 行代码；「按世界属性」不行。**
> 本稿领域节点里「不会 / 半成品 / 完整 / 开放」四档用的是固定权重（55 / 24 / 18 / 3），
> 一旦 `weightByParam` 落地，就可以改成 `talent` / `origin` 调制——比如「御三家旁支 ⇒ 完整领域 +18」。
> 调**池子**（某些术式根本不出货）仍然做不到，那要靠 `goto` 拆节点，或者干脆不给。

实测分布（seed 1..400，choose 取首项）：高阶技巧 **0 样 14% / 1 样 33.5% / 2 样 37.5% / 3 样 15%**；
站位 canon 34.5% / highschool 28.5% / curse-user 16% / ancient 9% / foreknowledge 8% / curse-spirit 4%（与权重 30:22:14:10:8:6 一致）。

## 3. 三个内容判断

**① 六眼不进池（外加受肉体也不进）。**
六眼与无下限、与天元的因果是绑在一起的：五条在世时不可能出现第二个六眼，写进池子就是
「白送无下限 + 无限」。同理「受肉体（宿傩容器）」是虎杖的位置，抽到即自带一个宿傩。
两者都从池子里删了，池子剩 9 项，权重按「遇到的人有多稀有」给。

**② 术式池里没有血继 / 唯一术式。**
无下限（五条家 + 六眼）、十种影法术（禅院血统）、赤血操术（加茂血统）、御厨子（宿傩）、
无为转变（真人）、咒灵操术（夏油）都在原作人物身上。陌生玩家抽到就是「两个十影」这种硬伤——
比「抽不到想要的」严重得多。留下的是 10 系原创 + 无术式（天与咒缚）+ 未觉醒。

**③ 领域名是作者命名，不是公式书。**
十个领域（无间回廊 / 百八烦恼 / 胎藏 / 须弥 / 常夜 / 梵钟 / 腐海 / 万宝槌 / 白纸黑字 / 命数转盘）
全部是我为这 10 系术式起的，**原作战里不存在**，所以不受「不许编」的约束；
但它们的必中效果必须与术式一致（影子系钉影 ⇒ 人不能动；声波系共鸣 ⇒ 从内往外碎）。
最后一个「命数转盘」是刻意回扣：运势因果系的领域就是开局那个转盘本身。

## 4. 一条写模板时必须守的纪律：一个 param id 只能有一个写者

`resolveParamMap` 是 `Object.assign` 逐条合并，**后写覆盖先写，且不报错**。
旧开局踩过：第六格选的咒具被入学式那格悄悄换成急救包（玩家实测「送的咒具没进背包」）。

本稿的对策是按节点分名：`originAttr1` / `originAttr2` / `ageAttr` / `techBodyAttr` / `domAttr` /
`talentAttr` / `talentAttr2` / `bodyAttr` / `enterAttr`，每个 id 只有一个写者。
同理三条高阶技巧用 `highSkill1/2/3` 三个独立参数——写成同一个 id 就只剩最后一条。

（静态检查过：跨节点重名的只剩 `who` / `line` / `originTag` / `clock` 与十个领域节点共用的一组，
它们**在路径上互斥**——同一局只会走到其中一个，不构成覆盖。）

## 6. 还没定的三件事

1. **2017 / 2018 起点怎么补章节**：乙骨 / 虎杖 / 伏黑 / 知情者 / 受肉 / 咒灵六条路径都用 `clock` 直接推到
   11–12 年后，跳过的章节 flag 一个都没写。要么章节表按「时间锚」重写，要么给这些路径补一段
   「跳过的十二年发生了什么」的蒙太奇节点。
2. **原作人物要不要给一点转盘加成**：现在是全跳过（进他的局）。若希望「借名字也能微调」，
   把 `c-*` 的 `goto` 从 `n-entrance` 改成 `n-talent` 即可，但这等于给五条加天赋，我不建议。
3. **咒灵线 / 古代线的年龄口径**：现在照样抽 15–32 岁，实际是「受肉体 / 拟态的年龄」。
   要不要在这两条线把年龄节点换成「苏醒年数」，取决于 L5 / L6 怎么写。

## 7. 加权转盘关联「开局参数」——设计稿，未实施

### 7.1 它为什么不违反 ADR-001 D-4

D-4 的原话是「开局期**未实例化** ⇒ 补正/最终面板无法计算，世界属性加权复用不了」。
它反对的是**读世界属性**（`inflicted`、`infamy` 那些要等面板算完才有值的），
不是反对加权本身。而 `origin` / `technique` / `talent` 是**前面节点已经 roll 定**的参数，
在本会话的 param map 里是确定值，不存在「算不出来」。

所以正确的说法是：**「按世界属性加权」不行，「按开局参数加权」可以。**

> **2026-11-19 已落**：作为 **ADR-001 D7**（不开新文档），`optionWeights()` + 加载期 dominator 校验 +
> `describeNode` 下发最终权重。本节保留为设计依据。

### 7.2 机制（已落：ADR-001 D7）

```yaml
- node: n-dom-shadow
  mode: roll
  options:
    - id: d-full
      text: 完整领域
      weight: 18
      weightByParam:
        talentTier: 0.8          # 数值参数：最终权重 += 值 × 系数
        origin:                  # 枚举参数：按落定值查表
          御三家旁支: 12
          诅咒师世家: 8
          平民: -6
```

规则：

| 项 | 约定 |
| --- | --- |
| 语义 | `final = max(0, weight + Σ 数值参数×系数 + Σ 枚举查表)`，与事件侧 `weightBy` 同一套算法，只是取值源换成 param map |
| 加载期校验 | 引用的 param 必须在此节点**之前**于所有路径上落定，否则拒载 `opening_weight_param_unresolved`（DAG 单向，天然无环，跨分支读是唯一风险） |
| 运行期缺值 | 按 0 处理（不抛错），因为「某条路径上没抽过这个参数」在语义上等于「没有偏向」 |
| 结果可见 | `describeNode` 必须把**本会话算出的最终权重**发给前端。转盘扇区面积与实际概率不一致，玩家看到的就是假盘——这是这条能力的唯一消费链路 |
| 可复现 | 权重只影响 `pickWeighted` 的入参，不改变按 node 派生的 RNG 序列；同 seed 同结果 |

### 7.3 代价与建议

- 代码：`OpeningBranchOptionSchema` **新增** `weightByParam`（`weightBy` 的 `refine` 原样保留，不拆 D-4 的墙）、
  `resolveStep` 的 roll 分支十来行、校验 2 条，**前端不用改**（只要服务端给最终权重）。
- 流程：这是 schema 改动，按 AGENTS G1 需要一份决策记录。**实际做法：作为 ADR-001 的 D7 并入**
  （它本来就是 D-4 的修订条款，单开一份会让人以为是「先拒载又放开」）。
- 排序：只影响开局手感，不影响剧情波次 —— 已在 W1 之前做完。

### 7.4 落地之后能写出来的东西

- 「御三家旁支出身 ⇒ 完整领域概率翻倍」——出身第一次有了机制后果，而不只是文案；
- 「天与咒缚 ⇒ 反转术式格几乎必空」——体质与高阶技巧的负相关；
- 「诅咒师世家 ⇒ 黑闪/束缚格权重上抬」——同一种天赋，不同门派教法不同；
- 「古代受肉 ⇒ 术式池偏向古代术式」——现在只能用两个独立节点硬拆，加了调制就能一个节点解决。

## 8. 落地记录（2026-11-19）

接进模板时改了四处，都是「照原稿直接上线会坏」的地方：

**① 十个领域节点补 `goto: n-talent`。**
DAG 的默认后继是「数组里的下一个节点」，十个领域节点是连排的 ⇒ 抽到影系领域后会接着抽声系、
毒系……一路抽完十个。实测原稿每一步都走满十个领域节点。补上 goto 后每局恰好一个。

**② `era` / `chapter` / `ready1`·`ready3` / `clock` 从入场节点挪到「出身」与「借名」两组选项。**
原因：入场节点读不到站位（DAG 只能编译期分流），而事件的 era 门（`flag: era, eq: 1`）必须与时间锚一致——
2018 年入场却标 era 1，整条 2006 事件链照常触发。现在六种出身各写自己的起点：

| 出身 | era | chapter | ready | 时间锚 |
| --- | --- | --- | --- | --- |
| 平民 / 御三家旁支 / 诅咒师世家 | 1 | 1 | ready1 | 92 天（2006-04） |
| 知情者 / 古代受肉 / 咒灵 | 2 | 5 | ready3 | 12 年（≈2018-01） |
| 五条 / 夏油 / 理子 | 1 | 1 | ready1 | 92 天 |
| 乙骨 / 虎杖 / 伏黑 | 2 | 5 | ready3 | 11 / 12 年 |

**③ 入场节点补了 20 个章节 / 死亡黑板基线旗标**（`spDone`…`moleClue`），全 `false`。
旧开局是在入学式一次性落定的；新开局漏了这批，事件里 `ne: true` / `eq: false` 的判断会退化。
晚起点「跳过的九个章节」仍统一留 `false`——章节表定稿后再按路径补（§6.1）。

**④ 用上了 `weightByParam`（ADR-001 D7）两处**，这是 §7 提议落地后的第一次实战：

| 位置 | 写法 | 语义 |
| --- | --- | --- |
| `n-high1` / `reverse` | `techFlag: { none: -18 }` | 天与咒缚没有咒力可乘 ⇒ 反转术式 20 → 2 |
| `n-talent` / `t-genius` | `originTag: { clan-branch: 6, curse-family: 4 }` | 家学：旁支 / 诅咒师世家出天才的比例更高 |

实测（seed 1–400）：天与咒缚占 39/400，其 `reverse` 权重恒为 2，其余恒为 20；
`describeNode` 下发的是**最终权重**，所以转盘扇区面积与实际概率一致。

**验收**：`pnpm inspect check` → error 0；`npx vitest run` → 381 例全绿；`pnpm typecheck` 0 错；
前端 build 通过。60 个种子跑完开局 → 12 步、恰好一个领域、`era` 与 `worldTime` 一致。

# R2.8 迭代 · 轻量模板治理（只读列表 + 目录即元数据 + 运行时热加载）

> 本文件是本轮的**范围、裁决台账与读法**说明，不是产品规格，也不是代码。
> 权威内容始终在 `AGENTS.md`、`specs/`（含本迭代四件套）、`docs/DECISIONS.md` 与代码里。

## 0. 本轮缘起（用户两次指令，逐字）

第一次：

> 模板管理先做轻量的 暂时不做市场 所有人都能导入 导入之后所有人都能看 只需要说明两个事情
> 1. 模板是什么 生成id
> 2. 模板的版本
> 选择的时候也是先选模板 再选版本
> 快照引用还是字节：引用即可，可复现只在模板还在的时候有价值 模板都不在了 也没必要复现了 后续出现问题再review
> 改 yaml 免 ADR 依旧保持 现阶段模板不是稳定资产 会非常频繁的变更 可复现诉求 仅在迭代测试中保证即可 能保证bug稳定复现 有的排查

补充：

> 此外你需要考虑模板可能不只是yaml 也可能是资源 甚至后期会开自定义函数的口子 本次保留扩展性

第二次（**砍板，覆盖第一次的导入部分**）：

> 再砍一板需求 只做读 能选就行 砍掉前端导入模板的口子 但是可以直接改服务端文件 服务端能在运行时热加载就行 运行时丢模板导致报错可容忍（基本不会这么做）

## 2. 范围

| 包含 | 说明 |
|---|---|
| **只读模板列表** | `GET /api/templates` 返回「模板 → 版本」两级；前端两级选择；开局列表按所选版本取 `openings` |
| **文件系统即管理面** | 模板 = `specs/data/templates/<id>/<version>/` 一个目录；`mkdir` 是新增、改文件是更新、`rm -rf` 是删除；**无写端点** |
| **运行时热加载** | 请求驱动 `ensureFresh()`（比对**版本目录内文件 mtime 的最大值**，不用目录 mtime），无定时器、无 `fs.watch`；只影响新建世界与后续载入；运行期单目录隔离失败，不 fail-fast |
| **内存快照隔离** | 已载入世界持有自身 `{state, template, lookup, entry}`，热加载不替换它 |
| **存档引用固化** | 信封加 `templateVersion?`；`persist` 读世界自身 ref，不再现查全局指纹表 |
| **分层指纹 + 文件角色** | `semanticFingerprint` 只算 yaml、决定可载性；`assetFingerprint` 只算 `assets/**`、只做诊断；`code` 类文件加载期 warn + 忽略 |
| **可诊断拒载** | 封闭 reason 枚举；世界列表区分「可载 / 存在但不可载」；修 E-03 |

| 明确**不做**（本轮） | 依据 |
|---|---|
| 任何导入端点 / 导入 UI / multipart / 上传体积限制 / 导入鉴权 | D-2（R-TG-17 负向守护） |
| 删除 / 下架 / 引用守卫（`disable`、`template_in_use`） | D-8「丢模板可容忍」 |
| 公开模板市场（发现/评分/搜索/下载/分享链/审核） | D-1 |
| 模板字节快照库 / 内容寻址 / 存档内嵌模板 | D-3 |
| 模板在线编辑器 | `OPEN_QUESTIONS #6` 另一半 |
| 模板副本 GC | 无引用计量 |
| owner 隔离 / 权限分级 / 审核 | 无账号体系（`ADR-0025`） |
| `fs.watch` / 定时器式热加载 | D-8（Windows / 容器挂载丢事件） |
| zip 上传 | 随导入一并砍掉 |
| 资源下发（`assets/` 存得进、用不上） | design H-7 |
| 自定义函数执行 | design H-6（四条前置） |
| 存档上云 / 跨设备续玩 | `BACKLOG B-24` |
| `schemaVersion` 升 3 | 一次性拒载现存 6 份可载档 |
| 抗 YAML 别名炸弹 | 未实测，不写进验收 |

# iteration-2026-11-19-opening-allocate

开局加点系统：抽点数 → 提交前自行分配 → 落进世界。

## 范围

- **做**：`allocate` 节点从「半成品」补成可用链路（预算动态、加载期白名单校验、运行期四条校验、
  投影带标签/样式、复用组件、开局所得、jjk 模板落地）。
- **不做**：游戏内加点的实际触发点（升级/训练/奇遇）。组件与契约先就位，注释注明复用方式（用户 2026-11-19 裁决）。
- **不做**：洗点 / 重置已加属性 / 用点数换技能（当前闭集没有「技能点」概念，技能不可量化）。

## 冲突与对齐

1. **与 ADR-001「参数闭集」**：新增 `kind: "number"` 属于闭集扩张，ADR-001 要求「新参数类型需改 core + ADR」——
   本轮的 ADR-004 即该 ADR，闭集同步更新为 13 项。
2. **与 ADR-003「enum 带样式」**：加点只对数值类属性开放，文本属性的样式能力不受影响；
   `targets[].style` 只是**标签着色提示**，不是给属性写样式。
3. **与既有测试**：`jjk2006-dag.test.ts` / `attribute-types.test.ts` / `custom-resources.test.ts`
   的 DAG 走查只处理 `roll` / `choose`，模板加入 `allocate` 后会抛 `opening_step_expects_allocate`——
   三个 helper 都要补 `allocate` 分支（按预算平均分配）。

## 验收口径

- 模板加载：target 指向 `enum`/`composite`/未声明属性 ⇒ `template_invalid`，错误信息带字段路径。
- 内核：预算不足/超额、白名单外的键、小数、负数、超上限 ⇒ 400 且错误码可诊断。
- UI：剩余点数实时、`+`/`-` 到界禁用、重置、带样式的属性名。
- 提交后：`state.player.attributes` 等于「基础值 + 分配值」，且「开局所得」列出每一项。

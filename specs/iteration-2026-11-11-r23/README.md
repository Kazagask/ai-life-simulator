## 3. 五个必须先对齐的点

新需求里有些措辞是**设计意图**，直接照搬会推翻既有决策：

1. **「修可见性」≠ 给历史加一个过滤函数就完事。** 真正要定的是**口径**：归档记录是玩家自己的存档事实，保不保留 hidden？本包建议「服务端保留全量、下发给玩家端只含 public + 一条未公开计数」，理由与替代方案见 `design.md` §2.4，需用户确认。
2. **「加存档」≠ 引入数据库。** R2.2 的 DoD 第 6 条是「无新增 npm 包」，`better-sqlite3` / `pg` 都算破线。本轮落 `node:fs` JSON 文件 + 原子写；PostgreSQL 与账号体系仍在 `OPEN_QUESTIONS` #1/#2，属 P1。
3. **「时间跨度」≠ 把每轮步长从 4 小时改成 1 个月。** 那样一次行动跨半月，叙事密度直接崩。本包走**双轨**：细粒度日常轮（现状不变）+ 粗粒度跨度轮（新增），见 `design.md` §4。
4. **「穿脱端点」≠ 服务端直接改 `state.player.equipment`。** 必须与其它行动入口同构：`game-core` 提供 `equipV2` / `unequipV2`（含 `assertActive` 门禁、历史写入、投影、终止边界），server 只做参数校验与错误码映射。否则门禁会出现第五个缺口。
5. **`mode: "fast"` 是既有死参数。** `turn.ts:492` 声明了 `mode?: "single" | "fast"`，全仓无任何读取点。本轮用它承载跨度模式，不新增命令字段（`endLife` 已占一个）。

## 4. 硬约束（继承自 `AGENTS.md`，不可协商）

- `game-core` 是确定性内核，不依赖 React / Fastify / DB / LLM SDK；对外输入一律 Zod 校验。
- 同初始状态 + 同输入 + 同 seed ⇒ 相同结果（含时间推进、历史、装备效果、AI 决策）。
- AI 只做叙事与候选生成，不得写入权威状态、不得决定评分。
- **`hidden` 不得进入玩家端 API 投影**（本轮 A 项的验收核心）。
- 世界观专属规则只能进模板，不得硬编码进通用引擎（本轮 C 项的模板可配参数受此约束）。
- 时间、随机数、ID 必须可注入；禁止 `any`；禁止吞异常。
- **改核心数据模型 / 技术栈 / 游戏规则前先写 ADR**：本轮需 **ADR-0007（存档选型与落盘格式）**、**ADR-0008（时间跨度与步长语义）**。（ADR-0006 已被「结局可见性 DSL 化」占用，2026-11-11：删除 `EndingTemplate.visibility`，统一 `unlockConditions` + `narrativeConfig.masked`。）
- 一次只做一个任务，小步提交；`DEFERRED` 只登记，不实现、不测试、不计入 DoD。

1. 先读本文件 §2/§3，确认范围与五个对齐点；有异议**停下来说明**，不要自行扩大或缩小范围。

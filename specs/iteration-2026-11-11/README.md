## 3. 必须先知道的六个对齐点

新补充方案里有些措辞是**设计意图**，不能直接照搬成实现决策，否则会推翻已有 ADR：

1. **「事件栈 / 未来事件队列」≠ 新增调度结构。** 附录 A 的 A4 已决定「保持现状：不引入事件栈，维持事件池 + chains 状态机 + `nextEventId`」。补充方案 §3.5 的意图应映射到现有 chains 状态机（当前连续事件）与 schedule 事件（未来触发），详见 `design.md` §7。
2. **「来源 `opening`」≠ 新增事件类型枚举。** A5 已决定「语义复用，不加枚举」。开局事件来源用实例级元数据 `origin` 表达，不动 `source` 枚举。
3. **「通用基础属性 / 公式覆写」不在本轮。** ADR-0002 已决定维持纯自定义属性层与 preset 白名单、拒绝自由表达式 DSL。装备与战斗 AI 只能在既有语义上扩展。
4. **「时间穿越延期」≠「把接口封死」。** 本轮不实现穿越、不写 ADR-0005，但新增的 `EventInstance`（`instanceId / definitionId`）、`TimeAdapter` 与可见性投影**不得写死「时间单调」假设**；具体预留点见 `design.md` §8 末。这是 R3 能低成本接入穿越的前提（该 seam 与阶段无关，退役 Lifecycle 不影响 R3）。
5. **「生命周期」不是本轮概念。** 补充方案把开局/结局/评价/归档统一归入 Lifecycle，但用户 2026-11-11 决定：**模拟终止要新建，六阶段状态机不要**。不得产出 `lifecycle.ts` / `Phase` / `PhaseTransitionLog`；三条不变量由 `R-TM-*` 与 `R-OP-07` / `R-EV-06` / `R-AR-02` 承担。理由与成本对比见 `design.md` §3.1。
6. **三条产品规则已由用户定夺，不得再当待决项**：装备词条统一动态补正（不写回基础属性）；HP 模拟中 ≥ 1、死亡由战败 + 条件 → 死亡事件或直接结局；条件化 AI 条件求值只读公有字段。`docs/OPEN_QUESTIONS.md` #9 / #11 / #13 已登记为已决，#27 编号冲突已解决。

## 4. 硬约束（继承自 S4，不可协商）

- `game-core` 是确定性内核，不依赖 React / Fastify / DB / LLM SDK；对外输入用 Zod 校验。
- 同初始状态 + 同输入 + 同 seed ⇒ 相同结果（含阶段序列、结局、评价、装备效果与 AI 决策）。
- AI 只做受约束叙事与候选生成，**不得写入权威状态、不得决定评分**；LLM 输出必须经结构校验，失败回退模板文本。
- 隐藏信息（`hidden`）不得进入玩家端 API 投影。
- 世界观专属规则只能进模板，不得硬编码进通用引擎；不得为逻辑拆分过度拆包。
- **改核心数据模型 / 终止标记落点之前先写 ADR**（`AGENTS.md` §0）。本包已把需 ADR 的点列在 `design.md` §12（本轮为 ADR-0004），实施阶段不得跳过。

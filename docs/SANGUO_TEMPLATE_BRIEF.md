## 2. 「天意」考据 —— 这个模板的机制内核〔① 已考据〕

**用户的直觉正好命中了一个现成的二创体系**：「天意」（又称**天意侵蚀**、**天意爷**）不是自造设定，而是新三国吐槽圈为解释"剧情离谱却总能回到历史主线"而提出的**娱乐解释理论**。

- **原剧出处**：第 20 集《煮酒论英雄》，刘备被雷惊掉筷子后对曹操说：「**迅雷乃天意，世人谁敢不畏天意？**」；另第 14 集刘备让徐州时反复说「今日之变，可以说是天意」「天授徐州与你」。
- **理论出处**：B 站 UP 主「吃蛋挞的折棒」在第 43 期正式提出，灵感被指向《命运石之门》的世界线收束；后由大量 UP 主补充派生理论。媒体（虎嗅、观察者网、腾讯新闻）把它概括为"**天降补丁**"。
- **核心命题**：存在一个高等存在「天意」，会周期性干涉世界、把偏离的历史**强行修正回主线**；角色行为突变、逻辑崩坏，都是"天意这只大手发力了"。

| 机制/术语 | 二创定义 | 转成游戏机制的直译 |
|---|---|---|
| **世界修正** | 重要历史节点强制令事件符合正史，平时保证关键人物存活；不必修正事件本身，也可只修正**所有人的认知**（关羽实际只过三关斩四将，但人人都觉得是过五关斩六将；苦肉计明明被识破却"成功"了） | ⭐ 主线锚点：到点强制收束、flag 复位、进入下一章；文案永远写"天意发力了" |
| **天意侵蚀** | 分类型干涉；已知子类**精神错乱**（智力下降、记忆错乱、感官失能、举止疯癫，如曹操发癫、荀彧"中原第一雄关"） | 可挂 status／扣属性／改叙事口吻的 debuff |
| **天意护体** | 关键人物在锚点前不会死；刘备"自刎归天"被二创解读为想提前下线脱离天意，但总被拦住 | 绝境保命（不是无敌，是"死不了但代价照付"） |
| **灵魂锁链** | 桃园结义「同年同月同日死」的单向链：刘备受损→关张同死；关羽→张飞；张飞→无人。解释二弟三弟为何拼命阻止大哥自刎 | 关系边 + 连锁状态；注意本引擎关系边语义是 `from: A, to: B, kind: father` = B 是 A 的父亲，别写反 |
| **胜利目标说** | 每个角色有独立「胜利目标」，达成才能**摆脱天意的制裁** | ⭐ 结局系统的天然母题：多结局 + 隐藏结局"摆脱天意" |
| **窃听机制** | 室内小声密谋必被偷听；**室外大喊必无人听见**（"国贼董卓嘛"即反例） | 规则怪谈式事件条件：同一密谋，室内/室外两支 |
| **三国 ELO** | 曹操「胜兵必骄→骄兵必败→败兵必哀→哀兵必胜」无限循环，被戏称内置 roguelike 状态轮转 | 可做 `statuses.yaml` 的四态轮转补正 |
| **新三国道** | 同一条山路复用二十余次，跨时空传送点 | ⭐ 魔幻化主线位移装置：任何离谱支线都"走新三国道"回到下一锚点 |

> 结论：**用户要的"剧情再离谱都能回主线"不是需要新发明的规则，而是把这套现成二创理论做成模板的显式机制**。而且它自带世界观内的合法性——所有强行收束都可以用一句「天意发力了」买单，正好符合"不严肃、魔幻"的文风。

## 4. 设计构想〔③ 构想 / 未实现 / 未裁决〕

### 4.1 定位与文风
- **不是正史、不是演义，是"新三国平行宇宙"**：正经外壳 + 荒诞内核。服化道越一本正经，台词越离谱越好笑。
- 主角用**命数转盘**开局（沿用现有 `opening.yaml` / chain 机制），出身可以是诸侯、谋士、小兵，**甚至一头乌角鲨**。
- 主线锚点按章回推进：讨董 → 陈留大食堂 → 徐州 → 官渡 → 赤壁 → 三分 → 归一。每个锚点由「天意」强制收束。
- 硬规则只有一条：**天意一定会把世界线拉回主线**；其余随便荒诞。这条既解释剧情，也解释引擎行为。

### 4.2 「天意回主线」在现有引擎里的落法（目标：**T-1 仅 yaml**）
现有模板工具箱（已核验 `events.yaml` 实际用到的 effect）：`setFlag` / `adjustFlag` / `startChain` / `advanceTo` / `applyStatus` / `cureStatus` / `adjustAttribute` / `adjustMood` / `adjustResource` / `adjustRelation` / `setNpcLifecycle` / `spawnNpc` / `unlockSkill` / `grantItem` / `log` / `setIdentity`；触发侧有 `source: chain | pool | action | hp | mp`、`kind: normal | random | combat`，结局侧有 `worldState` / `timeReached` / `playerRequested` 与 `triggerConditions` + `priority`。据此：

1. **锚点收束事件**：每个历史节点配一条高 `priority` + `once` + `conditions` 的「天意·世界线修正」chain 事件；触发时 `setFlag` 把主线锚点复位、`advanceTo` 跳到下一节点、`startChain` 进入下一章。玩家在支线里怎么浪都不影响锚点。
2. **认知改写而非状态回滚**：离谱支线的后果**不撤销**（不回滚 flag/资源，引擎也没有回滚能力），改用叙事 + `log` 让所有人"觉得事情本来就是这样"——这正是二创「世界修正」的原义，也避免为模板加内核兜底（AGENTS §0.3 第 3 条）。
3. **天意侵蚀度**：在 `attributes.order` 加一维（键必须 ⊆ `attributes.order`，加载期 fail-fast），离谱事件累加；`statuses.yaml` 定义「精神错乱 / 集体失焦 / 天意护体 / ELO 四态」补正，`applyStatus`/`cureStatus` 挂载与清除。
4. **新三国道 + 乌角鲨**：前者做成 `advanceTo` 的叙事包装（任何地理/时间跳跃都算走国道），后者做成 `items.yaml` / 战斗 NPC / 召唤技能，是"魔幻"的主要投放口。
5. **胜利目标说 → 结局**：`endings.yaml` 多条结局按 NPC 各自目标分派，隐藏结局「摆脱天意的制裁」用 `unlockConditions` + `narrativeConfig.masked`。
6. **三国杀台词**：`skills.yaml` 没有独立"台词"字段，短句放 `description`，完整台词放事件 `narrative` / 选项 `text`；**不要在 `game-core/src` 写任何专名**（`boundary.test.ts` ⑤ 强制）。

> ⚠️ 待验证：`priority` 能否抢占已入队的随机事件、`once` 与锚点 `advanceTo` 的组合是否会出现重复触发或漏触发。若引擎不支持"即时打断"，天意就退化为「**下一锚点前的收束事件**」——仍然成立，只是不打断当前槽位。**先做小样跑 playthrough 验证，别先写 3898 行 events.yaml。**

### 4.3 梗的使用纪律（建议写进模板文件头注释）
- 每条梗在 yaml 注释里标 **原句 / 人物 / 集数 / 是否二创合成句**；考据不确定的不写死集数。
- 流行句式与剧中原句分开用：叙事给原句，选项给复读梗。
- 梗是**文案与事件**，不是权威规则；不得为了让梗生效去改 schema 或内核。
- 不把「老三国」台词、未核实的自媒体杜撰台词混入。

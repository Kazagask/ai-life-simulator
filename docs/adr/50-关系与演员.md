# 50 · 关系与演员

> 覆盖 ADR-007 D2（关系是事实，`scope` 说明多少人知道）、ADR-006 D3（关系行说人话）、
> ADR-010（演员同构与能力流转）、ADR-017（关系协议收敛）。
> ADR-007 另一半（世界时间表）在 `20-事件与世界时间.md`。
> 原始记录：`archive/ADR-007-…`、`archive/ADR-006-…`、`archive/ADR-010-…`、`archive/ADR-017-…`。

**这一层的不变量**

- **关系是事实，不是观察者的属性**。「谁看得见」由边自己的 `scope` 决定，
  不由「有没有这个人的卡」决定。
- **一个人只有一个身份来源**：`state.player` 是 self 的唯一权威实体，
  被复用（扮演）的角色**不再进** `state.npcs`。
- **强度只有一个家**（ADR-017 D1）：端点是 self ⇒ `npc.relationship` 标量；其余边才带 `value`。

## ADR-007 D2 · `scope`：这条关系几个人知道

旧字段 `visibility: known | inferred | unknown | hidden` 有三个毛病：把**观察者**写进了事实；
把「猜测」和「知情」做成互斥两档（实际正交）；默认值反向（缺省 `unknown` 对当事人并不成立）。

```ts
scope: "public" | "limited" | "private"
```

| 值 | 谁能看见 |
|---|---|
| `public` | 任何人 |
| `limited` | 当事人 + `knownBy` 名单（**必须写名单**，否则等同 private，加载期拒载） |
| `private` | 只有 `from` / `to` |

- **唯一读法** `relationScopeOf(edge)`：`scope` 优先，没有时按旧 `visibility` 折算
  （`known` / `inferred` → `public`，其余 → `private`）。旧档、旧模板直载，不升 `schemaVersion`。
- **唯一判定** `relationVisibleTo(edge, viewerId)`：投影、扩展贡献边、展示层都调它，
  不许各自再判一遍。
- **一次投影只回答一个观察者**：`viewerId` 缺省 = `selfId`。不做逐卡视角 ——
  否则玩家能从别人的卡上读到不该知道的私情。
- 多跳推导行的 `scope` 由构成边**合成**（最保守一档：任一段 `private` ⇒ 整条 `private`），
  由 `extensions/family` 负责，不许自己写 `public`。
- 展示：只画**非公开**档（`公开` 是默认，逐行标等于噪音）；词表 `公开` / `部分人知道` / `仅当事人知道`。

**不做**：逐观察者的知识表（`knownBy` 只记"谁知道有这条"，不记"谁以为它是什么"）；
关系附「确信度」；事实进历史（要留痕写 `note`，只进后台编排图）。

## ADR-006 D3 · 关系行说人话

1. **「无档案」在撒谎**。行尾的胶囊要说明**为什么没有卡**：`counterpartState`
   （`unspawned` / `hidden` / `enemy`）+ 翻译「尚未登场 / 未现身 / 不在名册」。
2. **裸数值没有参照系**。数值换成档位：深厚 ≥60 / 亲近 ≥20 / 平常 ±20 内 / 疏远 ≤-20 / 敌视 ≤-60；
   原值仍放在 `title` 与进度条上。
3. **词表补全**（旧四档），英文兜底不能赌「这档永远不来」。

**明确不做**：`?` 占位行（「知道你有一段不知道的关系」）—— 泄露的是信息设计问题，等产品口径。

## ADR-010 · 演员同构与能力流转

同一个「人」有两个身份来源（`state.player` / `state.npcs`）。`actors.ts` 统一了**读**
（`actorOf` / `selfIdOf`），这一份统一**写**与**能力**。

### D1 字段同构：两个结构互为子集

不引入第三种 `V2Actor`（会与「self 唯一权威」打架），而是让字段集合互为子集：

- `V2Player` 增可选：`lifecycle` / `personality` / `goals` / `traits` / `knowledge` / `secrets` /
  `visibility` / `isEnemy` / `birthTime` / `lastActedAtTurn` / `relationship`
- `V2Npc` 增可选：`resources` / `equipment` / `growthLevel`

全部可选、无默认值 ⇒ 旧档直载。`transplantActor(source, target, groups)` 是切换 / 夺舍 / 继承的
**唯一通道**：四个分组（body / mind / identity / standing）各自独立搬运，`age` **不在任何分组**里，
源没有的字段会被删除（不留残影）。

不做「去单例」重构（`state.player` 有 142 处引用，风险高于收益）。

### D2 能力流转一律带 `who`

`grantItem` / `removeItem` / `unlockSkill` / `adjustProficiency` / `applyStatus` / `adjustResource`
增可选 `who`（缺省 = self），解析走唯一入口 `writableActorOf(state, who)`：
`who` 是 self ⇒ `state.player`；否则必须是 `state.npcs` 里 `alive` 的那个（否则静默无效并记原因）。
加载期校验 `who` 指向已声明角色。

### D3 NPC 装备与状态生效

`characters[].equipment` 可声明；战斗单位构建时静态词条叠属性、动态词条按当前状态现算 ——
与玩家**同一个函数**。`mood: 50` 硬编码改为读实例 `mood`（真 bug：NPC 心情从不影响 AI）。

**玩家侧也有关系行**（2026-11-20）：`PlayerVM.relations` 与 NPC 卡同源同函数，
两个方向都下发（`direction`）—— 关系不再只能靠在别人的卡上反向看。图见 `60-表现层与仪器.md`。

### D4 观察者视角：`viewerId` 只影响可见性

只做两件事：关系可见性按它判、写进快照供前端显示「你在看谁」。

**模板入口**（2026-11-20）：`{ type: "observeActor", actorId }` 把镜头交给别人，
`null` 收回。写进 `state.viewerId`，投影三级取 `显式参数 > state.viewerId > self`。
可以挂在行动、事件、时间表上 —— 「以父亲的眼睛看一页」是一个行动，不是调试按钮。
**不改 `self` 段** —— 观察者是「看别人」，不是「变成别人」；换人控制走 `transplantActor` + 改 `selfId`。

### D5 `relationship` 语义收窄

`npc.relationship` = 「该 NPC 对**当前 self** 的单向好感标量」，供 AI 效用评分与投影显示。

> ⚠ **本条已被 ADR-017 D1 修订**：原文写「不参与任何判定（判定一律读关系边）」，
> 现在带 `kind` 的条件在端点为 self 时**读这个标量** —— 因为强度只有这一个家，
> 「判定读边、展示读标量」正是双真相的来源。

### D6 NPC 成长走世界时间表

技能集只能由 `scheduledFacts` + `unlockSkill(who)` 增长（与 ADR-007 D1 同一定位：世界到点就该如此，
不吃主轮 RNG、一事实一次）。不引入 `character.upgrades` 第二套机制。

### D7 三个预留位置

| 场景 | 路径 | 状态 |
|---|---|---|
| 观察者 | `viewerId` | 已做 |
| 切换角色（夺舍 / 继承） | `transplantActor` + 效果 `inheritActor` | **已接模板入口**（2026-11-20） |
| 共生（一体双意识） | 未定 | 不建字段 |

**模板入口**：`{ type: "inheritActor", from, to, groups }`（2026-11-20）。
它只搬字段，不动 `state.selfId` —— 换人控制仍要另改 self；源可以是死者（继承发生在人死之后），
目标必须活着。`groups` 四选：`body` / `mind` / `identity` / `standing`。

**夺舍不需要新字段**：身体 = 目标的 `attributes` / `hp` / `statuses` / `equipment`，
意识 = 原 self 的 `skills` / `growthLevel` / `knowledge`。`age` 用 `birthTime + worldTime` 现算。

## ADR-017 · 关系协议收敛

三条归档期债，形态相同：同一件事有两个存储位置，只有一个有读者。

### D1 强度单一真源

**判据**：强度属于「`from` 对 `to` 的看法」。`to` 是 self 时（「他视你如何」）只住在
`npc.relationship`；边的 `value` 只对「当事人之外」的边有意义。

| 位置 | 行为 |
|---|---|
| 模板声明 | `to: player` 带 `value` ⇒ **加载期 error**（不静默丢：作者写了 70 就会以为 70 生效） |
| 复用角色当自己 | `to: npc-gojo`（= self）带 `value` ⇒ **折叠进标量**，声明顺序后者胜 |
| `adjustRelation` 边形态 | 端点落 self ⇒ 标量 `+= value`；边照建（kind 是事实）但不带强度 |
| `addRelationEdge` | 同上，但 `value` 是**绝对赋值**，覆盖标量 |
| 条件 `{relation, kind}` | `to` 归一后等于 self ⇒ 读标量；否则读边 |

冻结规则（ADR-0020 单向棘轮）在写标量之前判，所以「逝者的关系不再变」对两种形态同时成立。

### D2 玩家侧关系边：`playerTemplate.relations`

`characters[].relations` 的 `from` 恒为该角色 ⇒ 玩家**作为玩家**时没有地方声明「你视他为何」，
关系图上只有入边。`PlayerTemplateSchema` 加可选 `relations`：`from` 恒为 self，
`to` 必须是已声明角色，**不许写 `value`**（你的观感由行为养成）。

投影零改动：`buildRelationRows` 早按 `from === viewerId || to === viewerId` 出边，
反方向的行带 `direction: "out"` —— 缺的一直只是声明点。

### D3 `flags` 不放描述性事实

`infoVisibility:<npc>`（知情档位）与 `relationSource:<npc>`（「父亲」这类来源文字）全仓库无读者，
且都不是「可判定谓词」。都删。知情程度由三件真事实表达：

| 想知道 | 读哪 |
|---|---|
| 人物列表里有没有他 | `npc.visibility` |
| 这条关系几个人知道 | 边 `scope` |
| 他的秘密 | `npc.secrets` —— **永不投影** |

`npcSetup.visibility` 从 schema 移除，声明它 ⇒ 加载期报一句人话（不是 "Unrecognized key"）。

### D4 契约层 `relationEdge` 说 `scope`

`story.submitBranch` 的 `relationEdge` 增 `scope` + `knownBy`（`limited` 必须给名单），
旧 `visibility` 降为可选兼容 —— 模型侧只该见到一套词汇。这条关掉了 ADR-007 的遗留。

## 模板侧的写法约定（`jjk-2006/3.0.0` 实测）

- 边语义是「`to` 是 `from` 的 kind」：要表达「夜蛾视你为弟子」必须写
  `{ from: npc-yaga, to: player, kind: disciple }`；写成 `mentor` 会读成「你视夜蛾为师父」。
- **指向玩家的边不写 `value`**（现在也是加载期 error）；强度写 `relationship:`。
- 只有「世界开局就成立的事」才进初始表；会随时间成立的（「五条把惠要到自己名下」）
  写成 `scheduledFacts`。

## 关系边的方向（2026-11-20 现场事故）

**语义**：一条边 `from → to kind` 读作「`to` 是 `from` 的 `kind`」。`{ to: npc-gojo, kind: disciple }`
挂在夜蛾身上 = 「五条是夜蛾的弟子」（不是「夜蛾是五条的弟子」）。

**亲缘必须两个方向各写一条**：`heir → player father`（玩家是他父亲）+ `player → heir son`
（他是玩家儿子）是两件事，引擎**不自动互推** —— 自动补反向会凭空造出「他也认你」这种事实，
而弃养、私生、不认亲正是要表达的东西。写反了不会报错，只会在面板上读成
「小罗兰是罗兰的父亲」，所以 valmont 的出生/认领两幕把这条约定写进了 YAML 注释，
`test/unit/valmont-features.test.ts` 有一条用例专门盯方向。

### 判重按「读法」，不按「有没有事实边」（2026-11-20）

`extendRows` 原来有一句「这个人已经有事实行 ⇒ 推导行一律不要」。它在
「娶了自己的外婆」这种局面下吃掉真实信息：事实行只说「妻子」，多跳推出来的
「外婆」被当成重复整条丢弃 —— 面板上看起来就是**外婆边消失了**。

现在的规则三层：

1. **按称谓判重**：事实行已经说过同一个称谓（`kinshipTerm`）才算重复；
2. **只让多跳读法单独立行**：一跳的另一种叫法（「兄弟」对「哥哥」、「同父异母的妹妹」
   对「妹妹」）是同一段关系的用词变体，仍旧走 `kinshipTerms` 并列；
3. **已有具体血亲事实的不再推**：绕路推出来的「表兄弟」对上一个「父亲」纯属噪声。
   `relative`（远亲）不算具体血亲 —— 它本来就是「说不清哪一档」的兜底，
   多跳读法在那上面才是新信息。

配套还有一条**数据纪律**：婚姻要写**双向**（`player→她 wife` + `她→player husband`）
并调 `addSpouse`（族谱的配偶行读 `spouses`，只写边画不出来）。手写一条 `relative`
去「补」祖孙关系反而有害 —— 同类型会把推导行判成重复。

### 玩家侧的关系边必须写（2026-11-20）

关系图只画出边之后，`playerTemplate.relations` 从「锦上添花」变成**必需**：
只写 `characters[].relations` 那一侧（`to: player`）的话，玩家的图会整张空掉。
jjk-2006 第一版正是这样，补了六条镜像（mentor / friend / colleague）。

玩家侧边**不写 `value`**（加载期拒载）：你自己的观感由行为养成，模板不能替你定。

### 皮肤属于身体，不参与字段搬运（2026-11-24）

`ActorSkinState { skinId?, customSkin? }` 加在 `V2Player` / `V2Npc` 的公共结构上，
但**故意不进 `ACTOR_FIELD_GROUPS`**（`packages/game-core/src/v2/actors.ts`）的任何一组。

- `transplantActor` 的语义是「覆盖列出来的字段」，未列字段留在目标身上 ⇒ 皮肤跟着**身体**走。
- 羂索夺舍夏油：`groups: [mind]` ⇒ `npc-geto` 的 `skinId` 不变 ⇒ 显示的是夏油的形象。
  要表现缝合线，由剧情 `setSkin` 切到对应皮肤，**不是**让搬运把上一具身体的长相带过来。
- 与 `age` 同一档：`age` 也是「不搬运、按 `birthTime + worldTime` 现算」，理由写在同一个常量上方。

**被否**：把 `skinId` 放进 `identity`（切换角色时一起搬）。否它的理由是 `identity` 搬的是「他是谁」，
而皮肤是「这具身体现在长什么样」—— 夺舍之后「谁」换了、「长相」没换，两者本来就不同步。

**`setSkin` 的作用域**（2026-11-24 评审核定）：不限剧情 / 战斗场景，但

- 只能写**已存在的、可写的人物实例**（`writableActorOf`）；不存在的 id 静默跳过（与 `inheritActor` 同策略）；
- **不支持战斗临时单位**（没有 NPC 实例的敌人 / 召唤物）—— 它们的形象由 `Combatant.characterId` 只读解析；
- 只写 `skinId`，**不碰任何数值与身份字段**；`skinId: null` = 清除覆盖、回到规则。

# 70 · 本地化与离线（模板 / 存档 / 服务端退场）

> 现行口径。上游裁决见 `docs/BACKLOG.md` 顶部的「方向约束（2026-11-20）」。
> 本卷只回答一件事：**没有云端时，世界从哪儿来、存在哪儿、谁来算。**

## 不变量

1. **游戏核心不依赖网络**：`packages/game-core` 只依赖 `@life-sim/shared` + `zod`，
   零 `node:` 导入 —— 这一条今天成立，本卷不得破坏。
2. **判定与来源分离**：模板「是否合法、指纹是多少」与「文件从磁盘 / fetch / IndexedDB 来」
   是两件事。前者只吃 `TemplateSource`，后者是可以替换的适配器。
3. **LLM 的调用形态不变**：一次 invocation = 多轮工具循环 + 叙事正文，`story.submitBranch`
   仍是唯一写入口。去服务化不改变这件事。
4. **拒载必须在加载期暴露**：模板版本不兼容、指纹漂移、扩展缺失，一律在拿到模板时判定，
   不允许「先玩起来，玩到一半才发现缺文件」。
5. **旧档不静默漂移**：语义指纹变了就拒载，不做「尽力迁移」。

## 三期（按序，不并行）

| 期 | 目标 | 完成判据 |
|---|---|---|
| **一 · 迁位置** | 模板与存档不再挂在服务端机器上 | 模板可由内存源加载；存档读写走接口，fs 只是其中一个实现 |
| 二 · 下资源 | 模板与资产从云端下载 → 客户端校验 → 本地存 | 断网后仍能打开已下载的世界 |
| 三 · 去服务化 | 去掉 server，走 Service Worker；远端只存云存档 | 浏览器直连 provider，无中转 |

### 第一期：`TemplateSource`

```ts
interface TemplateSource {
  list(relDir: string): readonly { rel: string; kind: "file" | "dir" }[];
  read(rel: string): string;
  exists(rel: string): boolean;
}
```

- **接口在 `packages/shared/src/template-source.ts`**（契约层），实现各自在适配器：
  `FsTemplateSource`（服务端，`apps/server/src/template-source-fs.ts`）、
  `MemoryTemplateSource`（测试 / 客户端预热，同一文件里给纯实现）。
- **纯层**：`loadTemplateFromSource(source, files?)` 负责合并分域、schema、跨文件引用与
  扩展版本核对。服务端 `scanVersion` 只负责目录发现、mtime、资产扫描与注册表策略。
- **同步接口**：整条加载链是同步的。客户端在拿到字节后先建内存源，不做异步 loader
  （异步会把 `createWorldV2` 的调用点全部染成 async，收益为零）。
- **验收**：把同一批文件塞进内存源，`loadTemplateFromSource` 的结果必须与磁盘加载
  **逐字段相等**（`test/unit/template-source.test.ts`）。这条成立，客户端与服务端就不会
  算出两个世界。

### 存档：`WorldStore`

服务端今天是 `data/worlds/*.json` 直读直写。第一期只做接口化，不换默认实现：

```ts
interface WorldStore {
  list(): readonly WorldMeta[];
  read(id: string): WorldStateV2 | undefined;
  write(state: WorldStateV2): void;
  remove(id: string): void;
}
```

- fs 适配器保持现有目录与文件格式（零迁移），客户端适配器（IndexedDB）在第二期接。
- **指纹校验留在 store 之上**：store 只搬字节，不判断能不能载入 —— 否则每个适配器都要
  抄一遍拒载逻辑。

### 两个前置决定（第一期开工前定）

1. **L2 扩展的运行时 —— 已裁决（2026-11-21）：编进 web bundle 白名单。**
   > 用户原话：「加扩展就重新构建 编进去就行了」。

   - 扩展仍是 TS 包（`extensions/*`），**模板包里不带任何代码**；构建期由
     `apps/server/src/extensions.ts` 与 `apps/web/src/extensions.ts` 各注册一行。
   - 模板 `extensions:` 声明了没编入的 id ⇒ 加载期 `unknown_extension`（只废该版本，不崩进程）。
   - **代价**：加扩展 / 改扩展 = 重新构建前端与后端；不能热插拔。
   - **收益**：浏览器与 Service Worker 里不需要扩展运行时（不能执行下载来的任意 TS），
     第三期去服务端时这条路是通的。
   - **守卫**（机械）：`test/unit/extension-build.test.ts` 断言
     ① 前端 `webExtensionIds` 与后端 `installedExtensionIds()` 完全一致；
     ② 所有模板声明的扩展 id 都在这批里。任何一边漏编，CI 直接挂。
   - 被否的两个方案：L2 降级为纯 yaml（family 这种要跑图算法的扩展写不出来）、
     保留薄扩展 host（没去干净，SW 里还要再养一个运行时）。

2. **拒载的客户端表达**（未定）：今天 `template_content_drift` / `schema_version_mismatch`
   只是服务端日志里的 `save_skipped`；客户端自己持有模板后，这是玩家眼前的一屏错误。
   - 需要：错误页（说清「哪个世界、哪个版本、为什么」）+ 「保留旧模板版本」策略
     （至少留最近一个能载入的版本，否则一次更新废掉所有档）。

### 第三期：去服务化（2026-11-21 开工）

目标收窄为一句可验收的话：**服务端只剩「读模板」与「同步存档」**。切分（`specs/iteration-2026-11-21-local-play/tasks.md`）：

| 任务 | 内容 | 关键决定 |
|---|---|---|
| T1 | 运行时包下沉 | `loadTemplateBundle` 进纯加载器；服务端 `scanVersion` 与客户端下载包共用 |
| T2 | 本地世界仓库 | 客户端另起**异步** `LocalWorldRepo`，不改 shared 的同步 `WorldStore` |
| T3 | 本地引擎会话 | 只调 core 入口，投影参数与服务端 `projectWorld` 同串 |
| T4 | 传输适配层 | `api` 同形状的本地实现，组件零改动 |
| T5 | 存档同步 | `PUT/GET /api/sync/worlds...`，服务端只搬字节 |
| T6 | LLM 客户端化 | 浏览器内 gateway；失败回退模板 |

- **为什么另起异步接口**：`WorldStore` 是 fs 语义的同步接口，IndexedDB 是异步。为了客户端
  把服务端 10 个调用点全改成 `await` 是纯亏，而两端本来就不共享"文件从哪来"。
  判定（信封 / 版本 / 指纹 / schema）仍在接口之上 —— 与第一期同一条纪律。
- **本轮不接 LLM**：先把「无 LLM 也能完整玩一轮」跑通，再把 gateway 搬进浏览器；
  顺序反了会同时调协议与网络两件事。
- **老档不动**：服务端世界继续在服务端跑（T4 的远端回退），不做迁移。

### 不做 / 本轮边界

- **不做**异步模板加载链（见上）。
- **不做**资产二进制通道：`assets/**` 仍由服务端 fs 扫描，指纹与清单逻辑不动；
  第二期下载时才需要给 `TemplateSource` 加二进制读。
- **不做**服务端退场：第三期之前，`apps/server` 仍是唯一能起局的地方；本卷只是把
  「从哪儿读」这一步解耦，不改 API 形态。
- **不改** `templates.ts` 的目录发现 / mtime / 热加载：它们属于适配器，第二期再由客户端
  适配器各自实现。

## 三类指纹与媒体缓存（2026-11-24）

### 指纹分工

| 指纹 | 覆盖 | 变化时 |
|---|---|---|
| `semanticFingerprint` | 机制：world / characters / skills / items / statuses / events / equipment / combat-ai / opening / endings / evaluation / rules / lore | 拒载（`template_content_drift`） |
| `assetFingerprint` | `assets/manifest.yaml` + 资源字节 | 只刷新资源，不拒载 |
| `legacyFingerprint` | 旧算法（含 manifest，排除 ui.yaml） | 只用来识别旧档，不下发 |

- 新 `semanticFingerprint` **再排除 `assets/manifest.yaml`**：它决定「能不能看见图」，不参与任何判定。
- **换算法本身会让旧档对不上**，所以存档记录新增可选 `fingerprintVersion`：
  - 带 `fingerprintVersion: 2` 的档**只**校验 `v2`；
  - 没有版本号的旧档算两个值：命中 `v2` 就认；命中 `legacy` 就**放行并就地升级**成 `{ v2, version: 2 }`；
    都不命中 ⇒ `template_content_drift`。
- **安全性的依据**（2026-11-24 评审核正，上一版写成了循环论证）：
  不是「legacy 与 v2 相等」，而是「存档值 == **当前模板用同一套旧算法**算出的值」。
  这等价于「当前模板在旧算法眼里就是当年那份」，而旧算法覆盖的是机制文件 + manifest 的**超集**
  ⇒ 机制文件逐个未变 ⇒ 不会有真实漂移被放行。
- 唯一损失面：存档时 manifest 存在、之后又被改过（两值都对不上 ⇒ 判漂移）。
  **这是硬损失，不做兜底**——旧档里没有任何信息能区分「manifest 改了」还是「机制改了」。
  当前模板从未有过 manifest，本轮窗口实际损失为零；此后每个存档都带版本号，这一格不再出现。

### 媒体缓存

- 独立 `Cache Storage`，名字 **不带 `life-sim-` 前缀**（`character-media`）——
  `activate` 会删掉所有 `life-sim-*` 旧缓存，带前缀等于每次部署清空媒体。
- 只拦 `GET /api/templates/:id/:version/assets/:assetId`，`stale-while-revalidate`：
  先回缓存，后台 `fetch` 覆盖，**后台写必须包在 `event.waitUntil` 里**（否则 SW 被回收，写一半）。
- 上限 128 MB，**FIFO** 淘汰到 80%（`Cache` 读不到访问时间，伪 LRU 更贵且不准）。
- **URL 带 `?v=<assetFingerprint 前 8 位>`**：作者换图 ⇒ 指纹变 ⇒ URL 变 ⇒ 天然不命中旧缓存。
- 后台回 404 ⇒ **删除该条**，不再无限回旧图；同一 URL 的并发刷新用 `Map<url, Promise>` 去重。
- 尊重响应头：`Cache-Control: no-store` 的资源不写缓存。
- 其余 `/api/*` 仍然 network-only（JSON 与 `package` 已有 IndexedDB 包缓存，不进 Cache Storage）。

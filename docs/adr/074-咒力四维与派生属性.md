# 74 · 咒力四维拆分与派生属性

> **状态：已定稿并落地（2026-11-23，用户口述裁决）。**
> 上游：ADR-003（属性类型）、ADR-011（有效属性下限）、ADR-018（状态三类）、ADR-073（暴击与钩子）。

---

## 0. 用户裁决

> 原有咒力属性（不是 mp 咒力）拆分为咒力输出 / 咒力总量 / 咒力操作 / 咒力效率。
>
> - 咒力输出 = 技能伤害
> - 咒力操作 = 暴击率、黑闪资质
> - 咒力效率 = mp 消耗
> - 咒力总量 = hp、mp 最大值
> - 咒力 = mp（资源和总量挂钩，无基础值，普通人的总量不等于 0）
> - 体术 = 体术系技能伤害、hp
> - 敏捷 = 闪避率
> - 天与咒缚 = 总量按比例换成体术与敏捷，最终总量 = 0、mp = 0
>
> 属性/资源最大值需要一个新字段，声明「这个值依赖其他属性」；编译模板时阻止循环依赖，
> 计算最终面板属性时按依赖顺序算。黑闪：暴击后按黑闪资质（最终属性）判定，
> 通过则暴击伤害 ^2.5，挂「黑闪」——层数无上限、持续到战斗结束、不可驱散。

---

## 1. 为什么不是「四条都存盘」

四条都落存档会立刻产生一个死结：**开局加点只加一条**。加总量，输出/操作/效率不涨，
「练了咒力但伤害不变」；四条都加，加点预算与 UI 立刻变成四倍复杂度。

所以：`cursedEnergyTotal` 是**唯一存盘**的那条，另外三条是**派生**：

| 属性 | 存盘 | 公式 | 语义 |
|---|---|---|---|
| `cursedEnergyTotal` 咒力总量 | ✅ | — | 唯一的基础量；普通人默认 5，不是 0 |
| `cursedEnergyOutput` 咒力输出 | ❌ | `总量 × 1.0` | 技能伤害 |
| `cursedEnergyControl` 咒力操作 | ❌ | `总量 × 0.4` | 暴击率、黑闪资质 |
| `cursedEnergyEfficiency` 咒力效率 | ❌ | `总量 × 0.5` | mp 消耗 |

派生属性**可以被 `attributeModifiers` 补正**（六眼 +30 操作 / +60 效率），
所以「输出高但总量低」这种角色仍然写得出来 —— 公式只是缺省比例，不是天花板。

## 2. 派生属性协议

```yaml
attributes:
  defs:
    critRate:
      kind: number
      derived:
        base: 3
        from: [{ attribute: cursedEnergyControl, perPoint: 0.2 }]
        max: 40
```

- 值 = `base + Σ perPoint × 依赖属性的最终值`，再夹 `min/max`；
- **只读**：`setAttribute` / `adjustAttribute` / 开局 attribute 参数 / 角色卡直接赋值，加载期与运行期都拒；
- **不落存档**：`state.player.attributes` 里永远不会出现它；
- `signed: true`：允许负值（`mpCostRate: -37.5` = 便宜 37.5%），跳开「属性不为负」的兜底；
- `role`（`critRate | evadeRate | mpCostRate`）：**引擎按角色找属性，不认属性 id**。
  世界把暴击率叫 `myCrit` 也行；没声明角色 ⇒ 这条通道不存在（引擎退回世界/技能/状态的暴击词条）。
  同一模板内每个角色只能有一个属性，重复在加载期拒。

### 求值顺序（`effectiveAttributes`）

```
基础值（跳过派生键）
→ 状态/装备/心情的 attributeModifiers（派生键的补正先存着）
→ 属性转化（天与咒缚）
→ 派生属性（拓扑序：依赖在前；补正在公式之后加）
→ caps
→ 负值夹 0（signed 属性除外）
```

### 加载期校验

- 依赖必须存在、必须是数值属性、不能依赖自己、不能重复；
- **循环依赖直接拒载**（`attributes.defs[id].derived` 报「循环依赖」）——
  运行期没有「先算谁」的答案，DFS 顺序只是实现细节，不能当规则；
- 派生属性出现在任何写点（defaults / 角色卡 / `setAttribute` / `adjustAttribute` / 加点目标）都拒。

## 3. 属性转化（天与咒缚）

```yaml
- id: heavenly-restriction
  kind: talent
  conversion:
    - { from: cursedEnergyTotal, to: { physique: 0.5, agility: 0.35 } }
```

- 取 `from` 的**最终值**，按比例加到目标，`from` 归零；只能挂在 `kind: talent` 上；
- 因为转化在派生计算**之前**，由 `from` 派生的输出/操作/效率会一起归零 ——
  「没有咒力的人」不会残留一条输出；
- `mp` 上限也随总量归零（见 §4），这就是「mp = 0（计算后）」。

角色卡写法：甚尔 `cursedEnergyTotal: 30, physique: 1, agility: 4` ⇒ 最终 16 / 14.5、总量 0、mp 0。
**刻意不写「0 + 高基础值」**：那样转化规则一次都不会被走到，等于没实现。

## 4. 资源上限读有效属性

`maxHp(player, template, attrs?)` / `maxMp(...)` 的第三参缺省是基础属性（旧调用点零迁移），
但**战斗、投影、开局、木桩**都必须传 `effectiveAttributesOfActor`。

不这么做会出现：「最终总量 = 0」的角色面板上仍写着 60 点 mp，战斗里也能放术式 ——
换算只发生在显示层，等于没发生。

## 5. 战斗接线

| 通道 | 读什么 | 位置 |
|---|---|---|
| 技能伤害 | 模板 `scaleBy: cursedEnergyOutput`（体术系写 `physique`） | `rollFormula` |
| 命中判定 | 模板 `hitCheck.attacker/defender: cursedEnergyControl` | `hitChance` |
| 暴击率 | `role: critRate` 的属性（百分点） | `critOf`，夹 [0,1] |
| 闪避率 | `role: evadeRate` 的属性（百分点） | `evadeOf`，独立一道门 `1-Π(1-x)`；日志来源名取 `attributes.labels` |
| mp 消耗 | `role: mpCostRate` 的属性（百分点，负数=便宜） | `effectiveCost`，与状态 `costMultiplier` 同乘区 |
| HP / MP 上限 | `cursedEnergyTotal` + `physique` | 资源公式 |

jjk 的系数（都在 `world.yaml`，改数值不用改引擎）：

```yaml
critRate:    role: critRate,   base 3, control × 0.2, max 40
evadeRate:   role: evadeRate,  agility × 1, max 50
mpCostRate:  role: mpCostRate, efficiency × -0.6, min -90, signed: true
hp:          75 + 4×总量 + 2×体术
mp:          0 + 2×总量
```

世界的 `combat.crit` 只保留 `multiplier: 1.5`；**不再写 `chance`**，否则会与 `critRate` 的底数叠成两个。

## 6. 黑闪（对 ADR-073 的修订）

- 资质 = `cursedEnergyControl` 的**最终值**（含状态/装备补正），每点 0.3%；
- 判定链不变：`crit` → 资质骰 → `critExponent 2.5`（1.5^2.5 ≈ 2.76）；
- `black-flash` 状态：`stacking: stack`（**层数无上限**）、不写 `rounds`（撑到战斗结束）、
  `dispellable: false`；
- `cureStatus` 与战斗道具的解除都尊重 `dispellable: false`。天赋本来就不在驱散候选集里。

## 9. 通用性自查（2026-11-23）

针对「引擎里有没有把某个作品硬编码进来」做了一次全量扫描，结果与处置：

| 发现 | 性质 | 处置 |
|---|---|---|
| `critOf / evadeOf / effectiveCost` 直接读 `critRate / evadeRate / mpCostRate` 三个**属性 id** | 真耦合：换世界必须叫同名才有暴击/闪避/折扣 | 改成模板声明 `role`，引擎按角色找；找不到 = 没有这条通道 |
| 开局序章写死「只展示咒力/体术/敏捷/智力/幸运」 | 真耦合：别的世界开场白一条属性都没有 | 改读 `statusBar` 的 attribute 段（退回 `attributes.order`），跳 hidden / 非数值，最多 5 条 |
| 内核注释里大量以某个作品举例（六眼 -90%、天与咒缚、npc-gojo…） | 不影响运行，但会被下一个人抄进逻辑 | 全部改成通用表述；新增 `engine-generic.test.ts` 连注释一起守 |
| `makeTestTemplate` 夹具用 `cursedEnergy` | 测试专用，但会被当成“引擎词汇” | 改名 `energy`；YAML 旧夹具（`test/fixtures`）保留，它们只是数据 |
| `templateId ===` / 按世界分支 | 未发现 | 守卫里加静态模式检查 |

守卫（`test/unit/engine-generic.test.ts`）覆盖 `game-core / shared / template-loader /
agent-runtime / apps/server/src/narrative`，禁用词包括作品名、角色 id、世界专属属性/状态 id，
并要求源码里不出现 `templateId ===` / `world === "..."` 这类分支。

## 10. 不做 / 风险

- **不做**「属性依赖资源」：资源上限依赖属性，反过来会成环；
- **不做**运行时新增派生属性（模板加载期定死，调试期改模板重启）；
- 风险：闪避进基础盘之后，所有命中率整体下降约 5–20% —— 数值验收写区间，不写死单点；
- 风险：`attributeModifiers` 指向派生属性时，账本的归因是「补正」而不是「公式」，
  所以账本以**公式裸值**作基础（见 `presentation/ledger.ts`）。

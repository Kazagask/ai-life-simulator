# 60 · 表现层与仪器

> 覆盖 ADR-002（表现层协议）、ADR-015（技能封印与状态时长口径）、ADR-011 D4（战斗仪器）。
> 原始记录：`archive/ADR-002-…`、`archive/ADR-015-…`、`archive/ADR-011-…`。

**这一层的不变量**

- **投影是只读的**：所有 VM 字段都由权威状态**派生**，没有一个字段反过来写状态。
  写状态只有一条路：`story.submitBranch`（以及开局 commit）。
- **样式是引擎词，标签是模板词**。模板给「这个词叫什么」，引擎给「它长什么样」。
- **同一个数只写一遍**：文案与判定必须来自同一个函数，否则会出现「面板写 18、实际扣 2」。

## ADR-002 · 表现层协议

### D1 表现层字段一律只读投影

`V2Snapshot` 里的样式 / 效果摘要 / 收获 / 叙事全是派生。客户端不写权威状态。

### D2 样式词汇受控：枚举 + 颜色 token

- 预设 7 种 style + `#hex` / token + 4 种动画；解析在**投影期**；
- 未知 id ⇒ **加载期拒载**（不是静默回退成灰色）。

### D2b 标签是模板词，样式是引擎词

模板只写标签名；引擎按预设把标签映射到样式类。两者分离，模板不会长出一套 CSS。

**样式的落点是名字，不是句子**（2026-11-20 用户裁决）：效果条目常是「施加 束缚」
「战斗中每回合施加 适应」这种句子，样式只能染在**被引用实体的名字**上。
把整句塞进 `StyledName` 会让「施加」「每回合」「召唤 3 只」跟着变色加粗。

**契约给三段，不给整句**：`EffectSummary` 带 `lead / refName / trail`（`text` 由三段拼出，
仅供无障碍与复制）。UI 直接渲染三段，**不做字符串切分** —— 早先按 `refDetail.title` 在
整句里找位置，文案改一个字样式范围就漂。
**可点条目也一样**：「施加 束缚（2 回合）」里只有名字带下划线（`.ls-effect__link > span`），
按钮本身 `text-decoration: none` —— 整颗按钮带下划线时，「施加」「（2 回合）」也会被读成链接的一部分。胶囊（`status-chip`）保持现状，`×N` 与名字同色。

**隐藏状态整条不拼**：`visibility: hidden` 的状态在效果摘要里连名字都不出现
（也不写成「施加 未知效果」——那等于告诉玩家这里有个查不到的东西）。

### D2c 品级是标签，正负是字段（2026-11-20 修订）

原先「增益 / 异常」是引擎预置 tag（`buff` / `abnormal` / `neutral`），靠
`toneOfTags` 反推正负。问题有两个：同一个词既当**分类**又当**配色来源**，
补一个标签就改了游戏语义；而 `buff` 与品级标签写在同一个 `tags` 数组里，
「神话·增益」到底算身份还是算正负，取决于数组顺序。

现在：

- `statuses[].polarity: positive | negative | neutral` **必填**，是状态的正负唯一来源；
- 语义标签（`buff` / `abnormal` / `neutral`）**不再参与状态配色**；
- 品级标签（`mythic-unique` 这类）仍然给**身份色**（六眼的流动彩虹），
  与「战斗中绿/红/灰」是两套口径，互不覆盖。

`resolveEntityStyle` 在实体有 `polarity` 时会把语义标签从配色候选里剔除，
只保留品级标签 —— 于是「个人面板看身份、战斗看正负」同时成立。

### D2d 战斗态用**语义色**，与身份色分离

「中毒」这类状态的色不跟角色主题走，否则红队中毒看不出是中毒。

**实现上不再下发 `battleStyle`**（2026-11-20）：后端只给 `polarity`，
前端用 `ls-tone--positive / negative / neutral` 三档类名上色。
战斗芯片与技能描述里的状态引用（「施加 束缚」）都读同一份正负 ——
后端不再为「战斗中长什么样」做第二份解析，也就没有两处颜色漂移的可能。

**文案同源**：施加时按正负选动词 —— 增益「获得了「X」」、异常「陷入了「X」」、
中性「「X」生效」。`hidden` 的状态连名字都不写（名字本身就是情报）。

### D2e `quality` 与品级标签合流

### D2f 四档光谱并入阶梯：**十四档平铺**

唯一入口 `isQualityTier(id)` / `QUALITY_TIER_IDS`。不允许多处各写一份档位表
（三档 / 四档并存曾是「同样品质显示不同色」的来源）。

### D3 效果摘要由**定义**派生

动态状态只描述规则（「每回合受到 4 点」），不把当前层数算进去 —— 层数是实例的事。
`statusEffectSummaries` / `skillEffectSummaries` 是唯一出口。

**浮层可分节**（2026-11-20）：`DetailSheetData.groups[]` 让一个浮层按「一行一个」列出多组
「标题 + 效果」（召唤物的技能表就是每行一个技能）。分节里仍然复用 `EffectList`，
所以「施加 X」这些引用条目照旧可点，而状态浮窗是**再叠一层** `DetailSheet`
（宿主维护栈，`onOpenRef` 统一推送）—— 不在分节里另写一套排版或第二套效果文案。

**常驻状态用芯片**：召唤物 `characters[].statuses` 声明的被动（如魔虚罗的法轮）不属于技能表，
浮层用与个人页同一套 `status-chip` 展示，点开走 `onOpenChip` 再叠一层状态浮层。
理由同上：状态只有一种展示形态，**不要在浮层里复述效果文案**。

**召唤合成一个对象**（2026-11-20）：`SkillVM.summon = { count, levelScale?, unit }` ——
`count / levelScale` 是**技能参数**，`unit` 是**召唤物面板**
（`ref/name/tier/description/skills/statuses`）。拆成两个可选字段时，只给其一会让 UI 半残
（链接缺前缀 / 浮层打不开），合成后「有召唤」只有一种形状。
两者都**不进召唤浮层**：技能参数由 `skillEffectSummaries` 写成技能自己的两行
（`召唤 1 名 · 强度 ×1.0`、`名额：英雄档共用 1 个位置`），浮层只描述「它是谁」。
名额是 `world.summonLimits` 的世界规则，VM 不重复下发（同一份数字只写一遍）。

**时长只属于施加点**：状态定义没有时长（ADR-009 D1），所以
① 技能行写「施加 束缚（2 回合，自身）」；② `refDetail` 不带 `durationLabel`；
③ 定义视图走**单独入口** `statusViewOfDefinition`（不经 `StatusInstance`，天然没有
`durationLabel`）—— 以前为了复用实例投影会伪造 `appliedAt=now` 再显示「直到被移除」，
那是假事实。

**代价只有一份**：`BattleSkillVM` 只发 `costs[]`（可扩展资源），不再留 `costMp`
兼容副本 —— 两个数迟早会漂；前端要 MP 就从 `costs` 里取。

### D4 回合增量 = 基线 + 差分，**不落库**

「本轮收获」是投影算出来的差，不写进存档。理由是它属于体验而非事实 ——
落库就会出现「读档后收获卡还在」这种鬼。

### D5 叙事按回合追加；模板兜底走同一条 trace

- 叙事是**全量累积**（ADR-002 采纳，用户裁决），前端只给最新回合播打字机；
- 兜底判据是 **`provider === "mock"`**，不是「trace 里有没有块」——
  invocation 落盘与事务收尾不保证先后，实测会重复写；
- 叙事**不参与**回合管线：`generateNarrative` 只装饰。

### D5b 结局与评价：同一屏、同一次装饰（2026-11-21）

用户反馈「结局没有 LLM 收尾和评价」。核对后是两个真实缺口，不是没接线：

1. **评价总结只在 `POST /archive` 生成** ⇒ 终止那一刻永远是引擎拼的
   「本局共记录 N 条经历」。现在收束时就生成（`evaluationOutcomeFor`），
   归档**复用同一份缓存**（键 `worldId:turn:perspective`，评价再加 `:evaluation`），
   不会让模型把同一段盖棺文案写两遍。
2. **请求里没有本局事实** ⇒ 模型只能复述模板句。现在两条请求都带
   `facts.history`：玩家可见经历（`historyDigestOf`，最近 80 条、单条 140 字，
   hidden 先滤掉），以及一条 `instruction`（字数、人称、不许编）。证据白名单
   `allowedEvidenceIds` 不变 —— 素材变多不等于允许编事实。

展示口径：

- **结局卡 = 结局收尾 + 五维评价**，同屏给出；卡面（`CharacterSheet`）不再重复
  评价分项（实机上相隔不到 100px，同一份数据出现两次）。个人页的评价块保留。
- `EvaluationVM.summarySource` 随投影下发，前端据此决定是否打「AI 叙事」标；
  `template` / `fallback` 不标（不把引擎文案说成模型写的）。
- 总结只覆盖 `summary` / `summarySource`，分项、总分、`canonDeviation` 逐字段不变
  （`decorateEvaluationView` 是纯函数，隐藏结局整块跳过）。

### D5c 条件 instruction：同一章的不同分支各写一句（2026-11-21）

`invoke.instruction` 从「一个字符串」扩成「字符串 ∪ 变体数组」：

```yaml
instruction:
  - as: npc-riko        # 「当前 self 是谁」的快捷写法：as: X ⇔ when: [{ selfIs: X }]
    text: 写「出发前那一晚」，你是被护送的那个人……
  - text: 写「出发前那一晚」，你是被派去护卫星浆体的人……   # 兜底（无 as）
```

- **`as` 与事件节点级的 `as` 是同一套语义**（ADR-010 D4）：它**参与判定**，
  选的是「这句话给谁看」，不往正文里加任何身份前缀。第一次实现把它当成「人称标签」
  渲染成「以「X」的身份」——用户当场纠正：要的是能判定的快捷语法，不是旁白。
- **选哪一条**：按声明序取第一个命中的；命中 = `as`（self 匹配，缺省不限）∧ `when`（条件 DSL，AND）。
  两者可叠加，用旗标在某个 self 内部再收窄。
- **有 `as` 变体就必须留一条无 `as` 的兜底** —— 与 ADR-010 D4 同规，写在 schema 的
  `superRefine` 里，加载期直接拒（运行期静默拿不到 instruction 是最难查的一类空场）。
- 求值用**独立派生流**（salt 53 + 触发器下标）：变体里写 `random` 也不会改变触发器
  本身的随机序列（同 seed 的既有对局不漂）。

**顺带修掉一个静默失效**：`condition-evaluator` 的扁平求值表只覆盖了一半 DSL
（`selfIs` / `selfIsNot` / `relation` / `mood` / `npcState` 整支缺失，`time` 是恒真占位）。
rules.yaml 里写这些条件**恒为假且不报诊断**；条件 instruction 的 `as` 依赖 `selfIs`，
才把它暴露出来。现在补齐到与 `engine.checkCondition` 同义，并有 parity 用例守着
（`attribute` 故意不比：引擎读有效值、触发器读原始值，是既有口径差异）。

### D5d 提示词卫生：通用运行时里不许有世界事实（2026-11-21 自查）

工具描述、写作指令、词表都是**所有模板共用**的一段话。它们一旦写进某个世界的叫法，
模型就会照抄，换一个世界全错。三条纪律 + 一个守卫：

1. **不写专名**：示例里的角色写 `<角色id>`，不写 `npc-yuji`；资源写模板的 label
   （`lookup.resourceLabel` / `statusBar[].label`），不写「咒力」。
   投影与日志同理 —— `seal.ts` 的 `not_enough_mp` 以前直接返回「咒力不足」。
2. **数字只有一处定义**：分支块数 `BRANCH_MAX_NODES`、选项效果数
   `BRANCH_MAX_EFFECTS_PER_OPTION`、生成 NPC 属性上限 `GENERATED_NPC_ATTRIBUTE_MAX`、
   历史条数 `HISTORY_HARD_CAP` 都是 shared / runtime 里的常量，schema、工具描述、
   工具表 `maxItems` 三处引用同一个。以前三处各写各的：模型按描述写 12 块、schema 只收
   8 块时，整轮作废且没人知道为什么。
3. **世界事实从模板读**：心情量程（`mood.min/max`）、资源叫法（`statusBar`）都在
   词表工具里现算；「一次挪多少」按量程的 1/10 给，而不是写死 ±10（窄量程世界会被一句
   话顶到上限）。

守卫：`test/unit/prompt-hygiene.test.ts` —— 扫所有模板 × 所有画像的工具描述，
不许出现 `npc-` / 「咒」/ 世界名；断言描述里的数字与常量、schema 上限三方一致；
换一个 mp 叫「能量」、心情 0..10 的模板，词表必须跟着变。

写入指令（结局 250–450 字、总结 150–300 字、序章 180–260 字）是**通用默认**，
不是世界事实；三条都可由调用方整句覆写（`instruction`），字数只在默认值里出现一次。

### D5e 提示词里的「名字 vs 代号」（2026-11-21 第二轮自查）

**凡是有名字的东西，给模型的名字与代号要一起给 —— 不能只给代号。** 这一轮改的：

| 位置 | 以前模型看到 | 现在 |
|---|---|---|
| stablePrefix 世界骨架 | `模板：jjk-2006@3.0.0` | `worldSkeletonOf(template)`：模板名 + 年代 + 描述 |
| 事件白名单 | `ev-hv-04、ev-hv-05` | `branchEvents:[{id,title}]` ⇒ `ev-hv-04（本殿）`（id 仍是闸门） |
| 滚动历史 | `kind: "npc_action"` | 旁边加 `kindLabel: "他人动向"`（`HISTORY_TYPE_LABELS`） |
| `world.history` | `type: "event"` | 旁边加 `typeLabel: "事件"` |
| `world.now.slot` | `from: "queueTake"` | 旁边加 `fromLabel: "排队到期"` |
| 输出契约 | —— | 新增一条：正文禁止出现系统标识符（`npc-` / `ev-` / 字段名 / 英文枚举），提到人用姓名或称谓 |

人话**不替代**机器字段：id / 枚举仍保留（工具参数、白名单匹配要用），只是不再「只有它」。
白名单缺标题时退回 id，渲染层不猜；标题来源 = 模板事件 ∪ LLM 生成事件（同一份来源）。

仍未解决（要协议改动，先记着）：
- `facts[].factRef` 是 `flag:savedRiko` 这种**作者键**，没有显示名。jjk 当前
  `knowledgeGrants: []` ⇒ player 窗口恒空，暂时不影响；将来要用，得给 flags 加 label 表。
- `contextHints` 是模板自由标签（jjk 现在写 `[facts, history]`）。它是模板内容不是引擎，
  想更自然就改 `rules.yaml`（会换指纹）；引擎只负责原样透传。

### D6 `schemaVersion` 保持 5

表现层是派生，不改存档形状。

## ADR-015 · 封印与「每回合」口径

### D1 战斗面的每一条都写明「战斗中」

一条状态可能同时有两个域（`simulation` 与 `combat`）。都写「每回合」时玩家分不清哪个域。

- 战斗面一律前缀：`战斗中每回合受到 4 点伤害` / `战斗中造成伤害 +20%` / `战斗中命中 +10%` / `战斗中闪避 +10%`；
- 模拟面保留「每回合」（= 回合推进，点「继续」时结算）。

两个域的结算各自独立：`moodDeltaPerTurn` 在回合推进时算，`combat.onRoundEnd` 只在战斗回合末算。

### D2 战斗内的时长说两件事

`remainingLabel(inst, worldTime, { inBattle })`：

- 战斗外：`还剩 2 天`；
- 战斗中且 `expiresAt`：`整场战斗有效（战后还剩 2 天）`。

**不换算回合数** —— 战斗不推进世界时间，所以「这一场会不会掉」的答案就是确定的不掉。
写「还剩 2 天」会读成「打一场消耗两天」。

### D3 封印：`seal { code, text }`，不是把技能藏起来

- `skillSealOf`（**持久**原因：没这个召唤物了 / 没有祭品 / 没有可收回的）供技能页与战斗面板共用；
  `battleSealOf`（**当场**原因）内部就是 `canUseSkill`。
- 契约：`SkillVM.seal?` 与 `BattleSkillVM.seal?` 同形 `{ code, text }`，`code` 机器可读。
- **技能用不了 ≠ 技能不存在**：两处都照常列出，并写明原因。
  这推翻了 ADR-013 D3 早期的「面板上直接删掉」——灰着点不动比没有更让人怀疑，
  但**说明白**就不一样了。
- **`skill_on_cooldown` 不下发**：面板已有「冷却 N」，盖两层会让一件事看着像两件。
- 前端：技能卡虚线 + 「封印」角标 + 详情原因条；战斗按钮置灰但**不做半透明**
  （那等于把原因藏起来），第三行直接写原因。

### D4 目标选择：先选目标，再放技能

`toBattleVM` → `skills[].target` → 点卡片选目标 → `targetInstanceId` → 引擎按 id 取人。
2026-11-20 用户裁决后的口径：

- **默认**：敌方（含中立）开局自动选第一个；友军**不选**（`null` = 还没选）。
  「没选」与「选了自己」必须分得开，所以「自己」也是一个真实 id（`player.id`）。
- **自己**：没有「自己」那张友军卡了，顶部资源面板（`.battle-self`）就是落点。
  **不做差异化展示、不加提示文案** —— 它就是资源面板，只是可点；状态芯片在按钮外，不会误触。
- **提示**：需要点选却没选 → 按钮写固定文案「请选择目标」；选中的人不合法 →
  「不是合法目标」，`title` 放 DSL 的 `disableReason`（如「你只能选中自己的召唤物」）。
  两种都和「封印」同一套处理：**置灰但原因可见**，不做半透明糊掉。
- **合法目标由内核算**（`legalTargets` / `legalTargetIdsOf`）：前端只做 `includes`，
  不重算阵营、不读 DSL —— 否则新增谓词时面板和引擎会各说一套。
- **中立与敌方共用一个目标框**：对目标判定来说它本来就是敌方（`campsOf` 把它并进双方
  `hostile`），再分一个「第三方」阵营只会让人以为技能选不到它。中立卡保留自己的配色，
  **选中态与敌方一致（红边）**。

## 仪器：`pnpm inspect`

先说纪律：**仪器不复写规则**。它建世界、摆对手、挑技能，然后交给真实的
`performBattleAction` / `projectSnapshotV2`。报告里的数字就是玩家会遇到的数字。

```
pnpm inspect check                          # 模板体检（error / warn / info）
pnpm inspect overview                       # 存档与模板总览
pnpm inspect tpl --flag|--event|--endings|--line|--npc|--grep
pnpm inspect trace                          # 最近一次 LLM 调用的块与诊断
pnpm inspect sim --tpl … --as … --dummy hp=5000,agility=8
```

`inspect check` 的规则表（`apps/server/src/admin-data.ts`）：

| 规则 | 级别 | 含义 |
|---|---|---|
| `dangling-edge` | error | 指路指向不存在的事件 |
| `orphan-chain-event` | error | `source: chain` 却没人指向它 |
| `sink-event` | warn | 链上事件没有出口 |
| `flag-never-written` | error / warn | 被读却无人写（读它的是结局 / 解锁 ⇒ error） |
| `flag-never-read` | info | 有人写没人读 |
| `ending-unreachable` | error | 结局条件依赖死旗标 |
| `unknown-condition-ref` | error | 条件引用了不存在的属性 / 状态 / 物品 / 技能 / 角色 |
| `opening-param-overwrite` | warn | 开局同一 param 被同一路径上的两处写（后写静默覆盖） |

CLI 若要自己加载模板，必须**先 `registerServerExtensions()` 再 `loadTemplates()`**，
否则扩展贡献的边与能力不会出现，体检会误报。

## ADR-018 展示面 · 两栏 + 一块

面板分两层：**「天赋」一栏**（`kind: talent`，不叠层、无时长、不可驱散）、
**「修正」一栏**（`modifier ∪ battle`，靠时长单位区分「还剩 3 天」/「还剩 2 回合」；
`battle` 只在战斗面板出现）。
`battle` 不会出现在战斗外的面板里。天赋单列的理由不是数值，是**稳定的身份**：
它几乎不变化，混在会抖的状态里会让玩家以为六眼快到期。

**合计**（`PlayerVM.modifiers`，`ModifierChannelVM[]`）：一行一条通道
（属性 / 增减伤 / 命中 / 闪避 / 消耗 / 每回合 / 行动限制），点开是每一笔的来源。
投影期算好，前端不求和；零值通道不发。

两条禁令：

- **不展示引擎不认的通道**。`simulation.actionEfficiency` 与 `eventConditionTag` 至今没有
  结算实现 —— 以前 `effects.ts` 会把「行动效率 -20%」拼给玩家看，那是面板在替引擎许诺。
  现在字段保留 + 注释，渲染删掉；将来先实现结算再上屏。
- **`refDetail` 不带 `durationLabel`**（既有口径）：时长只属于施加点，写在技能行里。

### 展示面修订（2026-11-20 晚，用户裁决）

- **只在个人页展示**：首页（`CharacterSheet`）不再挂状态区，状态只出现在「个人」页的
  `StatusBoard`。首页是"现在发生什么"，状态是"我身上有什么"，两件事不该挤在一屏。
- **芯片只写名字与层数**：`modifier` 的剩余天数**不上芯片**（详情里有），
  列表里每行挂一句「还剩 3 天」会把一屏挤成两屏；
  `battle` 例外——单位是回合，回合数是这一场里的战术信息，藏起来就算不出还能不能撑住。
- **实线 / 虚线**：`talent` 实线（身份），`modifier` / `battle` 虚线（会掉的东西）。
  只靠分组标题不够：滚动之后标题已经不在屏里。
- **天赋不写「持续」**：投影层就不再给 `talent` 下发 `durationLabel`（不是展示层过滤）——
  下发了总会有人渲染，然后「六眼 · 直到被移除」变成一句玩家要猜的话。
  战斗态省略 `rounds` 时写「整场战斗」，不写「直到被移除」（后者听起来像带出战斗）。
- **品级是一等字段**：模板写 `quality: mythic-unique`，标签由引擎按品级阶梯自动生成
  （`tagIdsOf` 的既有联动），不再手写 `tags: [mythic-unique, buff]`。
  `tags` 机制保留（字段、`ui.tags`、`resolveEntityTags` 都在），但状态数据里已不再使用。

## 玩家关系图（2026-11-20）

### 先补本体：`PlayerVM.relations`

以前关系**只挂得出 NPC 卡**（`buildRelationRows(npc.id, …)`）：玩家自己的父亲、母亲、子女、
配偶只能靠在别人的卡上反向看，或者根本看不见。这是投影缺了一块，不是展示层没写。

现在玩家的关系与 NPC 卡走**同一个函数、同一份 `observableRelations`**，且**两个方向都下发**
（`direction: out | in`）。另起一份口径会让「卡片上写了这行、关系图里没有」重新长出来。

### 呈现：`RelationGraph`（个人页「关系」子页签）

- 玩家居中，对端按环排布（容量 12 / 8 / 6 三圈），边按 `kind` 上色；
- **实线箭头朝外** = 我视他为 X；**虚线箭头朝内** = 他视我为 X。不合并：
  「我认这个儿子」与「这个儿子认我」是两件事；
- 点节点 → 跳「世界 · 人物」并滚到那张卡（跨页签的 `openNpc`，带自增序号 ——
  连着点同一个人两次也要重滚）；
- 点不开的人（尚未登场 / 未现身 / 不在名册）画虚线圆 + 名字下的原因，不假装有档案。

### 两条硬规矩

1. **布局必须确定性**：角度按索引从正上方顺时针排，不用力导图 —— 力导图的节点会互相推挤、
   每次打开位置都不同，玩家会以为关系变了。
2. **筛选按 `kind`，不按 `kindLabel`**：扩展推导出的亲属行会把行称谓换成人话里的具体叫法
   （`relative` → 爷爷 / 舅舅 / 叔公 各不同），拿它当类型名会出现「爷爷 7」。
   所以 VM 上分成 `typeLabel`（边类型的名字，筛选用）与 `kindLabel`（这一行的称谓）。

### 顺带

「冷却 0 回合」与「消耗 0 咒力」是同一类噪音：`cooldownTurns > 0` 才占一行，否则整行不出现。
字段不动（仍是结算判据），只是零值不上屏。

### 展示面修订（2026-11-20 晚）

- **关系图只画出边**：一张图回答「我视谁为什么」。入边（「他视你为 X」）在 NPC 卡的关系里
  已经写着，画进图谱会让每条亲缘变成两条反向的线。筛选条的计数也只数出边 ——
  点不掉的东西不该出现在筛选条里。
- **观察者接管关系主语**：`PlayerVM.relations` 由 `viewerId` 计算（原来是 `player.id`）。
  `observeActor` 把镜头交给谁，个人页「关系」画的就是**他的**关系，标题写「XX 的关系」，
  并用一条通栏细带写「以 XX 的目光看世界 —— 关系与可见性按他算，你自己的人和数值没变」。
  以前 `viewerId` 只影响可见性，在所有关系都 `public` 的模板里等于什么都没发生
  （用户 2026-11-20：「借父亲的眼睛 我在前端没发现有任何用」）。
  通栏而不是顶栏 chip：390px 上顶栏已被「第 N 轮 / 改名 / 重开」占满，再塞一个名字会把按钮挤成竖排。

### 状态芯片只有一个入口（2026-11-20）

`StatusChip`（`packages/rpg-ui/src/StatusChip.tsx`）是**全工程唯一**的状态呈现入口：
个人面板、NPC 卡、状态浮窗共用。以前各写一份，于是同一个「六眼」在三处长得不一样 ——
NPC 卡上没有 `status-chip--{kind}`，**修正看起来像天赋（实线）**；层数 `×2` 落在样式
`span` 外面，**不跟名字同色**。

三条规矩写在组件里：实线=天赋 / 虚线=修正与战斗状态；层数与名字**同一段文本**；
`modifier` 不写剩余天数、`battle` 写回合数。

### `sink-event` 认「交接给时间表」（2026-11-20）

规则本意是抓死胡同：链事件既没有 `nextEventId`，也没有写任何终止条件读的旗标。
但有一类**合法终点**：写完门闩旗标就结束，下一幕是 `source: schedule` 的定时门
（`ev-bs-06` 写 `ready3`/`chapter`，`ev-ch3-gate` 到点才开）。以前一律报 warn，
作者只好硬塞一个假的 `nextEventId`，反而把定时门变成立刻触发。

现在：**本事件写的旗标，被某个非链事件的 trigger 读走 ⇒ 不算 sink**。
jjk-2006 的 warn 因此从 6 降到 0（剩下两条在 valmont）。

## 角色媒体与技能 CutIn（2026-11-24 · 迭代 character-media）

**不变量**：人物身份、皮肤、资源、演出四段解耦；引擎只做解析，不存图、不认识任何角色名。

- **配置位置**：皮肤集合写 `ui.yaml.characterMedia`（表现域，不进语义指纹）；资源登记写
  `assets/manifest.yaml`（`AssetDescriptorSchema` 已有 `kind/characterRef/visibility`）；
  CutIn 写 `ui.presentation.skills[id].cutIn`（`FxOverride` 上的可选字段）。
- **解析顺序**：`skinId`（持久化）→ `skinRules` 首个命中 → `defaultSkin` → 占位符。
  只有 `skinId` 落盘；规则每次投影重算，所以**时间回溯会自动恢复**。
- **槽位回退只在同一皮肤内**：`avatar → bust → full → 占位符`。跨皮肤回退会让 2017 的五条用 2006 的头像。
- **条件子集**：`skinRules[].when` 复用 `Condition`，但加载期只放行 `time` / `flag` / `eventOccurred` 三类，
  其余（`status` / `attribute` / `relation`）报 `ui_invalid`。人物状态驱动的换装先走 `setSkin`。
  **禁止**通过临时替换 `state.player` 或 `selfId` 来求值 —— 那会污染关系图与观察者。
- **CutIn 门控**：抽成轻量 `useCastPlayback(fx)` —— `cast.seq` 游标 + `release(seq)`（**幂等**）+ `cancel()`。
  完成 / 跳过 / 超时（`durationMs + 500` 兜底）走 `release`；**组件卸载走 `cancel`**（组件没了不该再启动后续 FX）。
  `BattleFxLayer` 只消费这个 Hook，不再自己维护游标；不新建演出引擎，不阻塞内核结算。
  不用固定 `holdMs`（连续施法、动画取消、卸载都会让它错位）。
- **素材优先级**：`skillCutIns[skillId] → cutIn → bust → full → 纯文字`，**专属优先于通用**。
- **释放时快照**：CutIn 的 `assetId` 在 cast 生成时解析并随 `fx.casts[i]` 下发，播放时不再回查 state ——
  否则演出途中一次 `setSkin` 会把同一次释放的立绘换掉。
- **战斗单位**：敌人与召唤物没有 NPC 实例，媒体按 `Combatant.characterId` 查模板，**不为取图造实例**。
- **占位符**：复用文字头像（首字 + 稳定底色），不新造图形资产。

**被否**：① 新建一套演出引擎（`BattleFxLayer` 的游标已经够用）；② 用固定延迟代替回调（见上）；
③ 把媒体配置塞进 `characters.yaml`（那是机制文件，进语义指纹会毁存档）。

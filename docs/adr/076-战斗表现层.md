> 状态：**设计定稿，未实现**。前置：ADR-002（表现层协议）、ADR-073（战斗 Hook）、ADR-075（战评）。
> 本文只管「打出去之后长什么样」，**不改任何战斗判定**。施工顺序见 §12。
> 可视化原型：`docs/prototypes/battle-fx.html`（可点，非正式实现）。

> **2026-11-24 更新（ADR-078）**：本文 §3 的三张 preset 表（施法 / 轨迹 / 受击）

> 引擎只保留不表达世界观的几何（箭头 / 扇刃 / 上升气流 / 火花 / 登场 / 离场 / 消散）。

## 0. 不变量

1. **数字来自结算，表现不改数**。`amount` 是 `dealDamage` 的最终值；表现只能决定怎么显示。
   模板可以改字号、描边、颜色、后缀、位置，**不能改数值，也不能翻转符号**。
2. **轨迹是风格，数字是事实**。技能配成紫色，只染轨迹；伤害数字默认仍是红的 ——
   除非某一层**明确声明**了 `number.color`。
3. **解析在投影期，全场只解析一次**。前端拿到的每个字段都是终值，不做第二套级联。
   理由与 ADR-002 D2 同：多端各算一遍，必然出现「同一个暴击，手机和桌面显示不一样」。
4. **颜色不是唯一通道**。每种语义必须另有一个形状 / 符号冗余（§4.3），黑白截图也能读。
5. **播放器设置不是层，是闸**。减少动画 / 快速战斗 / 关闭闪光在级联之后执行，模板覆盖不了。
6. **内核零作品词**。轨道型、等级、字段名都是机制词；`CRITICAL` / `黑闪` 这类文案由 `ui.yaml` 提供。

## 1. 级联：P0–P5 六层 + P6 闸

| 层 | 来源 | 能改什么 | 例子 |
|---|---|---|---|
| P0 | 引擎默认（`presentation/fx.ts`） | 六型轨道几何、六档语义色、三级字号/描边 | 伤害红、能量弧 |
| P1 | 世界主题 `ui.presentation` | 调色板、默认轨道、字号阶梯、标签文案 | 咒术世界：咒力紫光粒子 |
| P2 | 单位 `presentation.units[actorId]` | 该角色出手时的默认轨道 / 色调 | 五条悟偏蓝紫 |
| P3 | 技能 `skills[].style` + `presentation.skills[skillId]` | 这一招的轨道型、颜色、宽度、字号 | 虚式「茈」紫色 42px |

**P2 / P3 是「可选的染色」，不是默认行为**：模板不写，就一路回落到 P0 的语义色。
jjk-2006 现在 `skills.yaml` 与 `characters.yaml` **一处 `style` 都没有** ⇒ 实装后所有伤害轨迹都是红的
（原型里的蓝紫是手写的 P3 示例，不是模板现状）。要给「苍 / 赫 / 茈」上个人色，
必须在 `ui.presentation.skills` 里显式写，而不是指望技能自带。
| P4 | 状态 / Hook `presentation.hooks[hookId]` | 命中被某个钩子改写时的强表现 | 黑闪：红黑刀光 + `!!` |
| P5 | 事件 `presentation.events[eventId]` | 本场强制表现（剧情演出） | 挡枪：慢镜 + 定格 |
| **P6** | **播放器设置（客户端）** | **减少动画 / 快速战斗 / 关闭闪光** | **任何层都盖不掉** |

**合并规则**（三条，缺一不可）：

- **字段级覆盖，不整块替换**。高层的 `trace` 只改它写了的键，字号、颜色、后缀继续往下继承。
  「配了紫色轨迹，数字就全紫了」是这套设计要避免的第一号事故。
- **`labels` 是数组**：默认 `append`（按 id 去重，后写赢），要换整套必须显式 `replace: true`。
  否则两个 Hook 同时触发时，先注册的那个会把后一个的文本吞掉。
- **同层冲突按 `priority` 降序**，同值再按稳定 id 字典序。**不许依赖注册顺序** ——
  那是「改一行 yaml 顺序，视觉效果就变」的经典来源。

## 2. 配置落在 `ui.yaml.presentation`

**位置**：`specs/data/templates/<id>/<ver>/ui.yaml`，新顶层键 `presentation`。

**为什么不写进 `skills.yaml` / `statuses.yaml`**：那些文件进语义指纹，改一个颜色会让旧存档
`template_content_drift`。视觉调参不该有这种代价。`ui.yaml` 已有同样的先例
（`qualityStyles`、`resources`、`tags` 都是「引用语义 id、只影响展示」）。

**引用完整性在加载期校验**（与 `ui.resources` 同口径）：

| 键 | 必须是 |
|---|---|
| `units.<id>` | `characters.yaml` 里存在的角色 id |
| `skills.<id>` | `skills.yaml` 里存在的技能 id |
| `hooks.<id>` | 三处钩子表之一里存在的 hook id（`status.combat.hooks` / `skills[].hooks` / `world.combat.hooks`，见 §3.4） |
| `events.<id>` | `events.yaml` 里存在的事件 id |
| `trace` | 六型轨道之一（`energy / linear / slash / lock / area / domain`） |
| 颜色 | `#hex` 或 `ui.palette` 的键 |

未知 id ⇒ **加载期拒载**，不静默回退成灰色（ADR-002 D2 的既有口径）。

形状（值都可以省，省了就是继承上一层）：

```yaml
presentation:
  palette:   { damage: "#FF6B7F", heal: "#58E3A7", buff: "#7EC6FF", debuff: "#B387FF", miss: "#A0A8B8", immune: "#E6C97A" }
  trace:     { default: energy, width: 2 }
  number:    { size: 24, stroke: 2, suffix: { crit: "!", critTier2: "!!" } }
  labels:    { crit: "CRITICAL", miss: "MISS", immune: "免疫" }
  units:     { npc-gojo: { color: "#7C8CFF" } }
  skills:    { sk-limitless-red: { trace: area, color: "#FF4D6D", width: 4, sizePx: 42 } }
  hooks:     { black-flash: { trace: slash, color: "#FF3344", width: 6, numberColor: "#FF3344", label: "黑闪" } }
  events:    { ev-hv-06-block: { trace: slash, slow: true } }
```

## 3.0 四段式：施法 → 轨迹 → 受击 → 结算

一次施放不是一个动画，是**四段**（2026-11-23 第三版补齐，前两版只有「轨迹 + 数字」）：

| 段 | 挂在哪 | 默认（P0） | 说明 |
|---|---|---|---|
| **施法** `cast` | 施法者手上 | `charge` 蓄力环 | 起手。没有它，技能像凭空出现 |
| **轨迹** `trace` | 施法者 → 目标 | 六型之一 | 只有攻击/治疗才需要；领域类可以省 |
| **受击** `impact` | 目标身上 | `burst` 火花 | 命中与否的**唯一**视觉区分点 |
| **结算** `result` | 目标卡右缘 | 数字 + 后缀 + 标签 | 只有这一段是「事实」，前三段是特效 |

**为什么必须分开**：前三段可以随技能/钩子/世界改，第四段不行 ——
数字来自结算，改它就是说谎。把「受击」独立出来，还顺带解决了
「未命中怎么演」：以前只知道「没伤害」，现在是**轨迹断掉 + 没有受击段**。

### 施法特效 `cast`

**默认是 `none`**：大部分技能不需要施法段 —— 抬手就打才是常态。只有**召唤**与**奥义**用它。

> **归属（2026-11-23 用户裁决）**：引擎只内置 **trace / impact / result** 三张固定表；
> **`cast` 不进引擎闭集** —— 下面的 charge / sigil / flash / ultimate 是**建议的模板预设**，
> 由 `ui.presentation.cast` 或扩展注册表提供，引擎只负责把 `cast` 字段透传给渲染层，缺省即 `none`。
> 这样「大部分技能没有施法」不需要在引擎里开特例。

| id | 形态 | 方向 | 用在 |
|---|---|---|---|
| `converge` | 三段反向环 + 10 条内吸光条 + 8 颗向心粒子 + 核心 | 向内 | 引力类（苍） |
| `repulse` | 12 条外扩条纹 + 双层冲击环 + 7 颗离心粒子 | 向外 | 斥力类（赫） |
| `collapse` | 蓝/红两球对撞 → 紫核 + 双层畸变环 + 外扩粒子（两拍，240ms 处坍缩） | 先内后外 | 虚式（茈） |
| `mandala` | 地面影池 + 上升光柱 + 双层反向环 + 12 刻度 + 6 枚召唤纹 | 仪式 | 召唤 |
| `flash` | 八向星芒 + 双环 | 爆发 | 黑闪这类「抬手就打」 |
| `ultimate` | `mandala` + 上下遮幅 + 立绘占位 | 仪式 | 奥义（见下） |
| `none` | 无 | — | **一般技能的默认** |

**方向是这套施法语言的第一原则**：引力朝内、斥力朝外、虚式先内后外。
不看颜色、只听名字也能猜出是哪一招 —— 这是给「同屏两个术式同时起手」留的辨识度。

### 奥义：预留立绘 / 过场的接口

`ultimate` 目前只做「法阵 + 遮幅」。立绘与过场动画**本次不设计**，但字段先占住：

```yaml
cast:
  preset: ultimate
  splash: sk-gojo-hollow-purple-splash   # 立绘资源 id（未实现，占位）
  cinematic: cutin               # none | cutin | full（未实现，占位）
  durationMs: 900
```

渲染层拿到未知的 `splash` / `cinematic` 时**降级为 `ultimate` 的现有形态**，不报错 ——
这样将来补上立绘，只换渲染器，不动协议。原型里那块「奥義 · 立绘 / 过场（预留）」就是降级形态的样子。

### 轨迹特效 `trace`

| id | 形态 | 说明 |
|---|---|---|
| `arrow` | 弧线 + 开口 V + 白钻 | 通用单体 |
| `precision` | 发丝直线 + 中途菱形 + 四角框 | 精准 / 必中 |
| `fan` | 每个目标一根锥形扇刃 | 群体 |
| `updraft` | 单股上升气流（细起粗收）+ 端点箭头 | 自身治疗 / 自身增益 |
| `slash` | 黑→红刀光 | 黑闪的刃（轨迹在，受击另算） |
| `none` | 无 | 只有召唤（没有目标）用它 |

**miss / 抵抗不是独立轨迹，是轨迹的两种收尾**：`outcome: "miss"` ⇒ 虚线断在半路 + 渐隐点；
`outcome: "immune"` ⇒ 金线撞向目标。这样任何轨迹型都能演「没打中」，不用另写一套。

### 受击特效 `impact`

| id | 形态 | 用在哪 |
|---|---|---|
| `burst` | 火花 + 冲击环 | 普通命中 |
| `lightning` | 红黑雷弧 + 闪屏 + 顿帧 | 黑闪 |
| `cuts` | 数道短切口（宿傩「解」） | 斩击 |
| `shield` | 六边形盾 + 波纹 | 免疫 / 抵抗 |
| `arrive` | 落地光环 + 上升光柱 | 召唤物登场 |
| `depart` | 淡出 + 上升气流 | 收回 |
| `dissolve` | 紫焰消散 + 冲击环 | 献祭 |
| `none` | 无 | 未命中、纯治疗 |

**三者归位（2026-11-23 用户裁决）**：宿傩斩击 `cuts`、免疫盾 `shield`、黑闪雷电 `lightning`
**全部属于受击层**，不画在轨迹里 —— 它们描述的是「目标身上发生了什么」，不是「怎么飞过去」。

`miss` / `immune` 在语义上不是「受击特效的一种」，而是**受击段的不同分支**：
`miss` 干脆没有受击段；`immune` 只有盾、没有数字。

### 3.7 召唤：施法层复用，登场算受击层

召唤不是第五种东西，它仍然是四层，只是**目标为空**：

| 动作 | 施法 | 轨迹 | 受击 | 结算 |
|---|---|---|---|---|
| **召唤** | 施法者开法阵 `sigil` | **无**（没有目标） | 新友军卡上 `arrive` | 不产生数字，只出名牌 |
| **收回** | 施法者 `charge` | `updraft`（反向） | 召唤物 `depart` | 无 |
| **献祭** | 施法者 `charge` | `precision`（锁定） | 召唤物 `dissolve` | 无（可给资源） |

**离场：本轮灰卡，下一轮移除，且不占位**（2026-11-23 用户裁决）：

- 动效演完（≈320–380ms）后，卡片进入 **`departed`** 态：灰显 + 标「已离场 · 本轮灰卡」；
- 它**立刻失去召唤位**（`召唤位 N/3` 的 N 不含灰卡），也**不能再被选为目标**；
- **下一轮开始**才真正从列表移除 —— 因为本轮的轨迹还要指到它，先删会留一条指向空气的线。

这条同时解决两个问题：轨迹有落点、召唤位即时释放。
| **群体献祭** | 施法者 `charge` | `fan`（每个友军一根） | 每个 `dissolve` | 无 |
| **漩涡** | 见下（两段） | — | — | — |

**登场特效挂在「新生成的友军卡」上**，属于受击层 —— 它描述的是「这个位置上出现了一个单位」，
和「被打中」是同一种空间语义（目标身上发生的事），不是轨迹。收回 / 献祭同理：
`depart` 与 `dissolve` 都在目标身上，轨迹只负责「施法者的手伸向谁」。

**漩涡是两段，不是一段**：第一段友方群体（`fan` + `dissolve` ×N），第二段敌方单体
（直线束 + `burst` + 一个大数字）。两段各自有完整的四层，中间隔 ~400ms。
把它塞进一个「同时打两边」的单段，会让「先前摇后爆发」的节奏丢失。

**召唤物的首轮攻击不特殊处理**：它和玩家出手走完全同一套四层，只是轨迹的起点是
**召唤物卡的锚点**而不是玩家。这一点在原型里可以直接看到（「召唤 + 首轮攻击」）。

**斩击类也有轨迹**（2026-11-23 用户裁决）：宿傩的「解」是一道极快的 trace（`arrow`，150ms），
切口只是受击层。没有轨迹就不知道「谁打的、打向谁」—— 这条不能开例外。
miss 时轨迹照常断线，受击层再加「斩空」（切口落在卡外），两者一起说明「这一刀劈空了」。

### 群体：刃的数量 = 目标数

群体不再画「固定五根扇骨」，而是**每个目标一根**，各自独立结算：

- 命中的目标：完整刃 + 受击 + 数字；
- 未命中的目标：这一根**断在半路**（灰虚线 + 渐隐点），没有受击段；
- 无效的目标：刃撞在盾上（金色），没有数字。

于是「一次群体打出 命中 / 未命中 / 无效」在画面上是三种不同的线，而不是同一张图配三行字。

## 3. 轨迹（trace）

### 3.1 六型（历史版；现已由模板 DSL 表达，见 ADR-078）

| 型 | 几何 | 语义宽度 | 端头 | 适合 |
|---|---|---|---|---|
| `energy` | 二次贝塞尔弧（弧高 `clamp(0.24d, 24, 64)`），锥形彗尾 | 2 | 开口 V + 白钻 | 术式、能量弹 |
| `linear` | 发丝直线（尾部透明） | 1.4 | 开口 V | 远程、必中 |
| `slash` | 主刃 + 偏移副刃（双刀层次） | 5 | 尖锋（无箭簇） | 近战、暴击、黑闪 |
| `lock` | 发丝直线 + 中途菱形 | 1.4 | 开口 V + 四角框 + 命中环 | 精准、单体锁定 |
| `area` | 五根锥形扇骨 + 极淡洗地 | 3 | 无 | 群体 |
| `domain` | 全屏椭圆扩散 + 暗角 | — | 无 | 领域展开 |

模板只能**选型 + 覆盖颜色/宽度**，不能写路径。写路径等于把排版逻辑搬进 yaml，
改一次分辨率就废。

> 2026-11-24：这条「不能写路径」仍然成立 —— 但「型」本身也交给模板了。
> 模板写的是**图元组合**（环 / 雷弧 / 割口…），不是 SVG 路径；见 ADR-078。

### 3.5 三层结构：辉光 / 锥形带 / 白热芯

轨迹不是「一根描边」，是三层叠出来的（2026-11-23 第二版，第一版的「粗线 + 实心三角」已被否）：

1. **辉光** —— 同路径，宽度 ×2.1，`blur(6px)`，不透明度 0.2：只负责「亮」，不负责形状；
2. **锥形带** —— 沿路径采样 58 段，按剖面收放宽度，填充「尾部透明 → 头部实色」的渐变：
   起点细、中段饱满、终点收成尖，这才有方向感；
3. **白热芯** —— 宽度 ×0.13 的白色细线，不透明度 0.4：负责「能量」而不是「油漆」。

显影用**掩码**（mask 里一条同路径的白线跑 `stroke-dashoffset`），不是直接给描边做 dash ——
描边做 dash 只能显影描边，填充带根本长不出来；掩码对三层同时生效。

配置里的 `width` 是**语义刻度**（2 / 3 / 5–6），**渲染宽度由剖面放大**（2 → 9px、5 → 17px）。
写死渲染像素会让「同一档宽度」在 375 和 430 的屏上长得不一样。

### 3.2 几何由 DOM 实测，不写坐标

- 锚点：`[data-unit-id]` 元素的**矩形边缘中点**（施放者取朝向目标的边，目标取反向边）；
  找不到元素 ⇒ 退化为卡片中心。
- 覆盖层：`<svg class="battle-fx">` 绝对定位在 `.battle-body` 上，`pointer-events: none`，
  在 `resize` / 滚动 / 卡面增减时重算。**不与卡片同层**：动画不能改变布局。
- 竖屏（520px 上限）距离通常 40–200px：弧高、箭簇尺寸、数字位移都按实际距离缩放，
  否则桌面图上的大弧线到手机上会糊成一坨。

### 3.3 箭簇在 JS 里画

不用 SVG `<marker>`：`context-stroke` 兼容性差，marker 的颜色经常和线对不上。
按路径末端切线算一个三角形（9×7，暴击 12×9），颜色跟描边一致。

### 3.4 P4 的键是 **hookId**，不是角色

黑闪不是「五条悟的技能」，是「暴击被 `afterHit` 钩子放大了」。
所以 P4 的键必须是**触发这次改写的钩子 id**（`black-flash`），
`damage` 事件里带 `amplifiedBy: "black-flash"`。世界换一个作品、换一个钩子名，
表现层不用改代码。

### 3.6 四层都可被模板覆盖

四层是**并列的四个字段**，不是一条固定管线里写死的参数：

```yaml
skills:
  sk-gojo-blue:
    presentation:
      cast:   { preset: charge, color: "#7C8CFF" }
      trace:  { preset: arrow,  color: "#7C8CFF", width: 2, durationMs: 300 }
      impact: { preset: burst,  color: "#FF6B7F" }
      result: { size: 28, stroke: 1.4, suffix: auto }
```

- 每一层都能单独换 `preset`（闭集，见上三张表）与参数（颜色 / 宽度 / 时长 / 字号）；
- 没写的字段继承上一层（P0 默认 → P1 世界 → P2 单位 → P3 技能 → P4 钩子）；
- `preset` 是**引擎词**，不能写路径、不能写 SVG —— 写路径等于把排版搬进 yaml，换个分辨率就废；
- 同一层里 `preset` 与参数冲突时，参数赢（`preset: arrow` + `width: 4` 就是「更粗的箭头」）。

### 3.8 状态施加：`kind: "buff"`

纯状态技能（给自己挂无下限、给敌人挂封印）**既不造成伤害也不治疗**，
在此之前它们一条 `battle.events` 都不写 —— 表现层只能「点了没反应」。

新增事件（ADR-076 协议变更，2026-11-23）：

```ts
| { kind: "buff"; seq?; actor; target; skillId?; statusId;
    name?: string; polarity?: "positive" | "negative" | "neutral" }
```

- 三个施加点都会发：命中目标、挂自己、按阵营批量施加；
- `name` / `polarity` 取自模板，内核不认识具体状态；
- 表现层：**没有数字、没有受击段**，只有一条「往身上收」的轨迹；
- 颜色：增益红（`#FF6B7F`，用户裁决，与伤害同色）、减益紫（`#B387FF`）。

### 3.9 轨迹按「目标是谁」路由

同一条技能可以打自己、打一个友军、打全体，**轨迹不是技能属性，是「目标关系」的属性**：

| 目标 | 轨迹 | 理由 |
|---|---|---|
| 自己 | `updraft`（单股弧 + 箭头） | 自己对自己没有横向位移，只有「往上升」 |
| 单个友军 / 单个敌人 | `arrow` | 有明确的两端，才画得出「谁给谁」 |
| 全体 | 友军每人一根 `fan`，**自己那条仍是 `updraft`** | 扇形负责「扫到所有人」，自己不吃扇刃 |

实现上 `BattleFxHit` 多了一个 `trace` 覆盖字段（`preset` / `color` / `width`），
投影期逐目标填；`cast.trace` 只作缺省。这样「治疗全体」才能一人一支。

**updraft 的形状**：起点在卡内左下（`0.42w, 0.94h`）、终点在右上（`0.64w, 0.16h`），
控制点 `(mid + 40, mid + 6)`，细起粗收 + 端点一个 V。
不要竖直 + 右偏控制点（会卷成 C 形），不要 S 形，不要双股 —— 红色下都会被读成「自残」。

**两条边距用比例不用像素**：锚点盒子比可见面板多一点内边距，写死 `+6px` 会把箭头尖画到卡外（实测 11px）。

### 3.10 离场灰卡：留到「你下一次行动」

收回 / 献祭的单位**不从面板上立刻消失**，而是留在原地一张灰卡（`battle.departed`）：

- 不参与任何判定（不在 `allies` 数组里，只由投影并进视图并标 `departed`）；
- 不可选中、不可被治疗；
- **在你下一次行动开始时清空** —— 注意回合推进（`battle.round += 1`）发生在一次行动内部，
  在那里清会让灰卡根本来不及被看见（实测：收回后同一帧就没了）。

`BattleFxHit.departed` 不参与轨迹；离场特效仍由 `recall` 事件的 `depart` 承担。

### 3.11 一段施放独占一层

`playCast` 开头会清掉上一位留下的节点：**轨迹没有自己的生命周期**，
不主动清就会一直叠在屏上（多轮之后满屏横线、数字堆成一列）。
收尾再补一个 700ms 的「余辉清理」，用代次号防止把下一段刚画的擦掉。

### 3.12 献祭：`kind: "sacrifice"` 与漩涡的两拍

漩涡（`sacrifice` 技能）在此之前只有一行 log：单位被移除、伤害照打，
画面上却看不到「烧掉了什么」。新增事件：

```ts
| { kind: "sacrifice"; seq?; actor; target; skillId?; name? }
```

- **刻意不带 `skillId`**：献祭自成一「段」，与随后的伤害分两拍播 ——
  第一拍是友军消散（`dissolve`，无轨迹），第二拍才是敌方吃了那一击。
  同一 `skillId` 会把两拍并成一段，一起开演。
- 表现：`kind: "sacrifice"` 的 hit 没有数字、`trace.preset = "none"`、`impact = "dissolve"`；
- **灰卡照旧**（§3.10）：献祭的单位也在 `battle.departed` 里留到下一次行动。

## 4. 颜色与粗细

### 4.1 语义六档（P0 默认，`ui.palette` 可改）

| 档 | 默认 | 用在哪 |
|---|---|---|
| `damage` | `#FF6B7F` | 掉血数字、伤害轨迹 |
| `heal` | `#58E3A7` | 回血数字、治疗轨迹 |
| `buff` | `#7EC6FF` | 施加增益 |
| `debuff` | `#B387FF` | 施加减益 |
| `miss` | `#A0A8B8` | 未命中 |
| `immune` | `#E6C97A` | 无效 / 抵抗 |

### 4.2 粗细阶梯

| 等级 | 轨迹宽（语义） | 数字描边 | 触发 |
|---|---|---|---|
| 普通 | 2 | 1.4px | — |
| 暴击 | 3 | 1.8px | `critical: true` |
| 放大暴击 | 5–6 | 2.4px + 外发光 | `critTier ≥ 2` |

**描边必须随字号缩放**（≈字号的 4.5%）。第一版写死 1.6px，在 24px 的数字上等于每边吃掉
6.7% 的字腔 —— 八个方向的描边叠起来会把整个字盖成黑块（实测截图确认）。

**粗细只表达强度，不表达种类**：治疗暴击也变粗，但仍是绿色圆头 ——
否则「粗 = 暴击」和「粗 = 斩击」两套语义会打架。

### 4.3 冗余编码（颜色之外的第二通道）

| 语义 | 形状 / 符号 |
|---|---|
| 伤害 | 箭头端 + 数字前缀 `-` |
| 治疗 | 圆头端 + 数字前缀 `+` |
| 增益 | 轨迹带上箭头 |
| 减益 | 虚线 + 方块端 |
| 未命中 | 虚线 + **不出现数字** |
| 无效 | 轨迹撞盾符号 + **不出现数字** |

## 5. 数字

- **符号由 kind 决定**：`damage → "-"`、`heal → "+"`。模板**不得**翻转 ——
  「扣血显示成 +80」是谎报，不是风格。
- **显示值**取 `amount` 绝对值，不加千分位（战斗节奏短，`,` 反而是噪音）。
- **字号阶梯**：普通 28 / 暴击 36 / 放大暴击 42（`px @1x`，竖屏 420 基准）。
  模板可用 `sizePx` 钉死（「茈」42），钉死后不再随阶梯放大。
  第一版是 24 / 30 / 38 —— 在 420 宽的手机上数字太薄，被描边压得看不清，整体上调一档。
- **字重 800 + 等宽数字**（`tabular-nums`）：连击时数字不左右抖。
- **颜色**默认 = 语义色。技能紫**不染**数字，除非 P3 及以上显式写 `number.color`。
  例：jjk 的黑闪在 P4 把数字从 `#FF6B7F` 改成红黑渐变（`#fff4ea → #ff2038 → #9c0016`，自上而下），
  字号仍继承 P0 的 42 —— 这正是「高优先级只覆盖声明字段」的样板。
- **渐变数字**用 `background-clip: text` + `color: transparent` 实现；描边仍用文字阴影环，
  两者叠加时**先画阴影再画渐变**（Chrome 实测可行），不能反过来。
- **避让**：同目标多段纵向错位 26px；不同目标各自贴卡右缘，不跨屏。

## 6. 后缀阶梯

| 情形 | 后缀 | 判定 |
|---|---|---|
| 普通 | 无 | — |
| 暴击 | `!` | `critical === true` |
| 放大暴击 | `!!` | `critTier ≥ 2` |
| 未命中 / 无效 | 无（没有数字） | `miss` 事件 |

`critTier` 是**引擎词**：`critExponent !== 1`（有钩子把这次暴击的倍率又放大了一次）即为 2。
jjk 里就是黑闪（`1.5^2.5 ≈ 2.76`），但内核不知道「黑闪」这个名字。

后缀文本来自 `ui.presentation.number.suffix`（模板词），jjk 写 `{ crit: "!", critTier2: "!!" }`。

> **用户裁决优先于参考图**：示例图把 `-225!!` 标成「暴击」、`-100!` 标成「强化」，
> 与描述冲突 ⇒ **以描述为准**：`!` = 暴击，`!!` = 黑闪。
> 「强化」不设独立档位 —— 它没有独立判定，只是伤害更高。

## 7. 附加文本（label）

- 位置：数字右上方（竖屏），不遮 HP 数字。
- 集合（引擎只给 kind，文本由模板给）：
  | kind | jjk 文案 | 触发 |
  |---|---|---|
  | `crit` | `CRITICAL` | 暴击 |
  | `miss` | `MISS` | 未命中 |
  | `immune` | `免疫` | 无效 / 抵抗 |
  | `hook:<id>` | `黑闪` | 该钩子改写了这一击 |
- **没配就不显示**，内核不硬编码任何中英文文案（通用性守卫会拒）。
- **取代，不是叠加**：放大暴击配了 `label`（钩子自己的名字）时，`critLabel`（CRITICAL）**不再出现**。
  两条会压在同一块，而且信息重复 —— 「黑闪」本身就意味着这是一次被放大的暴击。
- **双语**：`label: { text: "黒閃", latin: "BLACK FLASH" }` —— 主文本一行，拉丁副标题一行（8px、字距 2.2）。
  黑闪这类「原作感」的里程碑效果靠这一行小字撑住，但它不是必需的；只配 `text` 就是单行胶囊。
- 合并：`append` + 按 id 去重；`replace: true` 才替换；同 id 后写赢。

### 7.1 黑闪：P4 的样板

黑闪是这套级联唯一「五条规则同时用上」的例子，值得单列（jjk-2006 的 `ui.presentation.hooks.black-flash`）：

| 字段 | 值 | 来源层 |
|---|---|---|
| `trace` | `slash` + 偏移副刃 | P4（钩子改写） |
| 颜色 | `#FF2F45` | P4 |
| 宽度 | `17px` + 雷电弧 | P4 |
| 数字 | 红黑渐变，字号 42 / 描边 2.4 | P0 字号 + P4 颜色 |
| 后缀 | `!!` | P0（`critTier ≥ 2`） |
| 文本 | `黒閃` + `BLACK FLASH` | P4 主文本 + P1 模板词 |
| 特效 | 命中顿帧 160ms + 红黑闪屏 + 12 道火花 | P4 |

**雷电弧**是画出来的，不是滤镜：从命中点向外 6 个方向、每道 6 段折线，
外焰（宽 3.4、`blur(3px)`、0.35）+ 主弧（宽 1.5）+ 白芯（宽 0.7）三层。
不用 `feTurbulence` 之类的东西 —— 移动端一帧掉到 30 以下就不是「闪」，是「卡」。

**顿帧**是这套设计里唯一允许「暂停」的地方：命中瞬间 160ms 不放任何数字，
让玩家的眼睛先看到雷，再看到数。其余效果一律不顿帧（连击会被顿成幻灯片）。

## 8. 时序与打断

一次施放 = 一个 **cast**（`skillId` + 若干 hit）。

| 阶段 | 时长 | 说明 |
|---|---|---|
| 轨迹展开 | energy 260 / slash 140 / area 320 / domain 480 | `stroke-dashoffset` 逐段显影 |
| 命中 | +0 | 数字 pop（0.6 → 1.08 → 1，260ms）、label 滑入、目标抖动（仅暴击） |
| 连击 | 每段 +200ms（快速战斗 +60ms） | 同 cast 内按 `seq` 顺序 |
| 放大暴击 | 顿帧 160ms + 闪屏 ≤120ms | 闪屏 ≤3Hz，可关（§11） |
| cast 上限 | 普通 900ms / 快速 300ms | 超时截断，不排队 |

- **动画不阻塞状态**：cast 到达时结算已经落库，动画只是回放。
- **新 cast 打断旧 cast**：直接跳到终帧再播新的。玩家连点不该看到动画排队。
- **刷新 / 读档不重放**：客户端把 `seq` 游标记成当前最大值，只播 `seq > cursor` 的事件。
  没有这条，读档会炸一屏数字。

## 9. 引擎缺口：命中也得是结构化事件

**现状**：命中骰没过、闪避成功、`beforeHit/afterHit` 取消，**只有一行 `log` 字符串**，
没有结构化事件。前端只能正则匹配中文，换文案就崩 —— 这正是「未命中 / 无效」画不出来的原因。

补齐（`packages/shared/src/v2.ts` 的 `BattleEvent`）：

```ts
| { kind: "damage"; seq: number; actor: string; target: string;
    skillId?: string; amount: number; critical: boolean;
    critTier?: 1 | 2; amplifiedBy?: string; hookId?: string }
| { kind: "heal";   seq: number; actor: string; target: string; skillId?: string; amount: number }
| { kind: "miss";   seq: number; actor: string; target: string; skillId?: string;
    stage: "beforeHit" | "hit" | "evade" | "afterHit"; reason?: string }
| { kind: "cancel"; seq: number; actor: string; target?: string; skillId?: string;
    hookId?: string; reason: string }
| { kind: "hook";   seq: number; hookId: string; text?: string }
```

- `stage` 决定轨迹终点：`hit`（命中骰没过）轨迹半途断掉；`evade` 撞上屏障；
  `beforeHit / afterHit`（被取消）轨迹消散。
- `reason` 只用于浮层解释（如闪避来源的状态名），不进主视觉。
- `seq` 单调递增、进存档；`projection` 只取最后 N 条（`events` 已有 200 条上限）。

## 11. 播放器设置（P6，客户端）

| 设置 | 行为 |
|---|---|
| 减少动画（含 `prefers-reduced-motion`） | 轨迹 120ms 淡出、无位移、无抖动、无闪屏；数字直接出现 |
| 快速战斗 | cast 压到 300ms，跳过 label 延迟；**数字与后缀照常**（信息不丢） |
| 关闭闪光 | 只关闪屏 / 发光，不影响数字、后缀、轨迹 |

三项都在客户端，**模板无法覆盖**：一个追求「演出感」的世界不该让人眩晕。

## 13. 未决

1. **同目标连续小伤害是否合并成一个数**（现在是逐段飞字，长盘会吵）。
2. **目标抖动的实现**：CSS `transform` 还是 Web Animations（低端机 60fps）。
3. **战斗回放**：`events` 有 200 条，但没有「施放时的站位快照」，回放只能重算布局。
4. **领域展开是否独占一屏**（会压住行动区，需要一次裁决）。
5. **多端一致性**：`sizePx` 写死 42 在平板/桌面是否还合适（可能需要 `sizePx` 只作上限）。

# 10 · 开局与角色

> 覆盖 ADR-001（前实例化开局）、ADR-004（开局加点）。
> 原始记录（含推导、被否方案、变更史）：`archive/ADR-001-前实例化开局.md`、`archive/ADR-004-开局加点.md`。

**这一层的不变量**：开局发生在世界**之前**。`commit` 之前没有 `WorldStateV2`、没有 NPC、没有事件槽，
`turnIndex` 全程 0 —— 所以「进游戏后又拿到开局天赋」在结构上不可能。

## ADR-001 · 前实例化开局

### D1 开局是世界的生成参数，不是世界内的事件

一段连续的 branch DAG，节点三种：`roll`（掷）/ `choose`（点）/ `allocate`（加点），可任意交错。
玩家一路走完，`commit` 时一次 `createWorldV2` 再按参数表落点写状态。

### D2 不记 Draft，不重放 effect DSL

会话只记 `results: [{ nodeId, optionId?, rollIndex? }]`，不记中间世界。
这样绕开「27 种 effect 变体作用在完整世界上」的复杂度，也不怕效果引用还不存在的 NPC。

### D3 引擎持有封闭参数表；参数分基本 / 附加

参数类型与落点注册在 **core**，模板只声明「用哪些、约束、展示什么」。值形状扁平（否掉 `who` 嵌套）。

| 类别 | 闭集 | 语义 |
|---|---|---|
| 基本属性 | `self` / `name` / `gender` / `age` / `attribute(set)` | 定义「你是谁」。**复用角色时整组来自角色卡，不读参数** |
| 附加属性 | `status` / `skill` / `item` / `relation` / `flag` / `points` / `attribute(add)` | 在基线上叠加，两种 self 都生效 |
| 时间锚 | `time: { value, unit }` | 一次写 `worldTime`，替代旧 13 步的 `advanceTo`；不进 effect DSL |

`status` 值可为 `statusId` / `statusId[]` / `{ id, stacks? }`，时长与叠层沿用模板定义。
**`mood` 不在闭集里**：心情由世界默认档位决定（开局想调就用 `status`）。
`character` / `npcSpawn` 已移除 —— 新人物固定实例化，不进刷新规则。

### D4 self 完整切换

`state.player` 是 **self 的唯一权威实体**，`id = selfId`。`selfId` 可指向任意角色：

- `{ kind: "default" }` ⇒ `player`，沿用 `playerTemplate`；
- `{ kind: "reuse", characterId }` ⇒ 基本属性整组取自该角色，**该角色不再进 `state.npcs`**
  （同一实体不能有两份真相）；
- `{ kind: "new", id, name, … }` ⇒ 调用方给定基本属性。

**`as` 是 node 级语法**（2026-11-18 用户纠正）：同一 `node` 别名写多份、各带 `as`，
即「同一节点按当前 self 给出不同正文与整套选项」。天然互斥；多变体必须有一份无 `as` 的兜底。
加载期展开成独立事件：as 变体带 `selfIs`，兜底带一组 `selfIsNot`（逐条 AND —— 否则 chain 来源下
两者会同时成立而串戏）。`goto` 与外部 `nextEventId` 指多变体首节点 ⇒ 展开成多条 self 门控的
同形选项，玩家仍只看到一条。**首节点也允许 `as`**。LLM 侧不开放 `as`。

### D5 名字可空、开局后可改

`playerName` 可选，留空显示 **「无名氏」**。

### D6 随机源按节点派生，不消耗主流

`derive(seed, openingId, nodeId)`，不推进世界 RNG 游标。同 seed + 同选择序列 ⇒ 同一世界；
中间插删步骤不挪动后续骰子。**抽到即认，不可重抽**（明确不做放弃入口）。

### D7 权重可按「已落定参数」调制

未实例化 ⇒ 按世界属性加权算不出来 ⇒ `weightBy` 继续**拒载**；但本会话前面已经 roll 定的参数是确定的。

```yaml
weightByParam:
  talentRoll: 0.8            # 数值参数：final += 值 × 0.8
  origin: { 御三家旁支: 12, 平民: -6 }   # 枚举参数：final += 表[落定值] ?? 0
```

- `final = max(0, weight + Σ)`，与事件侧 `wheel.segments[].weightBy` **同一套算法**，只换取值源；
- `resolveParamMap` 存的是 `option.set` 原样，所以先剥壳：对象且含 `value` ⇒ 取 `.value`；
- 加载期两道：`opening_weight_non_roll`（只有 roll 能加权）、`opening_weight_param_unresolved`
  （引用的 param 必须被当前节点**支配**，即每条路径都经过它；有回跳则跳过此检查）；
- 运行期相反：缺值 / 类型不符 / 表里没这个键 ⇒ **计 0，不抛错**（「没抽过」= 「没有偏向」）；
- `describeNode` 下发的 `weight` 必须是**本会话算出的最终值**，否则转盘面积是假的。

### D8 明确不做

第四种 settle kind / 重建 `taskDag` / LLM 参与开局决策 / 放弃与重抽入口。世界内加点走轮外端点，
复用同一 `AllocationSpec` 校验器。

### 硬约束

- **一个 param id 只能有一个写者**。`resolveParamMap` 是 `Object.assign`，后写覆盖先写且无提示。
  2026-11-18 的真实事故：`n13-entrance` 的 `begin` 也写 `weapon`，把第六格选的天逆鉾静默换成急救包。
  现在 `inspect check` 有一条 `opening-param-overwrite`（warn，按**可达性**判：
  分叉互斥的两个写者不算，同节点的两个选项不算）。
- **模板声明的 `set` 键必须是已声明 param id**（加载期拒载）；`allocate` 节点必须声明 `param`。
- `weightByParam` 只对 roll 生效，choose / allocate 挂了直接拒载。

## ADR-004 · 开局加点

### D1 只允许加**数值类**属性

文本 / 阶梯 / 复合属性不参与加点（没有「加 3 点阶梯」这种东西）。

### D2 预算由模板声明，引擎只解析不猜

`points: { pool, per, max, step }` 写在模板；引擎不提供默认值。

### D3 `number` 是开局期标量，不落世界字段

加点结果在 commit 时折进基础属性，**不留一个「剩余点数」字段**在世界里（世界内加点另说）。

### D4 运行期四条校验，失败即 400

总额不超预算 / 单属性不超 `max` / 步长对齐 / 属性必须是数值类。

### D5 落点是「叠加」而不是「覆盖」

与 D3 的基本/附加划分一致：加点叠在角色基线之上。

### D6 组件复用：`PointsAllocator`（`packages/rpg-ui`）

开局与（将来的）世界内加点共用同一个组件。

### D7 加点进「开局所得」

投影里算作开场收益，不写成「本轮收获」（那是回合增量）。

### 已知缺口

**游戏内加点已接**（2026-11-20，ADR-019，见 `40-属性资源与状态.md`）：效果 `grantAllocation`
挂请求 → 个人页 `PointsAllocator` → `POST /api/worlds/:id/allocation` 轮外提交，
校验器 `normalizeAllocation` 与本文件 D4 是同一份（不再是「将来复用」，是现在就复用）。

仍属产品裁决的：什么事件给点（升级 / 训练 / 奇遇 / 章节奖励）、能否洗点、是否允许战斗前临时加点。
**不走 `adjustAttribute` 直写**：那样等于替玩家做了选择。

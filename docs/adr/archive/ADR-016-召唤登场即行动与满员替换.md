# ADR-016 · 召唤登场即行动、满员替换，与中立单位的选敌

- 状态：已实施（2026-11-20）
- 触发：用户实测两条（2026-11-20 02:11）
  1. 「中立单位现在貌似只会打玩家。」
  2. 「召唤英雄单位之后再召唤其他英雄单位会失败；收回再切换需要空转一回合，且登场回合召唤物不行动，等于空转三回合，完全不合理。改成召唤那个回合召唤物会行动，收回不会行动（有代价）。召唤超出限制时，后面的替换前面的（不封印技能）。」
  追加约束：「替换的时候别把中立单位替换掉，只能替换友方单位。」
- 范围：`packages/game-core/src/v2/battle.ts`（AI 选敌、召唤、`canUseSkill`）、
  `seal.ts`（删掉一条文案）。**零模板改动**（不换指纹，用户手上的存档可以继续开）。

## 背景：三条规则各自都对，叠起来把「换手」罚成了最贵的操作

十影有六只式神共享一个英雄位。按 ADR-012/013 的规则，想换一只：

| 回合 | 玩家做的事 | 召唤物 |
| --- | --- | --- |
| 1 | 用 `sk-ten-recall` 收回玉犬（占掉这个回合的行动） | 玉犬下场 |
| 2 | 用 `sk-ten-nue` 召鵺（再占掉一个回合的行动） | 鵺登场但**不行动**（`enteredRound === round`） |
| 3 | 才能正常打 | 鵺终于出手 |

而「不收，直接召」在旧规则下被 `summon_limit` 拒掉。两条路都堵着 —— 一个以换手为卖点的术式，
换一次手要空转三个回合。这不是数值问题，是三条规则各自动机合理、合起来没人从玩家视角读过一遍。

## D1 中立单位从「两边」里挑最该打的那个

`campsOf` 早就规定中立对所有人敌对（ADR-012 D5），但**选目标**这一步漏了：
`resolveTargets` 不传 id 时取 `hostile[0]`，而敌对表是 `[玩家, ...友军, ...敌军]` 拼出来的，
第一位恒是玩家。于是「站在中间抽两边」实际只剩一边。

新增 `aiHostileTarget`：**只对中立单位生效**，从 `campsOf(caster).hostile` 里挑**血量比例最低**的
那个，同比例取先手序。

- 不掷骰子。`rng` 是整场战斗共用的一条流，为选目标多掷一次会让后面所有判定跟着变，
  旧战斗的可复现性当场碎掉。
- 只改中立：敌方 AI 打「敌人表第一位」是既有行为，一并改掉会静默改掉所有既有战斗的手感与录像。
- 结果：魔虚罗既会砍玩家，也会砍对面那只二级咒灵。它不再是谁的保镖，也不是谁的陪练。

## D2 召唤物在登场的那一回合就行动

`aiTurn` 的「入场当回合不行动」加一个例外：**`summonRef !== undefined`**（= 技能点名召来的）。

- 为什么要留这条规则给**中途加入**：援军从剧本里来，不是谁花一个回合召来的，
  到场即出手会读成「两次行动」。判据取「有没有被点名」，而不是「谁加的」。
- 为什么召唤物不该等：它是**玩家这个回合花掉的行动**换来的东西。同一回合里，
  玩家付了 MP、付了行动权，得到一只站着不动的召唤物 —— 那不是平衡，是延迟。
- ADR-012 D1 当初的担心（「召唤完它立刻借玩家的回合打一轮」）在这个口径下依然成立，
  只是结论变了：**这就是买它的钱**。真正的重复行动风险在援军身上，已由例外之外的分支挡住。

「收回不会行动」保持不变，它就是这条规则的另一半：收回要花掉一个回合的行动权，
没有返还、没有补偿。**代价在这里，收益在 D2** —— 一进一出正好是「换手要付一次钱」。

## D3 满员是替换，不是拒绝

`canUseSkill` 删掉 `summon_limit` 这条闸门；`performSummon` 在**一只都塞不下**时，
把**最早上场**的同档召唤物挪进回收架（`battle.bench`），新的一批顶上去。

- **只在塞不下时替换**：还有空位就照旧补满（`count: 3` 站着两只补第三只，ADR-013 D2 不变）。
- 被替换 ≠ 阵亡：进回收架，状态（hp / 补正 / 冷却）原样留着，不写 `state.lostSummons`。
  同一场里再点名它，原样回来 —— 与主动「收回」同一个去处。
- **名额按「落点阵营」算，不按召唤者阵营算**（用户追加约束「默认别把中立单位替换掉」，
  以及 02:26 实测「召唤魔虚罗的时候把玉犬替了」的修正）：`performSummon` 先定
  `team = faction === "neutral" ? "neutral" : caster.team`，名额统计、替换池、落点三者同源。
  早先写成 `caster.team`，于是召中立魔虚罗时它把自己算进「我的英雄档」—— 玉犬正占着那唯一的名额，
  于是玉犬被顶进回收架，中间站出一只不受控的魔虚罗。
  现在的口径：中立项与友军项各数各的，你的式神与它互不占名额、互不顶替（中立之间才互相替换）。
- 刚被这次召唤挤下场的单位**不参与**回收架的「认亲」：否则满员重召会变成
  「把三只挪进架子再把同一批搬回来」—— 花掉 MP，场上一个像素都没变。
- `seal.ts` 里 `summon_limit` 那条文案随之删除：面板上不该再出现「已经站满了」，
  因为它不再是一个「用不了」的理由。

## 后果

- 换一只式神 = **一个回合**（直接召，新的一只当场出手），不是三个回合。
- 场上同时存在「你的式神」与「不属于任何人的东西」成为常态。
- 献祭池也收窄到**同阵营**（`sacrificeTargets` / `sacrificeValueOf` 加 `team` 形参）：
  不受指挥的魔虚罗不可能是祭品，否则闸门放行、旋涡拿到加成，而场上那只一个像素没动 ——
  每次点都白赚一段伤害。`canUseSkill` 的 `sacrifice_empty` 同口径；模拟器跟着传 `"ally"`。
- `test/unit/adr-016.test.ts` 8 例锁住：中立挑最该打的、召唤当回合出手、援军仍不出手、
  满员顶掉先召的、中立不占名额、中立不被顶掉、**召中立不顶友军**。
- ADR-012 D1 的「入场当回合不行动」与 ADR-013 D2 的「满员补满否则拒绝」在本 ADR 之后只对
  「援军」与「补满」成立。

# ADR-014 · 未调伏的魔虚罗：中立召唤 + 适应

- 状态：已实施（2026-11-20）
- 触发：B-07 的验收项「魔虚罗能用纯数据配出来：开场或中途登场、敌我不分、每层减免递增、打不死才算输」
- 范围：**只做伏黑惠的 `sk-ten-mahoraga`**。宿傩借惠之身召出的魔虚罗、以及円鹿/貫牛之后那几只式神，
  等剧情追上再做 —— 现在配完，写到死灭回游时还要按那时的口径再改一遍。

## 背景

ADR-012 把四项机制（中立 / 召唤 / 胜负 / 补正层数）都建好了，但魔虚罗当时只配成一个「够硬够疼」的英雄档
召唤物：它会站在友军里打敌人，死了就永久失去。这跟原作差三件事：它**不听指挥**、它**越挨打越硬**、
它**打不死**。

本次不动引擎的骨架，只补一个字段，其余三条用已有机制拼出来。

## D1 `summon.faction`：召唤物站哪边

```yaml
summon:
  ref: shiki-mahoraga
  tier: hero
  faction: neutral        # 缺省 summoner（= 施放者阵营）
  onSummonerDown: stay
```

- 缺省 `summoner`：与今天逐字节一致（落进 `unitsOf(battle, caster.team)`）。
- `neutral`：落进 `battle.neutrals`。**敌我不分不需要任何新代码** —— ADR-012 D5 的
  `campsOf` 早就规定「中立对所有人敌对」，`aiTurn` 也从两边挑目标。
- 它不在 `enemies` 里 ⇒ 打死它不会白送一场胜利。这正是 B-07「不做」清单里那条：
  *不要把魔虚罗塞进 `enemies` 再加一条不死判定*——那会让胜利条件在数据层撒谎。
- 为什么叫 `faction` 而不是 `target`：`target` 已经是「这一发打谁」，`faction` 是「它站哪边」，
  两件事同时存在于一个技能上是常态（旋涡打敌人、魔虚罗站中间）。

## D2 每层适应：不加字段，用 `onRoundEnd` 叠层

```yaml
# statuses.yaml
- id: mahoraga-adapt
  stacking: stack
  combat:
    damageTaken: -0.15
    stacksPerLayer: true
```

- `stacksPerLayer` 是 ADR-012 D6 已有的开关：层数进战斗结算（`damageTaken` 乘 `stacks`）。
- 层数从哪来：`mahoraga-wheel`（挂在卡上）每回合末施加一层 —— `combat.onRoundEnd.applyStatus`
  的收件人恒为携带者自己（ADR-006 D1），正好是「它自己长」。
- 数学形状：5 层 = −75%，7 层 ≈ −105% ⇒ 伤害归零。**「越打越打不动」是这条式子的结果，不是特判。**
- 为什么不做「被打中才涨层」：那需要新增一个施加点（受击钩子），而回合末已经够表意，且**完全可回退**
  —— 删掉两段 yaml 就回到今天。

## D3 打不死：同样是数据，不是开关

`mahoraga-wheel` 每回合末 `heal: fixed 25`。配合 D2，它每回合回血、减伤递增，于是「杀不死」是
**血上限 / 减伤曲线 / 回血速率**三个数的涌现结果。

不新增 `unkillable` 标志：那等于把「打不死」写成一条不可解释的规则，玩家看到的是「血扣到 0 又活了」，
而看不到「因为它适应了这一击」。B-07「不做」清单里的第二条（满额 `immune` 当适应）否掉的正是这种写法。

「打不死才算输」也不需要新的胜负条件：它是中立的，会打你；你打不动它，输在 `player.hp <= 1`，
和今天的判负路径完全一致。

## D4 未调伏 ⇒ 不进 `lostSummons`

`markSummonLost` 跳过中立单位。

魔虚罗此时**没有调伏**，它本来就不在名册里（调伏是下一轮的名册机制）。阵亡就记进永久失去的话，
惠用一次「同归于尽」就永远少一张底牌 —— 而原作里这一手每次都是**再赌一次**。
等名册落地，调伏过的魔虚罗才会同时具备「个体」与「永久损失」两件事。

## D5 召回只收同阵营

`performRecall` 与 `canUseSkill` 的 `recall_empty` 闸门都只看 `unitsOf(battle, caster.team)`。

中间那只收不回来。这不是漏掉：**暴走的式神没有「收回」这个动作**，而「收得回来」正是调伏与否的分界线。

## 模板改动（`jjk-2006/3.0.0`）

| 项 | 改成 |
|---|---|
| `skills.yaml` `sk-ten-mahoraga` | `summon` 加 `faction: neutral`、`onSummonerDown: stay` |
| `statuses.yaml` | 新增 `mahoraga-adapt`（`damageTaken: -0.15` + `stacksPerLayer`）、`mahoraga-wheel`（`onRoundEnd` 回血 + 叠 1 层） |
| `characters.yaml` `shiki-mahoraga` | `statuses: [mahoraga-wheel]` |

`shiki-mahoraga` 的数值不动（CE 54 / 体格 15 / 375 血 / `sk-shiki-wheel` 必中）。

## 验收

- `faction: neutral` ⇒ 单位进 `neutrals`；它就绪后**同时**打玩家与敌人；它阵亡不判胜。
- `faction` 缺省 ⇒ 行为与今天完全一致（有回归用例）。
- 同一条 `mahoraga-adapt` 3 层与 1 层，`damageTaken` 不同；未开 `stacksPerLayer` 的补正一点不变。
- 魔虚罗阵亡后 `lostSummons` 不变、`sk-ten-mahoraga` 仍在面板上。
- `sk-ten-recall` 收不到中立那只（`recall_empty`）。

## 影响

- `SummonSpecSchema` 变 ⇒ 模板指纹变，旧档 `template_content_drift` 拒载（与本轮其它模板改动合并计一次）。
- `performSummon` 的目标数组从「施放者阵营」变成「`faction` 指定的阵营」；回收架、上限统计、实例 id
  都不受影响（它们按 `summonedBy` 认人，与阵营无关）。
- 中立召唤物随 `battle` 一起丢弃，不做敌人侧的 `writeBack`（与中立 NPC 同待遇）。

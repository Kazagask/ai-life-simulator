# ADR-008 必中与闪避（战斗判定的两层门）

- 状态：已实施（2026-11-19）
- 影响：`packages/shared`（skill / status-effect）、`packages/game-core`（battle / presentation/effects）、模板 `jjk-2006/3.0.0`（statuses / skills / characters）
- 起因：用户四条 —— ①「五条和伏黑个人线要写，这段时间在蒙太奇里，五条停一下再蒙太奇，伏黑直接在这里开局」②「无下限没做补正，补正做成闪避率 +100%（只有必中效果、强行术式解除才能命中），加一段官方描述」③「强行术式解除底层没有词表（计算时忽略对方增益），这该不该是一个词条？如果不是，就先做成必定命中」④「看看魔虚罗现在的机制能做吗」

第 ① 条是内容排期，见 `specs/iteration-2026-11-19-jjk-story-lines/draft/montage-boundary.md`；本 ADR 只裁 ②③④ 三条判定层的问题。

---

## D1 · 闪避是**独立的一道门**（`combat.evade`）

### 问题

原来的命中只有一条链：`hitChance = base + (攻-防)×0.05 + 补正`，最后**夹在 `[0.05, 0.95]`**。
也就是说，这个系统里**不存在「打不到」**，只存在「5% 也会中」。

拿它去表达无下限，只能写成「闪避 +95%」——读数上像「他有点滑」，而不是「他到不了」。
一条 5% 的破口会让 2006 年的五条每二十次挨一下，这不是数值问题，是**说反了**。

### 决定

`combat` 面新增 `evade: 0..1`，位置在**命中判定之后**：

```
掷命中骰 → 命中了 → 再掷闪避 → 闪过了就整段跳过（伤害/治疗/跟随目标的补正都不结算）
```

四条语义：

1. **不复用 `hitChance`**。后者是「掷骰修正」，被夹顶；前者是「到不到得了」，可以取 1。
2. **多来源按「至少闪掉一个」合成** `1 - Π(1 - x)`：两个 50% 叠起来是 75%，不是 100%。
3. **只对攻击性技能生效**（`target` 是敌方，或带伤害）。不加这条，闪避 100% 的单位会把自己
   的「反转术式·治疗」也躲掉——那是把防御写成了残废。
4. **日志必须点名是谁挡的**（`「无下限」把它隔在了外面`）。只说「没打中」，
   在「明明掷中了却没伤害」的时候读起来像 bug。

补正定义示例（`statuses.yaml`）：

```yaml
- id: infinity
  name: 无下限
  description: 把「无限」带到现实空间。任何东西靠近他都要走过无穷多的一半——无限减速、无限接近，永远停在「到达」之前。
  duration: { untilCured: true }
  stacking: unique
  combat:
    evade: 1
  visibility: known
```

`evade` 是**身份级**的东西（无下限、不可侵的结界），所以 `infinity` 保留了 `mythic-unique` 标签；
几回合就消失的战斗窗口仍按 2026-11-19 的品级纪律不打品质标。

## D2 · 必中是一个词（`hit: guaranteed`）

### 问题

「必中」在这份代码里一直是**隐式**的：省略 `hitCheck` 就等于命中率 1。
隐式写法有三个后果：

- 它挡不住闪避（闪避在下游），所以加了无下限之后，所有省略 `hitCheck` 的技能
  （业火、解、全体技）全部变成打不到；
- 它没法被检索：`inspect` / 展示层看不到「这个技能必中」；
- 它和「不掷骰」混为一谈，作者想写「命中率 100%」和「不存在没打中」时只有一个写法。

### 决定

`CombatSkillSchema.hit`：目前只有 `guaranteed` 一个值（留扩展位）。

| 写法 | 命中骰 | 闪避 | 用在 |
| --- | --- | --- | --- |
| `hitCheck: {...}` | 掷 | 掷 | 普通招式（体术、苍、赫、解、捌…） |
| 都不写 | 只掷满值（必过） | **掷** | 全力一击、无条件全体技 |
| `hit: guaranteed` | 跳过 | 跳过 | 领域、世界斩、强行术式解除 |

三条纪律：

1. **不写成「命中率 100%」**。命中率 100% 仍然会被闪避挡下（那是第二道门）；
   必中要的是「这条斩击里不存在没斩到」。
2. **与 `hitCheck` 互斥 ⇒ 拒载**。两个说法打架时不猜哪个优先（同 `onSelf`/`target`）。
3. **它是底层词表，与世界观无关**。领域、世界斩、咒术解除都走这一条——
   `battle.ts` 不认识「无下限」，只认识 `evade` 与 `guaranteed`。

模板里已落：

- `sk-domain-expansion` / `sk-domain-empty` / `sk-domain-malevolent`（伏魔御厨子）→ `hit: guaranteed`；
- 新增 `sk-sukuna-world-cut`（世界斩）：`hit: guaranteed` + `damage: fixed 48`。
  只给 `npc-sukuna-incarnate`（真身）：借伏黑之身那两个阶段还没把这招练出来（原作时序）。

> 为什么领域要显式标：领域同时「打全体伤害」和「给全体挂压制」。
> 伤害走目标循环（会被闪避拦），压制走阵营施加（不走命中）。
> 不标必中就会出现「压制挂上了、伤害被无下限挡掉」——半个领域。

## D3 · 「忽略对方增益」**不**做成通用词条

用户问的是：强行术式解除（计算时忽略对方增益效果）该不该进底层词表。

**裁：不做。** 三条理由：

1. **「增益」在协议里不是一类东西**。它至少是四类：属性补正（simulation）、命中/闪避、
   伤害倍率、控制语义（`control`）。「忽略」对每类的操作不同——是不读取、是移除、
   还是本回合压制？一个布尔词条说不清，最后一定是"作者以为穿透，引擎当成驱散"。
2. **强行解除的真实语义是一次性动作，不是结算修饰**。它是「把对方的术式停掉」，
   属于 `dispel` / `suppress` 家族的**动作**（有目标、有抵抗、有持续时间），
   而不是「我打你的时候不看你的 buff」。后者只是前者的一个副产品。
3. **现在的需求用必中就能完全表达**。世界斩打穿无下限，靠的是「必中」跳过对方唯一的防线，
   不需要知道对方身上还有什么。多一个词条不会让这一刀更对，只会让它更难解释。

**留给将来的接缝**：真出现「对方先开盾、我要把盾拆掉且持续 N 回合」的内容时，
按 `suppress`（压制补正 N 回合）单独设计，并在 ADR 里写清与既有 `seal`
（`control: cannot_use_skills`）的边界：`seal` 封的是**人**，`suppress` 压的是**补正**。

## D4 · 顺带修掉：阵营补正把本轮的伤害擦掉

写 D2 的测试时撞出来的**既有 bug**，与本次改动无关，但被它暴露：

`Combatant` 是**值拷贝**。`executeSkill` 先跑目标循环（伤害写进 target 快照），
再跑阵营施加——`campsOf()` 这时**重造**了一份快照，读到的是"还没写回"的旧血量；
收尾 `writeBack(extraReceivers)` 把旧血量写回，刚算出的伤害就没了。

命中面很宽：**所有「全体伤害 + 全体补正」的技能 = 每一个领域**，
日志里有「造成 35 点伤害」，血量一动不动。

修法：`campsOf(battle, state, caster, known?)` 接受本轮已在结算中的快照表
（施放者 + 目标），阵营施加复用它们，不再重造。

> 为什么旧测试没抓到：`battle-apply-target` 里那条「命中判定落空 ⇒ 敌人不掉血」
> 正是靠这个 bug 通过的（它以为自己在测「落空」，其实测的是「伤害被擦掉」）。
> 已按真相改写：必中不吃命中骰，随机数再差也照样造成伤害。

## D5 · 魔虚罗：现在做不了（评估，不实施）

用户问的三件事，逐条对现状：

| 想要的 | 引擎现状 | 结论 |
| --- | --- | --- |
| 召唤物 / 中途登场 | 战斗单位在 `createBattle` 一次建好；回合循环只遍历 `enemies` / `allies`；没有 `summon` 效果通道（`applyEffectsV2` 只在战斗外跑，战斗内物品效果还有白名单） | **做不了** |
| 中立单位、敌我不分 | `BattleState` 只有两个数组；`team` 是 `ally \| enemy`；AI 的 hostile 阵营由 `team` 反推；`checkBattleEnd` 以「enemies 全灭」判胜 | **做不了**（放进 enemies ⇒ 杀它就算赢；放进 allies ⇒ 它只打敌人，且不参与胜负） |
| 适应层数 | `multiplierOf` 按**实例**取值，`stacks` 不参与计算——同一补正叠 5 层和 1 层一模一样 | **做不了**（要"每适应一层减伤"就得让数值乘层数，或加按层数缩放的公式） |

**现在能做到的降级版（不改协议）**，两条：

1. **当技能**：现状 `sk-ten-mahoraga` 就是这条路——一次性大伤害 + 自身「力竭」。
   表达的是「拿命换时间」，不是「它会适应」。
2. **当开场就在场的单位**：`settle.combat.enemies/allies` 直接引用一张 `npc-mahoraga` 卡，
   配一个固定减免补正（`damageTaken: -0.5`）。没有层数，也不会随回合变强。

**建议**：真要做，按独立 ADR 设计「战斗内单位生命周期」三件事——
中立阵营（`team: neutral` + 目标选择）、召唤（`effect: summon` 在战斗内执行）、
计数器（补正按层数缩放）。三件里缺任何一件，魔虚罗都会写成"一个血很厚的杂兵"。
不要把它塞进技能里——那是把机制问题当成数值问题解决。

**后续（2026-11-19）**：已转成 `docs/BACKLOG.md` **B-07**，并把第四项补齐为
「胜负判定拓展」（`checkBattleEnd` 写死两条 if，中立/召唤物进来后必须能声明判据）。
那一条记录了四项各自的现状行号、要定的语义、依赖顺序与验收口径。

## 补记：无下限打完一场就消失（2026-11-19）

`combat.evade: 1` 是**身份**级别的机制，但它只有 `combat` 面。而 `finishBattle` 的补正转换
只留「有 `simulation` 面」的那些（规格 6.2：存续模拟面、清除战斗面）——于是玩家打完第一场
战斗，无下限就被当成一层战斗 buff 清掉了：**之后一次都躲不过，而且没有任何日志说它没了**。

**裁决**：判据从「有没有 simulation 面」改成「`duration` 是不是永久的」。

| `duration` | 语义 | 战斗收尾 |
| --- | --- | --- |
| `turns: N` | 打出来的、会到期的东西（眩晕、领域压制、黑闪余韵） | 只留 `simulation` 面 |
| `untilCured` | 这个人**本来就有**的东西（生得术式、六眼、无下限） | **一律留下**（哪怕只有 `combat` 面） |

为什么不改无下限本身（比如给它硬塞一条假 `simulation`）：那是在用数据绕过引擎的错，
下一条「只有战斗面的永久特质」还得再骗一次。`duration` 本来就是「这东西是不是临时的」
的唯一表达，判据应该读它。

顺带把同类问题一起收了（ADR-006 D1 的收尾）：`combat.onRoundEnd.applyStatus` 的收件人
只能是**携带者自己**。回合末结算按「谁身上挂着这条补正」逐个跑，没有施放者——写 `all_enemies`
既没有阵营可算，也会在补正挂在三个人身上时重复施加三次。**加载期拒掉**，不猜。
`chance` 在回合末也补上了掷骰（此前声明了却被静默忽略）。

验收在 `test/unit/battle-status-persistence.test.ts`（4）：无下限战后还在 / 六眼照旧 /
领域展开（`turns: 3`）被清 / 清掉之后闪避判定确实失效（不是只留一个名字）。

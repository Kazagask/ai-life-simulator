# ADR-017 · 关系协议收敛（强度单一真源 / 玩家侧边 / 情报档位下线）

- **状态**：已实施（2026-11-20）
- **提出人**：agent（收尾归档期协议债 B-19 / B-20 / B-21），用户 2026-11-20 指示「把剩下的 backlog 一起做了」
- **类型**：协议级（`schema/relation.ts`、`schema/world.ts`、`schema/opening.ts`、`engine.ts`、`turn.ts`、投影）
- **关联**：ADR-007（关系是事实，`scope` 说明多少人知道）、ADR-010 D5（`relationship` 语义收窄）、
  ADR-006 D3（关系行说人话）、ADR-014/016（中立项与名额）

---

## 背景：三条「写了两份、只用一份」

归档期（2026-11-16）留下三条债，形态相同：**同一件事有两个存储位置，只有一个有读者**。

| 债 | 两个位置 | 症状 |
|---|---|---|
| B-19 关系双真相 | `npc.relationship` 标量 / 关系边 `value` | 事件改一个，另一个原地不动：卡片 chip 与带 `kind` 的条件各说各话 |
| B-20 玩家侧边缺失 | `characters[].relations`（from 恒为该角色）/ 无 | 关系图上只有「他们视你如何」，没有「你视他们为何」 |
| B-21 情报档位 | `flags["infoVisibility:<npc>"]` / 无 | 开局往 `flags` 里写一串没人读的字符串（`relationSource:<npc>` 同理） |

三条都不是「功能没做」，而是**事实没有唯一归属**。补功能之前先把归属定死。

---

## D1 强度单一真源：端点是 self 就只住标量

**判据**：一条关系的强度属于「`from` 对 `to` 的看法」。当 `to` 是 self 时（「他视你如何」），
这个数字**只**住在 `npc.relationship`；边的 `value` 只对「当事人之外」的边有意义
（A 视 B 多重，而 B 不是你）。

落地：

| 位置 | 旧行为 | 新行为 |
|---|---|---|
| 模板声明（`turn.ts`） | `to: player` 带 `value` 照单全收 | 该 id 的 `value` **折叠进 `npc.relationship`**；边上不再留 |
| `adjustRelation` 边形态（`engine.ts`） | 写边的 `value` | 端点落 self ⇒ 标量 `+= value`；边照建（kind 是事实）但不带强度 |
| `addRelationEdge`（`engine.ts`） | 写边的 `value` | 同上，但 `value` 是**绝对赋值**，覆盖标量 |
| 条件 `{relation, kind}`（`engine.ts`） | 一律读边 | `to` 归一后等于 self ⇒ 读标量 |
| 加载期（`schema/world.ts`） | 不检查 | `to: player` 且写了 `value` ⇒ **error 拒载**（不静默丢弃） |

为什么加载期要拒而不是静默丢：作者写了 70 就会以为 70 生效，而实际生效的是卡上的
`relationship`。静默丢等于把「值不对」变成「值不对且没人知道」。

**唯一的折叠场景**是复用模板角色当自己（`as: npc-gojo`）：模板写的
`{ to: npc-gojo, kind: disciple, value: 80 }`（夜蛾视五条为弟子）在「你就是五条」这一局里
就是「夜蛾视**你**为弟子，强度 80」。以前这条 value 留在边上，而卡片读 `npc-yaga.relationship`
（8）—— 两个数字。现在折叠成 80，覆盖顺序 = 声明顺序（后者胜，与 `resolveParamMap` 同口径）。

冻结规则（ADR-0020 单向棘轮）对两种形态同时成立：`existing.frozen` 在写标量之前判，
所以「逝者的关系不再变」不因为换了存储位置而漏掉。

## D2 玩家侧关系边：`playerTemplate.relations`

`characters[].relations` 的 `from` 恒为该角色，所以玩家**作为玩家**（不是复用某个角色）时，
没有任何地方能声明「你视他为何」。关系图上于是只有入边。

`PlayerTemplateSchema` 加可选 `relations`（复用 `RelationDeclSchema`）：`from` 恒为 self，
加载期校验 `to` 必须是已声明角色，**不许写 `value`**（你自己的观感由行为养成，开局不预设数字）。

落地后投影无需改动：`buildRelationRows` 早就按 `e.from === viewerId || e.to === viewerId` 出边，
反方向的行带 `direction: "out"`。也就是说这条链一直通到前端，缺的只是**声明点**。

> 这是 B-20「玩家侧关系面板」的地基。面板本身仍属 UI 需求，记在 BACKLOG。

---

## D3 情报档位下线：`flags` 不放描述性事实

开局曾往 `flags` 写两组东西：

- `infoVisibility:<npcId>`（unknown / known / …）——`opening.yaml` 的 `npcSetup.visibility`；
- `relationSource:<npcId>`（「父亲」「学生」这类来源文字）——`npcSetup.relations[].source`。

全仓库没有读者（`grep infoVisibility` 只剩写入点与 mock 的清洗正则）。而且它们都不是
「可判定谓词」——`flags` 是条件 DSL 的谓词表，塞描述性事实只会让存档长出一串没人用的字符串。

知情程度在 V2 由三件**真事实**表达，各管一件事：

| 想知道 | 读哪 |
|---|---|
| 人物列表里有没有他 | `npc.visibility`（`public` / `hidden`） |
| 这条关系几个人知道 | 关系边 `scope`（`public` / `limited` + `knownBy` / `private`） |
| 他的秘密 | `npc.secrets` —— **永不投影**（投影注释早已写死） |

所以 `npcSetup.visibility` **从 schema 移除**，声明它 ⇒ 加载期报一句人话
（「已废弃，改用 characters[].visibility / 关系边 scope / secrets」），而不是
"Unrecognized key"。数据侧删掉 `jjk-shinjuku/1.0.0` 两处声明（`enemy-sukuna: known` 本来就是
缺省语义）；`relationSource` 不再假存旗标，来源文字留在声明侧（要展示就是关系行的副标题，
属展示层新需求，记 BACKLOG，不在这轮假装做了）。

---

## D4 契约层 `relationEdge` 改说 `scope`

`story.submitBranch` 的 `relationEdge` 仍要求旧四档 `visibility`（`known/inferred/unknown/hidden`），
而引擎早已用 `scope`。模型侧只应该见到一套词汇。

- `scope` 成为一等字段，`limited` 必须给 `knownBy`（否则这条关系谁都看不到，等于写了个黑洞）；
- `visibility` 保留为可选（旧调用方兼容），`engine-api` 的编译只在没给 `scope` 时才转发它。

---

## 后果

- 「卡片写 62、条件按 0 判」这类错位不再可能出现：只有一个数，两个读者。
- 模板作者多了一条加载期约束（`to: player` 不许带 value），但换来的是写多少就是多少。
- `playerTemplate.relations` 让玩家侧边有了声明点；投影与前端零改动。
- 存档不受影响：字段只减不增（`flags` 少两组字符串），旧档照常载入
  （`infoVisibility:*` 留在旧档里也没人读，不需要迁移脚本）。

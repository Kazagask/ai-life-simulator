# ADR-005 · 开局序章与第一幕

- 日期：2026-11-19
- 状态：已实施（W1 之后、W2 之前）
- 关联：ADR-001（前实例化开局 DAG）、ADR-0034（槽模型）、ADR-0027（R2.7 叙事层）、ADR-0035（编排层事务边界）
- 替换：无（编号 005 原先属于「开局权重按参数调制」，该文已并入 ADR-001 D7 并删除）

## 背景

1. commit 之后世界是冷启动：`slot === null`，玩家必须点一次「修炼 / 巡逻」才看得到任何内容。
   「这一生刚开头」在界面上是空的，只有一张属性面板。
2. 开局已经落定了 13 步（出身、术式、体质、加点…），但这些信息只以**卡片**形式存在，
   没有任何一句话把它们连成「一个人」。
3. 旧模板里唯一「开局即触发」的事件是 `evt:amane-short`（理子短线，语法验证用）：
   `source: pool` + `priority 110` + `window 92d`，抢在第一章之前，且两个出口都是死。
   用它当「开局事件」，等于把开局接到一个枪口上。

## 决定

### D1 序章是**装饰**，与 R2.7 同级

- 由服务端在 commit 时构造只读请求（`buildOpeningPrologueRequest`：世界、玩家、属性、
  术式/体质名、玩家真正拍板的那几步、`lore.md` 的 `always` 段），交 `generateNarrative` 校验。
- 输出 schema 只有 `{ text: string }`，**没有** `effects` / `state` / `flags` 任何写入口。
- 失败 / 超时 / 结构不符 / mock provider ⇒ `fallbackPrologue`（模板拼的确定性文案）。
  没有兜底就等于「没配 key 的玩家看到空白开局」，所以兜底文案是硬要求，有专门用例锁住。
- 不回写 `WorldStateV2` 的任何权威字段；只追加一条 `history`（`type: "milestone"`，`turnIndex = 0`）。

### D2 序章进 `history`，而不是只放进响应体

响应体只活在这一次 HTTP 里；刷新就没了。序章属于「这一局确实发生过的一句话」，
所以进存档的 `history`（`visibility: "public"`），同时**也**在 commit 响应里回传
（`prologue` / `prologueSource`），供开局结果页当场显示。

`type` 复用已有的 `milestone`：新增 history 类型是协议改动，这一轮没有为它开 ADR 的必要
（标签显示为「碑」，与章节标记同义）。

### D3 第一幕由模板声明，不由引擎硬编码

模板提供 `ev-open-01`：

```yaml
trigger: { source: schedule, window: { start: { value: 1, unit: minute } }, once: true }
conditions: [{ flag: creationDone, eq: true }]
```

- **必须是 `schedule`**：主线不许用 `pool`（池子是抽日常的；门的出现时间由时间表决定）。
  `window` 在 world 初始化时换算成绝对分钟固化，`1 minute` 即「立刻到期」。
- **由引擎在 commit 末尾呈现**：`presentQueuedEventV2` 只做 `nextTurn` 的「槽空 ⇒ 扫队列 ⇒ 写槽」
  这一段——不推 `turnIndex`、不耗行动、不加世界时间。否则序章与第一幕之间会断一次点击。
- 正文必须对六种出身都成立（只写此刻，不写身份），身份交给序章与章节门去说。

### D4 顺带裁决：主线门一律 `schedule`

`ev-ch1-gate … ev-ch7-gate` 由 `source: pool` + `probability: 1` + `time gte N day`
改为 `source: schedule` + `window.start = N day`。

- 语义等价（时间到 + 前提成立才上桌），但**不再消耗池子容量、不再参与随机抽取**，
  也不会因为「队列被日常占满」而把主线卡到 `timeReached`。
- 早到不了就 `hold`（`window` 内前提不成立 ⇒ 留队、每轮重估、零错失记录），与旧行为一致。

## 被否掉的方案

| 方案 | 为什么否 |
|---|---|
| 序章也走 `story.submitBranch`（LLM 写结构） | 开局第一句话不该有写世界的权力；R2.7 已经裁定 AI 只做叙事 |
| 在引擎里硬编码「开局事件 id」 | 引擎不认识某部作品的事件名（世界无关是硬约束） |
| commit 直接调 `advanceTurnV2({action:"wait"})` | 会凭空多一个回合、一次时间推进、一条「玩家行动」历史 |
| 让 `ev-open-01` 用 `pool` + `priority 999` | 池子仍可能被日常占满；优先级不解决「什么时候该出现」 |
| 新增 history 类型 `prologue` | 协议改动 + 迁移，收益只是标签从「碑」变「序」 |

## 验收

- `test/unit/opening-prologue.test.ts`：mock ⇒ 模板回退；合法输出 ⇒ `llm`；结构不符 ⇒ 回退；兜底只拼已落定事实。
- `test/unit/jjk2006-dag.test.ts`：commit 后队列 = 7 个章节门 + 开局第一幕（全部 `schedule-init` / `waiting`）；
  `presentQueuedEventV2` 把 `ev-open-01` 写进槽且 `turnIndex` / `worldTime` 不变；章节门不是 `pool`。
- `test/api/opening-prologue.test.ts`：真服务器 + 真模板走完 13 步 ⇒ `prologue` 非空、
  `snapshot.slotEvent.eventId === "ev-open-01"`、`history[0]` 就是序章，重载后仍在。
- `pnpm inspect check`：error 0。

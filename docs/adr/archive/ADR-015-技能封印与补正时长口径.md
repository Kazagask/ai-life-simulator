# ADR-015 · 技能封印 + 补正的两个「每回合」与战斗内时长口径

- 状态：已实施（2026-11-20）
- 触发：用户实测三连（2026-11-20 01:46）
  1. 补正的战斗效果写「每回合」分不清是战斗回合还是世界回合；咒火明明按天算，战斗里却写「还剩 2 天」。
  2. 战斗里选不了友军目标。
  3. 虹龙被献祭后，技能页那一栏还在，点开却什么也不发生 —— 应当「封印 + 原因」，而不是藏起来或装作能用。
- 范围：展示层（`presentation`）、投影（`projection`）、契约（`view-model`）、`rpg-ui`。
  **零模板改动、零引擎规则改动** —— 判据全部复用 `canUseSkill` / `expiresAt` / `roundsLeft`。

## 背景：一条补正同时活在两个域

`statuses.yaml` 的一条补正可以同时带 `simulation` 与 `combat` 两个面。咒火就是典型：
体术 -1（模拟面属性）、每回合心情 -1（模拟面，**世界回合**结算）、每回合掉 4 血
（战斗面，**战斗回合**结算）。面板把两行并排渲染，两行都写「每回合」——玩家没有
任何线索判断哪一行在战斗里生效、哪一行在他点「继续」时生效。

时长同理。ADR-009 之后时长只存在于**施加点**：`{ value, unit }` 落成绝对到期点
`expiresAt`（世界分钟），`{ rounds }` 落成 `roundsLeft`（战斗回合）。
战斗**不推进世界时间**，所以一场战斗里 `expiresAt` 一分钟都不会走。
沿用同一个「还剩 X 天」的文案，等于暗示「打一场会消耗两天」。

## D1 战斗面的每一条都写明「战斗中」

`statusEffectSummaries` 里，`combat` 段的所有行加前缀：

| 之前 | 现在 |
| --- | --- |
| 每回合受到 4 点伤害 | **战斗中**每回合受到 4 点伤害 |
| 每回合恢复 25 点生命 | **战斗中**每回合恢复 25 点生命 |
| 每回合施加 适应 | **战斗中**每回合施加 适应 |
| 受到伤害 -15% | **战斗中**受到伤害 -15% |
| 造成伤害 / 命中 / 闪避 | 同上，各加「战斗中」 |

模拟面保留「每回合」（= 回合推进）与直接读的属性行（`体术 -1`）。
不改判据、不改数值，只改这一层文案 —— 它是**定义 → 人话**的唯一出口（ADR-002 D3）。

## D2 战斗内的时长说两件事

```ts
remainingLabel(inst, worldTime, { inBattle })
```

- `expiresAt` + `inBattle` ⇒ `整场战斗有效（战后还剩 2 天）`
- `expiresAt` 否则 ⇒ `还剩 2 天`（个人页 / 玩家卡，口径不变）
- `roundsLeft` ⇒ `还剩 N 回合`（本来就是战斗内计数，两个域一致）

为什么是「整场有效」而不是「换算成回合」：没有换算关系。世界时间在战斗内是常量，
所以「这一场会不会掉」的答案是**确定的不掉**，不需要（也不该）估一个回合数。
ADR-009 的立场不变：**两个域各自计时，不做隐式换算**。

`finishBattle` 的收尾规则也不变：`battleOnly`（`rounds` / `untilBattleEnd` 施加）在战后清掉，
带 `expiresAt` 的原样留下 —— 所以「战斗中掉的血两天没好」是真的，打完还在。

## D3 封印：`seal { code, text }`

**取代 ADR-013 D3 的「从面板上拿掉」。** 藏起来比灰着更糟：玩家无法区分
「我没学过这一招」与「我学过，但现在没有」——虹龙被献祭之后，技能页那一栏还在、
点开却什么也不发生，正是这条口径造成的（技能页从来就没被过滤，只有战斗面板被过滤了）。

新增 `packages/game-core/src/v2/seal.ts`，两个入口、一份文案表：

```ts
skillSealOf(state, skillId, lookup)                  // 持久条件（只看存档）
battleSealOf(state, battle, casterId, skillId, lookup) // 这一回合（内部就是 canUseSkill）
```

| code | 文案 | 出现在 |
| --- | --- | --- |
| `summon_lost` | 「虹龙」已经不在了（阵亡或被献祭），本局再也召不出来 | 技能页 + 战斗面板 |
| ~~`summon_limit`~~ | ~~场上最多 3 只，已经站满了~~ —— **ADR-016 D3 已删除**：满员是替换，不是用不了 | — |
| `sacrifice_empty` | 场上没有可以献祭的召唤物 | 战斗面板 |
| `recall_empty` | 场上没有可以收回的召唤物 | 战斗面板 |
| `not_enough_mp` | 咒力不足 | 战斗面板 |
| `cannot_attack` / `cannot_use_skills` | 现在做不出攻击 / 现在用不了技能 | 战斗面板 |
| 其它 | 现在放不出这一招（不编原因） | 战斗面板 |

- **`skill_on_cooldown` 不下发**：面板另有「冷却 N」一行，再盖一层封印会让一件事看着像两件。
- 名字一律走 `lookup`（`summon.ref` → 角色卡 `identity.name`），模板里没有作品专名。
- 上限文案与引擎共用 `summonLimitOf`（本次导出）：面板写 3、引擎按 1 拒，是玩家永远想不明白的 bug。
- 契约：`SkillVMSchema.seal?`（技能页）与 `BattleSkillVMSchema.seal?`（战斗面板）同形，
  都是 `{ code, text }`。`code` 机器可读（将来做筛选/统计），`text` 直接上屏。

## D4 友军目标：补两处「看不见的缺失」

数据链本来就是通的（`BattleSkillVM.target === "ally"` → 点击友军卡 → `targetInstanceId`，
引擎 `resolveTargets` 的 `ally` 分支按 id 取人）。缺的是**能看见的东西**：

1. **没有「自己」这张卡**。友军单体技能的缺省目标是玩家自己，但玩家自己不在 `b.allies` 里；
   场上一只友军都没有时，面板上**一个可选目标都没有** —— 玩家的结论只能是「选不了友军」。
   现在 `needsAlly` 为真时在友军区首位渲染一张虚线「自己」卡，点它 = 清空选择。
2. **选中没有反馈**。`.ally.targeting` 从来没写过样式，`button.ally` 也没有 `cursor: pointer`，
   点完看不出选中了谁。现在与敌人卡片同一套高亮（`--accent` 描边 + 光晕），
   并在提示行写出「当前：自己 / 某友军的名字」。

⚠ 已知（本次不做）：jjk-2006 里**没有任何玩家可达的 `target: ally` 技能** ——
`sk-reverse-heal-ally` 只配在硝子和另一名角色身上。所以玩家在正式对局里摸不到这条链路；
要不要让「反转术式」同时授予「接续」，是产品决定（会换模板指纹，当前存档会被拒载），
留给用户裁决。

## 后果

- 面板能正确表达「技能在、但现在不能用」，四类理由各有名字；`canUseSkill` 仍是唯一判据。
- 战斗面板显示「整场战斗有效（战后还剩 2 天）」，不再暗示战斗消耗天数。
- `test/unit/adr-015.test.ts` 11 例锁死以上三条；ADR-012 里那条「面板上直接不给这个按钮」
  的断言同步改成「列出 + 带封印」。

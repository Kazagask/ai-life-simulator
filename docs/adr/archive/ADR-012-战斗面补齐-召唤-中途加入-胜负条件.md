# ADR-012 战斗面补齐：召唤、中途加入、胜负条件、层数与专属资源

- 状态：已接受（2026-11-19）
- 关联：ADR-003（自定义资源）、ADR-006（施加点收件人）、ADR-008（必中与闪避）、ADR-009（补正时长）、ADR-010（演员同构）、ADR-011（层数与战斗仪器）、`BACKLOG.md` B-07 / B-08
- 涉及：`packages/shared/src/schema/{common,skill,status-effect,equipment,character,item,event,world}.ts`、`packages/shared/src/{v2,v2-state}.ts`、`packages/shared/src/contract/view-model.ts`、`packages/game-core/src/{index.ts,v2/{battle,engine,projection,turn}}.ts`、`packages/rpg-ui/src/{BattleBoard.tsx,adapter.ts}`、`apps/web/src/style.css`、`apps/server/src/admin/sim.ts`（新，由 core 迁入）、`apps/server/src/{admin.ts,cli/inspect.ts}`、`specs/data/templates/jjk-2006/3.0.0/{characters,skills,statuses,items,events,world}.yaml`、`test/unit/{adr-012,sim,npc-actor-parity}.test.ts`

## 背景

B-07 列的四项（中立单位 / 召唤 / 胜负判定 / 补正层数）与 B-08 的两项（装备授予技能 / 施放消耗修正）都卡在同一处：**战斗里的「单位」只有开场那一次构建**。`createBattle` 跑一遍 `buildUnits` 就定终身，之后没有任何加人通道；胜负写死在两条 `if` 里；`stacks` 在战斗面完全不参与；装备只能给属性词条、给不了行为。

咒灵操术是这套缺口最完整的验收题：它需要「储备 → 召唤 → 收回 → 一次性献祭」四条路径，其中三条今天不存在。所以本轮以它为模板实验，一次把六项做完。

## 决策

### D1 召唤：技能声明，单位从角色卡建

```yaml
summon:
  ref: enemy-grade2-curse
  count: 1                       # 缺省 1
  tier: minion                   # minion | hero，缺省 minion
  limit: 2                       # 缺省见 D2
  consume: { resource: curses, per: 1 }   # 二选一：{ status: <id>, per: 1 } 按补正层数扣
  onSummonerDown: dismiss        # dismiss（缺省）| stay
  refundOnDeath: true            # 缺省 false：阵亡时把 summonCost 还给召唤者
```

- 单位一律走 `buildUnit`（`buildUnits` 拆出来的单件版本），所以它的装备、补正、心情、`levelScale` 与开场单位同源。
- 落进**施放者同阵营**数组，带三个新字段：`summonedBy`（召唤者 instanceId）、`enteredRound`（入场回合号）、`summonCost`（这次召唤花掉的资源，供召回返还）。
- **入场当回合不行动**：`aiTurn` 跳过 `enteredRound === battle.round` 的单位。否则玩家召唤完，它同一回合就替玩家打了一轮。
  （**已被 ADR-016 D2 收窄**：技能点名召来的单位（`summonRef !== undefined`）在登场当回合就行动；这条只对**中途加入的援军**继续成立。）
- `consume` 不足 ⇒ 拒绝码 `summon_fuel_short`；召唤物随召唤者倒下而移除（`onSummonerDown: stay` 可留）。
- `refundOnDeath`（缺省 `false`）：单位**阵亡**时把 `summonCost` 还给召唤者。默认关是通用直觉
  ——「召出来的用完即弃」；咒灵操术要的是反过来的经济，所以它在技能上显式声明（见 D9 补）。
  召回（`recall`）与阵亡都退，`onSummonerDown: dismiss` 那条**不退**（召唤者都没了，退给谁）。
- 技能有效性从「damage/heal/applyStatus 至少其一」放宽为「+ summon」。

**单一判定入口**：新增 `canUseSkill(state, battle, caster, skill, lookup)` → `{ ok: true } | { ok: false, reason }`。今天「够不够钱 / 冷却 / cannot_attack」在 `performBattleAction`、`aiTurn`、投影置灰、仪器挑招**四处各写一遍**，加召唤上限就会变第五处。统一后 `performBattleAction` 只把 `reason` 翻成错误码，其余三处直接用结论。

### D2 两级单位：minion（小框）与 hero（正常框）

| 档 | 缺省上限 | 前端 | 典型 |
|---|---|---|---|
| `minion` | 3 | 三分之一宽的小框，一行排三个 | 一般咒灵 |
| `hero` | 1 | 与真实战斗角色一致（整行） | 虹龙、魔虚罗 |

- 上限按**档**统计（同召唤者的存活召唤物总数），不是按 `ref`：所以「三只杂兵」可以混编，而英雄位只有一格。`limit` 可在技能上覆盖。
- `tier` 落在 `BattleEnemy.tier`，随投影下发；前端只按它选版式，不猜名字、不查模板。

### D3 中途加入：条件 / 回合 / 概率

```yaml
reinforcements:
  - id: ambush
    ref: enemy-grade1-curse
    side: enemy          # enemy（缺省）| ally | neutral
    atRound: 3           # 第 3 回合开始时判定
    everyRounds: 2       # 可选：每 2 回合再判一次
    chance: 0.5
    when: [{ flag: tengenCursed }]   # AND；不写 = 无条件
    maxAlive: 1
```

- 判定点在 `roundEnd` 末尾（`battle.round` 已 +1、新回合尚未开始），所以 `atRound: 3` 就是「第 3 回合开始时到场」。
- 未写 `everyRounds` ⇒ **只来一次**（触发后不再判）；写了则按间隔重复，受 `maxAlive` 限制。
- 进度记在 `battle.reinforcementFires: Record<string, number>`（键 = `id`，缺省用声明下标 `#0`），旧档缺省空表 ⇒ 不会重放。
- `when` 复用模板条件 DSL（`checkCondition` + 世界状态 + 战斗 rng），与事件触发同一套词表。
- 与召唤的区别写清楚：**召唤是技能消费资源换兵，中途加入是剧本按回合投放**。前者玩家能操作，后者是作者安排。
- 模板实验：`ev-combat-grade1` 加一条（`ref: enemy-grade1-curse`、`atRound: 3`、`everyRounds: 2`、`chance: 0.5`、`maxAlive: 2`、`when: [{ flag: missionsCompleted, gte: 1 }]`），五个旋钮一次写进真实事件。

### D4 胜负条件：判据可声明，缺省逐字节不变

```yaml
victory: [{ kind: unit_down, ref: npc-geto }]
defeat:  [{ kind: unit_down, ref: npc-riko }, { kind: player_down }]
```

| kind | 含义 |
|---|---|
| `all_enemies` | 敌方数组全灭（**胜利缺省**） |
| `unit_down` | 指定角色的**全部实例**倒下（含其召唤物） |
| `survive_rounds` | `battle.round > rounds` |
| `all_allies_down` | 友军全灭 |
| `player_down` | 玩家 hp ≤ 1（**失败缺省**） |

- 任一条为真即成立；仍按「先判胜、后判负」求值（与今天同序，保留那条 hp 恰好为 1 的边界行为）。
- 不写 ⇒ 完全走今天的两条 `if`，所以旧事件零漂移。
- `over` 仍是 `victory | defeat | flee`，不动存档协议与事件路由。

### D5 中立单位：第三方阵营，对所有人敌对

- `settle.combat.neutrals?: EnemyRef[]` → `battle.neutrals`（旧档缺省 `[]`）。
- `campsOf` 把中立并进**双方**的 `hostile`，它自己的 `hostile` 是全场其余人 ⇒ 三方混战。
- **不参与胜负**：缺省判据只数 `enemies`，中立死光不算赢、也不拦赢。
- 攻击倾向默认随机（无嘲讽类补正时），本轮不引入仇恨值。

### D6 补正层数：`stacksPerLayer`

`CombatFacetSchema.stacksPerLayer?: boolean`，缺省 `false`（今天的定值口径）。

为真时 `damageDealt / damageTaken / hitChance` 乘 `stacks`，`evade` 走 `1 − (1 − v)^stacks`（N 层独立门，而不是 `v × N` 直接捅到 1）。

模板里只有「每层适应」这类补正该开这个开关；毒、眩晕这类「层数只影响时长」的补正保持缺省。

### D7 装备授予技能：`grantsSkill`

- `items.yaml` 的装备加 `grantsSkill: <skillId>`，加载期校验技能存在。
- 技能集 = `角色/玩家 skills ∪ 装备授予`。`canUseSkill`、投影技能列表、`skill_not_owned` 判定三处同源。
- 不在战斗内动态装卸（没有换装指令），所以不需要「卸载即失能」的运行时路径；下一场自然重算。
- 模板实验：`eq-ten-spear`（天逆鉾）加 `grantsSkill: sk-ten-spear` —— `hit: guaranteed`、固定 32、`mp: 0`、`cd: 1`；`npc-toji` 的 `equipment` 挂上它，`skillWeights` 给 3。这样 ADR-008 的「必中」复用到装备上，顺带解掉「甚尔打五条 0 伤害」这个数值缺口（无下限挡的是伤害骰，必中技能穿过去），不必为一件装备新造一条 `ignoreEvade` 通道。

### D8 施放消耗修正：`mpCostMultiplier`

- `CombatFacetSchema.mpCostMultiplier?: number`，与 `damageDealt` 同形累加。
- 实际价格 `ceil(mp × max(0, 1 + Σ))`，**显式向上取整**：`18 × 0.1 = 1.8 → 2`；用 `round` 会让 -90% 漂成 -96%。
- 影响四处：`canUseSkill`（够不够）、`payCost`（扣多少）、AI 候选（自动跟上）、投影价格（面板显示）。

> **已被 ADR-013 取代（2026-11-20）。** D9 及其三个补充（咒灵经济 / 献祭 / 战后归池）
> 建立在「咒灵数量是一个池子」之上；用户随后判定这个池子只是「没法维护几百只」的规模压缩，
> 直接取消 —— 杂兵无限（场上限即稀缺）、英雄永久损失、献祭烧场上单位。
> 下面这一节保留原文，只作历史记录；现行口径见 `ADR-013-召唤协议简化-技能点名与英雄永久损失.md`。
> `summon.consume` / `refundOnDeath` / `recall.refund` / `consumeResource` 四个字段均已删除。

### D9 专属资源条：角色级资源池

```yaml
# characters.yaml
- id: npc-geto
  resources: { curses: { value: 3, max: 5 } }
```

- 形状 `Record<string, { value: number; max: number }>`，**自带上限**，不进 `world.resources`（模板全局池会变成「人人都有」）。
- 只在战斗单位构建时实例化（镜像到 `BattleEnemy.resources` / `resourceMax`）；玩家以该角色开局（`selection.kind === "reuse"`）时把池抄到 `state.player.resources` + `resourceMax`，战斗外也看得见。
- 池的三个读写口子：
  - `consumeResource: { resource, amount: "all" | number }` —— 技能结算尾部扣，「全清」与「定量」两种；
  - `gainResource: { resource, amount }` —— 命中后回补（咒灵操术的「吸收」就是它）；
  - `formula.preset: "resource-scaled"` → `{ base, perPoint, resource }` —— **先读后扣**：伤害按当前池算完，`consumeResource` 才清零，所以漩涡是「有多少打多少」而不是「先清零再打 0」。
- 引用校验：`summon.consume.resource` / `consumeResource.resource` / `gainResource.resource` / `formula.resource-scaled.resource` 的键，必须是「`world.resources` 的键」或「某个角色声明过的键」；运行期缺池按 0 处理（缺池 ⇒ 召唤不可用，而不是崩）。
- 战斗结束后，玩家侧的池随 `resources` 回写；NPC 侧是战斗镜像，随战斗结束丢弃。
  ⚠️ 回写时上限**必须**先问 `state.player.resourceMax[key]`：只问 `template.resources` 会让
  专属池被夹成 0（`resourceMax` 对未知键返回 0），表现就是「打完一场，咒灵全没了」。

#### D9 补 咒灵经济：存量，不是弹药（2026-11-19 用户口径）

| 事件 | 池 |
|---|---|
| 开局（`characters[].resources.value`） | 有 |
| 召唤（`consume.per`） | − |
| 召唤物**阵亡**（`summon.refundOnDeath`） | + |
| **主动收回**（`recall.refund`） | + |
| 旋涡献祭（`consumeResource: all`） | **永久 −，不回来** |
| 休息 / 时间 / 回合 / 任何被动 | **不动** |

- 所以「总共有几只咒灵」= 池（库存）+ 场上召唤物；两种减少方式里只有献祭是不可逆的。
- 因此**删掉**了 `sk-gather-curses`（原「每命中一次 +1」）：它在战斗里可无限重复，
  等于把存量变成弹药，与上表冲突。「吞咒灵」改由剧情效果落地（`adjustResource`）。
- `adjustResourceValue` 认专属池：`template.resources` 里没有的键，改用持有者自己的
  `resourceMax[key]` 当上限；两边都没有 ⇒ 不写（不凭空造池）。道具的 `adjustResource`
  同口径（否则「补 1 只咒灵」会被模板上限夹成 0）。
- **必须上屏**：池不在 `template.resources` 里，`resourceViews` 那两圈（statusBar / hp·mp 兜底）
  都扫不到它 —— 于是「夏油的咒灵数量」在界面上根本不存在。改法是给池声明加可选 `label`
  （`curses: { value: 3, max: 5, label: 咒灵 }`），投影在最后补一遍
  `state.player.resourceMax` 的键：值取战斗镜像 / 玩家身上那份，上限取声明值，
  标签取「第一个声明它的角色写的 label」，没写就用键名（不编造）。

#### D9 补二 献祭：场上的也烧（`consumeResource.includeDeployed`）

存量模型里「我有多少只」= 池（库存）+ 场上（已部署）。只读池的话，三只全放出去的夏油
会突然「没有储备」—— 而旋涡的设定本来就是**献祭**，场上那些当然能烧。

```yaml
consumeResource: { resource: curses, amount: all, includeDeployed: true }
```

- 读数：`resource-scaled` 用的那张表先补上「场上同资源单位的 `summonCost` 之和」，
  所以池 0 + 场上 3 仍然打出 55（`10 + 15 × 3`）。
- 消耗：**先扣池、再收单位**，两种来源之间不需要额外规则。收走的直接从战场移除、
  **不返还** —— 这就是献祭与召回的唯一区别（召回走 `recall`，会退 `summonCost`）。
- 单位不可分割：`amount` 写成具体数字时最后一只可能超额，多出来的部分算白烧。

#### D9 补三 战后归池：召出来没死也不能亏

战斗一结束，场上的召唤物随战斗消失；如果库存不跟着回来，「召出来、没死」就等于永久少几只。
`finishBattle` 因此补一步：**还活着的、属于玩家的召唤物**把 `summonCost` 退回池里
（阵亡的已经在 `markDeaths` 里按 `refundOnDeath` 退过，不重复）。败北同样退：
单位还活着，没理由因为主角躺下就判它们失踪。

同处还修了一个更致命的错：资源回写原先只用 `resourceMax(state.player, template, key)`，
而专属池不在 `template.resources` 里 ⇒ 上限算成 0 ⇒ **收场时把 `curses` 夹成 0**。
「打完一场咒灵就没了」的真正原因是这一行，不是「没退还」。

#### D6 补 友军单体目标

```yaml
target: ally   # 单体，不是群体
```

- 旧实现 `case "ally": return { targets: friendly }` —— **「治疗一个队友」变成了群体治疗**；
  而 `targetInstanceId` 原本只在 `enemy` 分支被读，前端也从来没有传过友军 id。
- 现在按 id 挑；缺省取 `friendly[0]`，在友军阵营里那就是玩家自己 ⇒「不传 = 治自己」。
  传入的 id 不在友军侧时同样回落到缺省（不返回空目标，免得技能白扣钱白进冷却）。
- 契约：`BattleSkillVM.target` 下发目标类型，前端据此决定「哪边的卡片可选」；
  友军卡片**只在存在友军单体技能时可点**（平时点它没有语义），再点一次回到「自己」。
- AI：`aiAllyTarget` 挑血量比例最低的那个友军，没人受伤就交回缺省 ——
  否则队医会一直对着满血的自己读治疗。
- 模板落点：`sk-reverse-heal-ally`（家入硝子，`target: ally`），给这条链一个真实用户。

### D10 咒灵操术重做（模板实验）
| 技能 | 形态 |
|---|---|
| ~~`sk-gather-curses`~~ | **已删**：每命中 +1 是「自然恢复」，与 D9 补的存量经济冲突；吞咒灵改由剧情效果给 |
| `sk-summon-curse`（新） | `summon: { ref: enemy-grade2-curse, tier: minion, consume: { resource: curses, per: 1 }, refundOnDeath: true }` |
| `sk-summon-dragon`（新） | `summon: { ref: enemy-grade1-curse, tier: hero, consume: { resource: curses, per: 3 }, refundOnDeath: true }` |
| `sk-recall`（新） | `recall: { count: 1, refund: true }`，把 1 只收回并返还召唤消耗 |
| `sk-uzumaki` | 改 `consumeResource: { resource: curses, amount: all, includeDeployed: true }` + `resource-scaled` 公式：base + 每点 × 15 |

这样储备在「三只杂兵 / 一只英雄 / 一发旋涡」之间取舍，一张卡把召唤、两级上限、召回、资源消耗四条链全压到。

配套：`npc-geto` 的 `combatHints.skillWeights` 同步新技能表（`sk-recall` 在内）；2018 的
`enemy-geto-parade` 与 `npc-kenjaku` 也补上了各自的池（5/8、6/9）与同一套召唤技——
此前它们只有 `sk-uzumaki` 却没有槽，`resource-scaled` 永远读到 0，等于把旋涡打成固定 10 点。
旧的 `absorbed-curses` 补正（拿层数当计数器、`combat: {}` 纯展示）随之删除。

## 验收

- 召唤：`limit` 生效（第 4 只被拒，`summon_fuel_short` 优先于 `limit` 判定）、入场回合不行动、召唤者倒下连带消失；
- 两级：minion 上限 3 / hero 上限 1，可被技能覆盖；投影 `tier` 正确；
- 中途加入：`atRound` 到点、`chance` 走 rng、`when` 为假不出现、`everyRounds` 重复且受 `maxAlive` 限制、存档重载不重放；
- 胜负：`unit_down` / `survive_rounds` / `all_allies_down` 各自命中；不写条件时与 ADR-011 的行为逐字节一致（回归用例）；
- 中立：不入胜负、被双方 AoE 波及、可作为单体目标；
- 层数：`stacksPerLayer` 两档各一例；缺省状态行为不变；
- 授予技能：持天逆鉾可放 `sk-ten-spear`（不写入角色 `skills`）、不持时 `skill_not_owned`；
- 消耗修正：`ceil` 口径（`18 × 0.1 → 2`）、四处一致、未声明时价格不变；
- 专属资源：夏油开局 3/5、召唤 −1、召回 +1 且返还的是**该单位自己的** `summonCost`、旋涡清零；
- 咒灵经济：召唤物**阵亡**也回补（`refundOnDeath`）、未声明的召唤物死了不退、旋涡献祭后
  连空过数回合池仍是 0（无自然恢复）、`adjustResource` 能加但被自身上限夹取、没有槽的角色加不上；
- 上屏：夏油的状态栏有「咒灵 3/5」这一条（标签来自角色声明的 `label`），其他角色没有这条；
- 献祭：池 0 + 场上 3 只 ⇒ 漩涡读 3 打 55，打完场上清零、池仍 0（不返还）；
- 战后归池：召唤 1 只（池 3→2）后战斗收场 ⇒ 池回 3，`state.player.resources.curses` 也是 3
  （回写不再把专属池夹成 0）；
- 友军单体：`sk-reverse-heal-ally` 指定某只友军 ⇒ 只有它回血，另一只不动；不传 id ⇒ 打自己；
- 计算顺序：`resource-scaled` 读到的是**扣之前**的池（池 5 ⇒ 伤害 base+75，随后池归 0）；
- 门禁：`pnpm test` / `pnpm inspect check` / `tsc` / `pnpm build` 全绿。

## 后门清理（同轮）

`packages/game-core/src/v2/sim.ts` 是给 CLI 与后台量数值用的仪器，它不是引擎能力，却从 `game-core` 的公共出口导出 —— 任何扩展只要愿意就能绕过回合管线造一场战斗。本轮移到 `apps/server/src/admin/sim.ts`（后台工具的实现位置，`/api/admin/sim` 与 `pnpm inspect sim` 共用），并从 `packages/game-core/src/index.ts` 删掉导出行。

连带把 `resources.ts` 正式导出（仪器要 `initPlayerResources`，那是正经 API 而不是后门），并让仪器吃上本轮的新规则：

- 挑招走 `canUseSkill`、价格走修正后的 `effectiveCostOf`、公式走带 `resourceSheet` 的 `rollFormula`；
- 技能集改问 `playerSkills`（角色自带 ∪ 装备授予）——直接读 `state.player.skills` 的话，仪器看不见天逆鉾；
- 期望伤害**折闪避**（`evadeOf` 因此对外导出）：不折的话「41 点但永远打不进无下限」会一直压过「32 点必中」，仪器就永远量不到必中；
- 报告加 `summonsPerDuel`、每行加 `summons`，命中率只在「这回合自己放的是攻击技」时才计（否则召唤物打掉的血会让命中率超过 100%）；
- 加 `stance: damage | coverage`（CLI `--stance`、木桩页「挑招姿态」）。`damage` 是原来的堆伤害口径；`coverage` 先把「召唤 → 满员 → 召回 → 再召唤」走完——夏油在 `damage` 口径下第一发就是旋涡，池清零，召唤链路一行都跑不到。

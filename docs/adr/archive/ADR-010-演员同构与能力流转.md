# ADR-010 演员同构与能力流转

- 状态：已接受（2026-11-19）
- 关联：ADR-001（前实例化开局）、ADR-003（属性）、ADR-007（关系范围）、ADR-009（补正时长）、`BACKLOG.md` B-07
- 涉及：`packages/shared/src/v2.ts`、`v2-state.ts`、`schema/character.ts`、`schema/common.ts`、`game-core/src/v2/{engine,turn,battle,projection,actors}.ts`、`specs/data/templates/jjk-2006/3.0.0/characters.yaml`

## 背景

同一个「人」在引擎里有两个身份来源：玩家在 `state.player`，其余人在 `state.npcs`。`actors.ts` 已经把**读取**统一成 `actorOf` / `ActorRef`，但**写入**与**能力**没有统一。审计出十项不对称：

| 能力 | 玩家 | NPC | 性质 |
|---|---|---|---|
| `equipment` | 有（29 处逻辑） | 无，模板都声明不了 | 甚尔拿天逆鉾只能手改 `attributes` |
| `resources` | 有 | 无，但 `BattleEnemy.resources` 有 | 模拟/战斗两套真相 |
| `skills` 运行时可变 | `unlockSkill` | 无（只写 `state.player.skills`） | 五条会赫只能造新角色卡 |
| `inventory` 效果 | `grantItem` / `removeItem` | 有字段、无通路 | 送/抢都做不到 |
| `applyStatus`（模拟域） | 有 | 无 | NPC 不能被下毒、治伤 |
| `growthLevel` | 有 | 无 | — |
| `lifecycle` / `personality` / `goals` / `traits` / `knowledge` / `secrets` / `visibility` / `isEnemy` | 无 | 有 | 切换角色必丢 |
| `age` 语义 | 当前年龄 | 起始年龄快照（ADR-0021） | 同名不同义，切换后算错 |
| `mood` | 真值 | **硬编码 50** | 真 bug：NPC 心情不进战斗 |
| `relationship` | 关系边（图） | 独立标量 | 与 `relations.ts` 零关联，双轨 |

这十项里，`equipment` / `resources` / `skills` / `mood` 是玩家能感知的缺失；其余是为「观察者模式 / 切换角色 / 夺舍 / 共生 / 继承」铺路时必须先补的。

## 决策

### D1 字段同构：两个结构互为可逆映射

不引入新的 `V2Actor` 实体（那会变成第三种身份来源，与 ADR-001 的"self 唯一权威"打架），而是让 `V2Player` 与 `V2Npc` 的字段集合**互为子集**：

- `V2Player` 增可选：`lifecycle`、`personality`、`goals`、`traits`、`knowledge`、`secrets`、`visibility`、`isEnemy`、`birthTime`、`lastActedAtTurn`、`relationship`
- `V2Npc` 增可选：`resources`、`equipment`、`growthLevel`

全部可选、无默认值 ⇒ 旧档直载（沿用 `birthTime` / `lifecycle` 的先例）。新增 `actorTransfer`（纯函数）做两个结构之间的字段搬运，**这是切换角色、夺舍、继承的唯一通道**。

不做"去单例"重构：`state.player` 有 142 处引用（engine 43 / battle 28 / turn 18 / opening-dag 14 / projection 9 / 其余 30），改造收益（同一时刻只有一个 self）低于风险。搬运法让这 142 处一行不动。

### D2 能力流转一律带 `who`

`grantItem` / `removeItem` / `unlockSkill` / `adjustProficiency` / `applyStatus` / `adjustResource` 增加可选 `who: string`（缺省 = self）。解析走单一入口 `writableActorOf(state, who)`：

- `who` 缺省或等于 `selfIdOf(state)` ⇒ `state.player`
- 其余 ⇒ `state.npcs` 中该 id，且必须 `lifecycle.state === "alive"`（否则静默无效并记一条拒绝原因）
- 加载期校验 `who` 指向「已声明角色」（`checkEffectRefs`）

这样模板写「给五条发赫」，不再需要为五条造第二张卡。

### D3 NPC 装备与补正生效

- `characters[].equipment` 允许声明（模板层），实例化时转成 `EquipmentInstance[]`。
- 战斗单位构建（`spawnUnit`）时，装备的静态词条叠加到单位属性；动态词条（`evaluateDynamicModifier`）按单位当前状态现算——与玩家走**同一个函数**，不写第二套。
- `mood: 50` 硬编码改为读实例 `mood`（`BattleEnemy` 增可选 `mood`）。
- 模拟域 `applyStatus` 走 D2 的 `who`，`applyStatusToPlayer` 改名为 `applyStatusTo`（保留旧名导出做兼容别名）。

### D4 观察者视角：投影带 `viewerId`（**只影响可见性**）

`projectWorld` 增加可选 `viewerIdArg`（缺省 = `selfIdOf(state)`），只做两件事：

- 关系可见性按它判定（`relationVisibleTo(edge, viewerId)` —— 这个判定早就参数化了，
  注释里写着「下次切视角换个 id 即可」）；
- 写进快照的 `viewerId`，前端据此显示「你在看谁」。

**不改 `self` 段，也不动那 9 处 `state.player`。** 观察者是「看别人」，不是「变成别人」；
「换人控制」是另一件事，走 `transplantActor` + 改 `selfId`（D1 的搬运法）。
两者混用会让「这条血条是谁的」失去唯一答案。

推论：观察者模式下 `relationship` 仍解释为「被观察者 → self」——因为 self 没变。

### D5 `relationship` 语义收窄

`npc.relationship` 保留，但语义固定为「**该 NPC 对当前 self 的单向好感标量**」，不参与任何判定（判定一律读关系边）。它与关系边是两种东西，不是双轨：

- 关系边 = 有类型的关系（`kind` + `scope` + `value`），可多条、是图；
- `relationship` = 无类型的总体态度，供 AI 效用评分与投影显示。

切换 self 后该字段**自动解释为新 self**，无需迁移。这一条要写进 `v2.ts` 的字段注释，否则下次还会有人以为是冗余。

### D6 NPC 成长走世界时间表

NPC 的技能集只能通过 `scheduledFacts` + `unlockSkill`（带 `who`）增长。理由：这与 ADR-007 D1 的定位完全一致——「世界到点就该如此」，不吃主轮 RNG、一事实只发生一次、按声明顺序执行。

不引入 `character.upgrades` 之类的第二套机制。

### D7 为切换角色预留的三个位置（本轮不实现行为）

| 场景 | 实现路径 | 本轮做什么 |
|---|---|---|
| 观察者 | `viewerId` | D4，已做 |
| 切换角色（夺舍/继承） | `actorTransfer` | D1，纯函数已就位 |
| 共生（一体双意识） | 未定 | 不建字段。真要做时再裁 |

**夺舍不需要新字段**：身体 = 目标 `V2Npc` 的 `attributes`/`hp`/`statuses`/`equipment`，意识 = 原 self 的 `skills`/`growthLevel`/`knowledge`。字段同构后可任意组合，组合规则属业务层，不进协议。

## 不做

- **去单例重构**（`state.player` → `actorOf(selfId)`）：142 处，风险高于收益。
- **夺舍/共生的专用字段**：先证明 `actorTransfer` 的组合不够用，再加。
- **NPC 自主使用物品**：`npcActions` 仍不读 `inventory`。等自主行动那波（缺口序列第 1 项）。
- **`age` 语义统一**：NPC 的 `age` 已是「起始快照」（ADR-0021），切换时用 `birthTime + worldTime` 现算，不改字段。

## 验收

1. `npc-gojo` 不再在开局就具备 `sk-gojo-red` / `sk-domain-empty`，由 `scheduledFacts` 在怀玉之后解锁（`fact-gojo-red` / `fact-gojo-domain`）。
2. 事件效果 `{ type: grantItem, itemId: x, who: npc-megumi }` 能把东西放进 NPC 背包；`who` 写未知角色时 `inspect check` 报 error。
3. `characters[].equipment` 声明的咒具经 `effectiveAttributesOfActor` 进入战斗单位构建（构建路径已改用同一函数；用例覆盖「带装备 vs 裸装」的属性差）。
4. `projectWorld(..., viewerIdArg: "npc-megumi")` 的关系行只含对该角色可见的边，`snapshot.viewerId === "npc-megumi"`，而 `self` 段仍是玩家。
5. `transplantActor` 的四个分组各自可独立搬运；`age` 不在任何分组里；源没有的字段会被删除（不留残影）。
6. 旧档 `loadable: true`（新增字段全可选）。
7. 门禁：`pnpm test` 67 文件 / 462 例全绿、`inspect check` error 0、`tsc` 0、`pnpm build` 通过。

## 备注

`mood: 50` 硬编码是本文档审计中唯一既存 bug（NPC 心情从不影响战斗 AI 的 `moodBand`）。D3 顺手修掉，不单独开工单。

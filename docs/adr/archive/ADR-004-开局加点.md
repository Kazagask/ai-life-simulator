# ADR-004 · 开局加点系统

- **状态**：已裁决（2026-11-19）
- **关联**：ADR-001（前实例化开局）、ADR-003（属性类型与自定义资源）
- **涉及包**：`packages/shared`（schema）、`packages/game-core`（开局 DAG 内核）、`apps/server`（会话 API）、`packages/rpg-ui`（组件）、`apps/web`（开局向导）、`specs/data/templates/jjk-2006/2.0.0`

## 背景

ADR-001 在开局 DAG 里预留了 `allocate` 节点，`packages/shared` 也留了 `points` 参数类型与 `budget` / `targets` 字段。
但落地状态是「半成品」：

1. 预算只能写死在参数声明里，**没法由前面的 roll 决定**——「抽技能点」表达不出来；
2. 前端只有一排裸 `input[type=number]`，显示的是机器属性名（`cursedEnergy`），没有标签、样式、上下限提示、剩余点数约束，也没有任何复用可能；
3. 内核只校验「合计 = 预算」和 target 的 `min/max`，**不拒绝白名单之外的键**，也不拒绝小数/负数；
4. `points` 结果没有进「开局所得」面板（提交后看不见自己加了什么）；
5. 没有任何模板真的声明过 `allocate` 节点，所以整条链路等于没跑过。

## 决策

### D1 只允许加**数值类**属性

加点目标白名单由模板 `params[].targets` 声明，但引擎在**加载期**强制校验：
每个 `target.attribute` 必须已声明，且 `kind ∈ {number, ladder}`。
`enum` / `composite` 一律拒载 —— 文本类属性没有「加一点」的语义，
放行会在 commit 时写出 `"特级" + 2` 这种脏值。

### D2 预算由模板声明，引擎只解析不猜

`budget`（字面数字）与新增的 `budgetFrom`（指向另一个开局参数 id）二选一：

```yaml
params:
  - { id: talentRoll, kind: number }
  - { id: talentPoints, kind: points, budgetFrom: talentRoll, targets: [...] }
```

- 有 `budgetFrom` ⇒ 预算 = 该参数在**本会话**已落定的数值（由 roll/choose 写入），
  参数没落定或不是非负整数 ⇒ 报 `opening_allocate_budget_unavailable`，**不回退 0**；
- 否则用 `budget`。

这样「抽多少点」是模板的自由：可以 roll 出 3/4/5，也可以直接写死 5。

### D3 `number` 是开局期标量，不落世界字段

参数闭集新增 `kind: "number"`：只存在于开局参数表，commit 时**不写**任何世界字段。
它存在的唯一理由是承载「预算」「加成数值」这类标量，
避免模板为了存一个数而去污染 `flags` / `attributes`。

### D4 运行期四条校验，失败即 400

`resolveStep` 收到 `allocate` 时逐条校验，任何一条不满足都抛错（不静默修正）：

1. 分配键 ⊆ `targets`（白名单之外的键直接拒绝，否则能绕过上限加任意属性）；
2. 每个值是非负整数；
3. 每个值落在该 target 的 `[min, max]`（target 不写 `max` ⇒ 不设上限，可吃下全部预算）；
4. 合计**不得超过**预算。

> **2026-11-19 修订（用户裁决）**：原来要求「正好等于」。实际玩家会遇到「这几点加哪儿都别扭」，
> 强制分完反而逼着乱点。现在允许放弃余额：内核只拒绝**超支**（`opening_allocation_over_budget`），
> 「还有余额就提交」由前端弹二次确认（`ls-alloc__confirm-mask`）提醒「剩下的点数会作废」。

### D5 落点是「叠加」而不是「覆盖」

`commitOpening` 把 `points` 按 `attribute += value` 写进 `state.player.attributes`。
与 `attribute` 参数的 `mode: set` 分开：加点永远是增量，
不会被后面的开局参数覆盖，也不会覆盖已从角色模板取到的基础值（复用角色路径同样成立）。

### D6 组件复用：`PointsAllocator`

UI 从 `apps/web/main.tsx` 抽到 `packages/rpg-ui/src/PointsAllocator.tsx`：

- 输入：`budget`、`targets`（带 `label` / 可选 `style` / `min` / `max`）、`value`、`onChange`；
- 行为：`+` / `-` 步进、剩余点数、每项上限提示、重置、禁用到界；
- **展示信息由投影下发**（`describeNode` 解析 label/style），前端不查模板；
- 游戏内加点（升级、训练、奇遇）**复用同一个组件**，见组件头部注释。

### D7 加点进「开局所得」

`collectOpeningGains` 补 `points` 分支：每个非 0 项产出一条 `category: "attribute"` 的
`up` 条目，与其它开局所得同一份数据、同一套样式。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| 用 `flag` 参数承载预算 | 会顺手写进 `state.flags`，留下一个没有任何规则读取的脏 flag |
| 允许加点写 enum/composite | 语义不成立，且会把文本属性写成数字 |
| 允许剩余额**静默**提交 | 玩家容易误以为「剩下的以后再点」，而开局不可回访 ⇒ 必须有二次确认（2026-11-19 已按此实现） |
| 支持负数加点（洗点） | 开局没有「已加点」概念，负值等于白送属性，且与 `min` 语义打架 |
| 把加点做成 effect DSL | 开局期没有 WorldStateV2，重放 effect 会引入第二条落点路径（ADR-001 已否） |

## 后果

- 模板作者多两个字段（`budgetFrom`、`targets[].label/style`），但换来「抽点数 + 带样式的加点面板」；
- `number` 参数是新的闭集成员：**新增参数类型必须走 ADR**（本 ADR 即该类型的第一例）；
- 加载期多一组交叉校验，写错 target 会在 `template_invalid` 里直接看到字段路径。

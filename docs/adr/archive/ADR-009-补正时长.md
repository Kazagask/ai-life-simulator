# ADR-009 补正时长：按各自域的时间轴量，不按指针次数

- 状态：已实施（2026-11-19）
- 影响：`packages/shared`（common / skill / status-effect / v2-state / v2）、`packages/game-core`（engine / turn / battle / opening-dag）、模板 `jjk-2006/3.0.0`（statuses / skills / events / opening）
- 起因：用户两条 —— ①「补正要不要带持续时间？yaml 里是声明、apply 之后才是实例。带着的话就会出现『眩晕=无法行动，战斗中持续两回合』，但现在 apply 可以指定回合数」；②「更麻烦的是：非战斗时事件、行动都是按事件走的，补正却按轮次走」

---

## D1 · 定义侧不带任何时长

补正定义只说**发生什么**（simulation / combat 面、`stacking`、`cureConditions`、展示）。
「这次多久」是**实例属性**，只能由施加点说。

理由不是洁癖——旧设计里 `duration` 是**必填**的，于是作者必须在定义里编一个数字、再在施加点编一个，
而四个读取方各读各的：

| 读取方 | 旧读法 |
|---|---|
| 模拟轮递减 `tickSimulationStatuses` | 读**定义** `duration.turns`，写实例 `turnsLeft` |
| 战斗到期 | 读**定义** `combat.battleRounds`，**完全不读 `duration`** |
| 战后存续 `finishBattle` | 读**定义** `duration` 判永久 |
| 施加侧 `applyStatus.duration` | 只在模拟域生效；战斗施加处根本不看 |

两个现成的病：

- `veil`（帐护）定义写 `duration: {turns: 2}` + `battleRounds: 2`，而三个技能的施加点写
  `duration: {turns: 3}`。作者以为「三回合是技能给的」，**战斗里实际生效 2 回合**，施加点的覆盖
  静默作废。
- `stun`（眩晕）写 `duration: {turns: 2}`，但它是纯 combat 面、战后必清，玩家的 `statuses` 里
  永远不会有这个实例 ⇒ 那个 `turns: 2` **从未被任何代码读过**。真正的时长由 `battleRounds: 1` 决定。

对纯 combat 面补正，`duration` 的信息量只有 1 bit（「战后留不留」），而这个 bit 可以从「挂载还是施加」
推出来。删掉不损失任何表达力。

## D2 · 模拟域时长 = 世界时间，实例存绝对到期点

### 为什么不能数「轮次」

`turnIndex` 数的是**指针推进了几次**，与世界观时间流逝脱钩：

| 路径 | 世界时间 | `turnIndex` | 旧补正 tick |
|---|---|---|---|
| 自由行动 | +1 天（`action.duration`，可配） | +1 | ✅ 全仓唯一调用点 |
| 事件结算 | `advanceBy` / `advanceTo` | +1（`settleSlotEvent`） | ❌ **完全不 tick** |
| 战斗 | 不动 | 战斗内单独推进 | 按 `battleRounds` |

`tickSimulationStatuses` 只有一个调用点（`advanceTurnV2` step 5）。而 `events.yaml` 有 **22 处
`advanceTo`，全部落在 518–4752 天**（1.4–13 年）。于是：

> 玩家挂着「重伤」（`turns: 3`），走完 W1 的 `advanceTo 518 day`，出来还是重伤。

反方向也错：同一时刻连按 5 次「休息」，`turnIndex` +5，重伤按 2 次休息就痊愈，而实际过了 0 秒。
更自相矛盾的是 `state.player.age` 按 `worldTime` 算、补正按指针算——同一个 state 里两套时钟。

旧设计「看起来对」纯属巧合：`world.defaultStep` = 1 day 且六个自由行动全部 `duration: 1 day`。
这是巧合，不是契约。

### 决定

```yaml
# 定义：不带时长
- id: injured-sim
  simulation: { attributeModifiers: { agility: -3, physique: -2 } }
  cureConditions: [{ item: item-antidote }]

# 施加：给世界时间（与 advanceBy 同一套 TimeAmount 词表）
applyStatus:
  - status: injured-sim
    duration: { value: 10, unit: day }
```

实例存**绝对到期点**：

```ts
interface StatusInstance {
  appliedAt: number;   // 施加时的 worldTime（分钟）
  expiresAt?: number;  // untilCured 无此字段 ⇒ 永不到期
}
// 到期 = worldTime >= expiresAt
```

**不需要在任何地方补 tick**：事件把时间推到 +4752 天，下一处读状态时它已经过期。
这不是「把 tick 加到事件里」，而是让「多久」不再依赖「谁推进了几步」。
存绝对分钟也意味着不会因为漏调一次 tick 就永远不过期。

## D3 · 两类东西必须分开

| 类 | 例子 | 单位 | 理由 |
|---|---|---|---|
| **持续状态** | 重伤、咒火、`debt.*` | 世界时间 | 世界观里伤是按天好的 |
| **每回合结算** | `regen`、`moodDeltaPerTurn` | 行动次数（`turnIndex`） | 玩法节奏：每做一个决定结算一次 |

第二类保持按行动计数，但注释必须写明「每**行动**一次」，别再叫「每回合」——
这个词已经被 `turnIndex` 占用了。

## D4 · 战斗域用战斗回合，因为战斗中世界时间不动

战斗是槽内过程，`worldTime` 全程不变。若战斗补正按世界时间算，它**永远不到期**。
所以战斗域只能按战斗回合：`rounds`。

两个域两把尺子，各自量各自的时间轴，谁都不数指针次数。这正是 D2 的推广，不是例外。

```yaml
applyStatus:
  - { status: stun, target: all_enemies, duration: { rounds: 2 } }
```

`StatusApplicationSchema.duration` **必填**，四态：

| 写法 | 含义 | 战后 |
|---|---|---|
| `{ rounds: n }` | 战斗内 n 回合 | 清（`battleOnly`） |
| `{ untilBattleEnd: true }` | 打到战斗结束 | 清（`battleOnly`） |
| `{ value, unit }` | 模拟域时长（「打完后两天内力竭」） | 按 `expiresAt` 留 |
| `{ untilCured: true }` | 永久 | 留 |

不留隐式缺省：静默默认我们已经付过一次学费（`veil`）。模板要省字用 YAML 锚点自己复用。

## D5 · 挂载即永久

`characters.yaml` 的 `statuses:` 与开局 `status` 参数不是「施加」，是**身份**
（`six-eyes`、`infinity`、`tech-*`）。它们造实例时不带 `expiresAt`、不带 `roundsLeft`，
天然是 `untilCured`。这条规则让「定义里没有时长」不产生歧义：
**一个补正有多久，取决于谁把它挂上去的**。

## D6 · `finishBattle` 改判 `battleOnly`

旧的判据是「有 simulation 面，或 `duration.untilCured`」——前者是代理指标，会把
「战斗技能施加的临时 buff」和「带来的长期补正」混为一谈（`exhausted` 就卡在缝里）。

新判据是单一标记：战斗域临时补正（`rounds` / `untilBattleEnd`）造实例时打 `battleOnly: true`，
战后只清这些。带入战斗的补正原样回写，战斗中施加的 `{value,unit}` / `{untilCured}` 也留。

## D7 · `cureConditions.restTurns` → `restDays`

`restTurns`（休息 N **次**痊愈）是同一个「数指针」的毛病。既然时长已经按世界时间，
「静养多久」也必须按世界时间：`{ restDays: 3 }`，`restProgress` 累计**休息行动消耗的分钟数**。

`{ item }` 分支不变。

## 影响与验收

- 删唯一 `DurationSchema`，拆 `SimulationDurationSchema` / `CombatDurationSchema`；
  `StatusEffectSchema.duration` 与 `combat.battleRounds` 移除。
- 实例字段：`turnsLeft` / `battleRoundsElapsed` 移除，加 `appliedAt` / `expiresAt` / `roundsLeft` / `battleOnly`；
  `restProgress` 单位由「次数」改为「分钟」。
- 新增 `pruneExpiredStatuses`，在每个改变 `worldTime` 的位置调用（动作时间步、`advanceBy` / `advanceTo` 效果、轮尾）。
- 模板：定义侧删掉 63 行时长声明（50 条 `duration` + 13 条 `battleRounds`）；技能施加点 77 处、
  事件施加点 56 处补上时长；`jjk-shinjuku` 同步（3 条 `untilCured` + 7 处施加）。
- **协议断代**：`jjk-2006/1.0.0` 与 `2.0.0` 无法满足新 schema，归档到
  `archive/2026-11-19-pre-adr009-templates/`（只留 `3.0.0` 在运行时目录）。
  冻结版不做迁移——给 2.0.0 灌 ADR-009 语义，它既不是 2.0.0 也不再是历史快照。
- 行为变化（有意接受）：挂在角色档案上的 `enrage` / `absorbed-curses` 现在**永久**，
  不再按旧 `battleRounds` / `turns` 中途消失；`cursed-burn` / `curse-poison` 由技能施加时
  按「天」计时，战斗中不再有回合上限（伤害仍在每回合结算）。
- 验收：新增用例「事件 `advanceTo` 跨月后，模拟域补正自动过期」与「时长只跟世界时钟走」。

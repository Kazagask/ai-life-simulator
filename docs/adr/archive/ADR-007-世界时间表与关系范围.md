# ADR-007 世界时间表与关系知情人范围

- 状态：已实施（2026-11-19）
- 影响：`packages/shared`（world / relation / common / v2-state / v2 契约）、`packages/game-core`（turn / engine / projection / relations / opening-dag / extensions）、`packages/rpg-ui`（adapter / RelationList）、`apps/web`（style）、`extensions/family`（全量改用 scope）、模板 `jjk-2006/3.0.0` 与 `jjk-shinjuku/1.0.0`
- 起因：用户两条验收意见 —— ①「2006 年的五条卡上不该有伏黑惠这条关系，他还不是惠的老师；建立关系不该和剧情强相关，应该在协议层有一个通用的事实调度（不占事件槽、无需玩家确认，但真实发生），NPC 生成 / 固定时间 / 效果叠加都走这条管线」②「完全不知道的就不该上屏；现在的可见性是单向给玩家的，将来做玩家切换必须 NPC 与玩家对等，应该是公开 / 部分人知道 / 仅自己知道」

两条是同一件事的两半：**世界事实的成立，与"某个观察者知不知道"，必须分开存。**

---

## D1 · 世界时间表（`scheduledFacts`）

### 问题

「世界自己往前走」在这之前只有两条腿，两条都不对：

1. **写成事件**。`ev-hv-*`（怀玉七幕）就是这条路的典型：关系建立、人要登场，全挂在"玩家选到某个出口"上。玩家没走那条剧情分支，2018 年的世界仍然是 2006 年的样子 —— 五条卡上于是出现一个 15 岁的徒弟（用户报的那个 bug）。
2. **硬编码进引擎**。`npcSpawnRules[].when` 是这种局部特例：只有"让人物登场"能定时，别的事实（关系、旗标、属性）享受不到；语法还长在规则对象里，看起来像刷新机制的一部分。

### 决定

`world.yaml` 增 `scheduledFacts`：一张**世界自己的时间表**。

```yaml
scheduledFacts:
  - id: fact-gojo-takes-megumi
    note: 一年级编成，五条把伏黑惠要到自己名下
    when: [{ time: { gte: { value: 4538, unit: day } } }]
    effects:
      - { type: addRelationEdge, fromId: npc-gojo, toId: npc-megumi, kind: disciple, scope: public, value: 50 }
      - { type: addRelationEdge, fromId: npc-megumi, toId: npc-gojo, kind: mentor, scope: public, value: 60 }
```

语义五条：

1. **不占事件槽、不进历史、不等玩家确认**。玩家看到的是后果（卡上多了一个人、关系行多了一条），不是一条系统通知。
2. **每轮 tail 求值一次**：本轮的结算都已落地、世界时间已经推进到新值，此刻判断"到点没有"与这一轮玩家做了什么无关。
3. **一事实一次**：执行后在 `state.facts` 追加 `{ factId, turnIndex, worldTime }`（append-only），有记录就跳过。存档里这条日志就是"发生过"的唯一凭据。
4. **跳年照常补齐**：条件写成 `time >= N day`，`advanceTo` 一次跨十年也会在下一轮把沿途所有到期事实按顺序执行。
5. **顺序即声明顺序**：同一回合到期的多条按书写顺序跑。`fact-megumi-enrolls` 必须排在 `fact-gojo-takes-megumi` 前面 —— 关系效果有判活检查，人还没登场就建边会被静默跳过。这条依赖靠排列表达，不靠隐式排序。

效果表就是现有的 `EffectSchema`（`spawnNpc` / `addRelationEdge` / `adjustRelation` / `setFlag` / `adjustAttribute` / `setNpcLifecycle` …），**不新造语法**；扩展效果同样可写（`TemplateEffectSchema`）。

### 连带：`npcSpawnRules.when` 删除

登场时点从规则搬到时间表，规则只剩「这个人是谁、登场时几岁」：

```yaml
npcSpawnRules:
  - { id: rule-toji-2006, characterRef: npc-toji, age: 31 }
```

引擎里的 `evaluateSpawnRules` 一并删除。**不保留第二套定时机制** —— 两套同时存在时，"为什么这个人没出现"永远要先问"是哪套没跑"。

`jjk-shinjuku` 的 `when` 是旗标条件（`kugisakiReady`）而非时间，同样改写为一条事实（时间表的 `when` 不限定只能写时间）。

### 加载期校验

事实没有"事件"那层兜底，写错引用就是静默不发生，因此在 `WorldTemplateV2Schema` 的交叉校验里拦：

- `id` 唯一；
- `when` / `effects` 做既有引用完整性检查（属性、资源、角色）；
- `spawnNpc.ruleId` 必须是已声明规则；`addRelationEdge` / `adjustRelation` 的两端必须是已声明角色或玩家。

### RNG

条件与效果各用独立派生流（`scanStream`）：给同一 seed 加一条时间表**不会**改变既有对局的随机序列（测试 `scheduled-facts` 的确定性用例锁这条）。

## D2 · 关系是事实，`scope` 说明"多少人知道"

### 问题

旧字段 `visibility: known | inferred | unknown | hidden` 记的是**玩家视角**下"这条关系看不看得见"。三个毛病：

1. **把观察者写进了事实**。同一条边对不同人应当有不同解释，但事实只有一个；写死"玩家看得见"意味着将来做玩家切换（扮演 NPC、或让 NPC 之间互相打听）时，整张关系表都得重写。
2. **"推断"是确信度，不是可见性**。`inferred` 与 `known` 并列，让"他知道这件事"和"他猜这件事"变成互斥的两档 —— 实际两者正交。
3. **默认值反向**。缺省 `unknown` 是"玩家不知道"，但对当事人双方这条关系完全成立（惠知道甚尔是他父亲，不需要外人知道）。

### 决定

`RelationEdge.scope: "public" | "limited" | "private"`：

| 值 | 含义 | 谁能看见 |
| --- | --- | --- |
| `public` | 大家都知道 | 任何人 |
| `limited` | 部分人知道 | 当事人 + `knownBy` 名单里的人 |
| `private` | 仅当事人知道 | 只有 `from` / `to` |

配套三条：

- **唯一读法** `relationScopeOf(edge)`：`scope` 优先，没有时按旧 `visibility` 折算（`known`/`inferred` → `public`，`unknown`/`hidden` → `private`）。旧存档、旧模板（`2.0.0`、`valmont`）直载，不升 `schemaVersion`。
- **唯一判定** `relationVisibleTo(edge, viewerId)`：当事人必见；`public` 人人可见；`limited` 查 `knownBy`；`private` 其余人不可见。投影、扩展贡献边、展示层都调它，不许各自再判一遍。
- **`limited` 必须写 `knownBy`**（否则等同 `private`），加载期拒载。

### 投影的观察者只有一个：`selfId`

一次投影只回答"**这一个观察者**看得见什么"：`projectVisibleRelations(state.relations, selfId)`。当前 `selfId` 恒为玩家，所以 NPC 卡上的行集合也是"玩家允许看到的那些"——不做逐卡视角，否则玩家能从别人的卡上读到不该知道的私情。

将来切换视角时只换这一个 id（`selfId` 指向 NPC 实例），NPC 卡的行集合随之改变，判定函数一个字都不用改。这就是用户说的"对等"。

### 连带：删掉两条 2018 年的初始关系

`npc-gojo → npc-megumi [disciple]`、`npc-megumi → npc-gojo [mentor]` 从 `characters.yaml` 移除，改由 `fact-gojo-takes-megumi` 在 4538 天建立。初始表只写"世界开局就成立的事"。

### 展示

- 关系行只画**非公开**档（`公开` 是默认，逐行标等于噪音）：`部分人知道` / `仅当事人知道`，虚边样式。
- 词表：`公开` / `部分人知道` / `仅当事人知道`。旧的四档（确知/推断/未知/未明）删除 —— 它们描述的是"玩家有多确信"，而确信度不再是边的属性：玩家压根不知道的关系，不该出现在他的图里。
- 多跳推导行的 `scope` 由构成边**合成**（取最保守一档：任一段 `private` ⇒ 整条 `private`），由 `extensions/family` 负责，不许自己写 `public`。

## 不做的事

- **不做逐观察者的知识表**（`knownBy` 只记"谁知道有这条关系"，不记"谁以为它是什么"）。真需要时再开一张表，别把它塞进边里。
- **不给关系加"确信度"**。`inferred` 删除后没有替代品：只听过传闻的关系，要么按 `limited` 记（"部分人知道"），要么它压根不该存在于玩家的图里。
- **事实不进历史条目**。要留痕就写 `note`（只进后台编排图）。玩家端的时间线是"你经历过的事"，不是"世界背着你发生的事"。

## 代价

- `RelationEdgeSchema` 同时接受 `scope` 与旧 `visibility` 两套写法，直到 `2.0.0` / `valmont` 一起迁移。折算函数是唯一入口，但读代码的人要知道有这一层。
- `extensions/family` 全量从 `visibility` 改到 `scope`（合成改为"最弱环"），语料脚本的旧模板解析保留折算。
- 事实在回合 tail 才求值：**世界创建那一刻不会立刻执行**（`worldTime` 还是 0/开局锚点）。需要"开局即成立"的事实，就用初始声明（`characters.yaml` / `opening`），别写成 `time >= 1 minute` 的事实。

## 遗留（2026-11-19 复核，尚未处理）

**LLM 分支提交仍说旧词表**：`contract/branch-submit.ts` 的 `relationEdge` 必填字段是
`visibility: RelationVisibilitySchema`（四档旧值），引擎侧 `engine-api.ts` 原样翻给
`addRelationEdge`。能跑（`relationScopeOf` 会折算），但意味着：

- 模型**无法表达**「只有当事人知道」——它只能写 `unknown`（⇒ private），写不出
  `limited` + 名单；
- 契约与模板侧两套词表长期并存，读的人要记住两份。

改法（未做，需动 LLM 工具 schema 与提示词，属另一件事）：`visibility` 降级为可选、
新增可选 `scope` / `knownBy`，映射优先级与内核一致。在那之前，**这条链路写入的关系
一律落在 public / private 两档**，不会出现 `limited`。

**另**：`world.ts` 里「效果的关系端点引用校验」目前有两份（`scheduledFacts` 内联一份、
`npcActions` 内联一份），`checkEffectRefs` 只覆盖属性 / 资源。`scope: limited` 缺名单的
检查已放进 `checkEffectRefs`（覆盖全部调用点），但那两份重复的端点校验没合并 —— 属于
重构，不是缺陷。

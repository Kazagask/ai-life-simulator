# 72 · 开局分线：as 数组 / 自建 id / 原作术式池

> 上游：ADR-001（开局 DAG）、ADR-010（演员同构）、ADR-070（本地化）。
> 本卷记录 2026-11-23 用户裁决后的三条改动，以及**刻意不做**的部分。

## 决策

1. **`as` 支持数组**（`string | string[]`，最多 8）：
   - LLM 条件 instruction：`as: [npc-gojo, player-clan-branch]` = self 是其中任意一个；
   - 事件节点级：加载期把数组**炸成多条单值变体**，复用既有 `selfIs` / `selfIsNot` 门控；
     兜底变体对每个 `as` 各挂一条 `selfIsNot`（数组 AND），不会串戏。
   - 两种 `as` 语义相同：只决定「这段给谁看」，不改变文本。
2. **自建角色 id 按出身区分**：`player-civilian` / `player-clan-branch` / `player-curse-family`
   （由 `opening.yaml` 的 `n-origin` 选项写 `who.id`）。加载期 `as` 校验对 `player-*` 放行
   —— 它们不在 `characters` 表里，是运行时生成的 self id。
3. **开局术式池按转盘 JSON 重做**（`archive/2026-11-16-pre-rewrite/specs/data-references/咒术转盘☆第二版.wheel.json`）：
   - 原作术式按出身 **0 基偏置**：御三家旁支 → 十影 / 赤血 / 无下限；诅咒师世家 → 咒灵操术 / 御厨子；
     平民 → 刍灵 / 雷电 / 咒言；
   - 不再以「两个十影」为由排除血继 / 唯一术式；**强度不设上限**，权重只决定「遇到什么」；
   - 没有专属领域节点的原作术式统一走 `n-dom-generic`（通用 `sk-domain-expansion`），
     以后要写专属领域再加节点；
   - 体质池也按出身加偏置（御三家 → 魔虚罗适配；诅咒师 → 毒抗 / 多重灵魂；平民 → 反转 / 广域感知）。
4. **高阶三格按天赋调权重**：`rankFlag` 决定「空签 / 高级签」的概率；天赋越好，实际拿到的
   高阶技巧数量越多。数量仍是概率性的 0–3，**没有**加第四格（DAG 无循环，且不想让低天赋
   多看一次空转）。
5. **`who` 的 4 处写入是刻意覆盖**：`n-self/o-new` 写骨架，`n-origin` 三个选项按出身覆盖成
   `player-<origin>`。`resolveParamMap` 是 whole-object 覆盖，不会丢加成；`inspect check`
   会报一条 `opening-param-overwrite` warn —— 这是预期，不是缺陷。

## 不做 / 下一步

- 未加入的原作术式：无为转变 / 十划咒法 / 不义游戏 / 黑鸟操术 / 投射咒法 / 坐杀博徒 / 术式没收
  （枚举 + 状态 + 技能三处都要补，成本高；先保留 8 条已具备完整定义的）。
- **六眼仍不进池**：它和五条悟、天元的因果绑在一起；放进去会出现「两个六眼」。
- 后续章节分线：本轮用 `as: player-<origin>` 给 `lt.hv-start` 写了三条出身线
  （平民 / 御三家旁支 / 诅咒师世家），并保留无 as 的兜底；怀玉之后的事件分支没有重写。

## 第二波（2026-11-23 下午）：转盘按分支 / 六眼（伪）/ 无下限要主动开

### D3 · 节点前置 `when`（引擎扩展）

旧契约里**选项**没有条件、`goto` 是编译期分流，于是「只有御三家才转传承那一格」写不出来：
要么给所有人看，要么把性别 / 年龄 / 天赋整段抄成三条 lane。后者会让 `years` / `rankFlag`
出现三处写者，`opening-param-overwrite` 立刻变成噪音。

新增节点级前置（`OpeningBranchNodeSchema.when`）：

```yaml
- node: n-heritage
  when: [{ param: originTag, in: [clan-branch] }]
```

- 判据只读**本会话已落定参数**（`resolveParamMap` 同一解包口径），**不看世界状态**——
  开局期还没有 `WorldStateV2`，复用事件条件 DSL 会诱导模板作者写 `flag` / `status`。
- 不成立 ⇒ **整格静默跳过**：跟着它自己的 `goto ?? 下一个` 走，不占步数、不写 `results`、
  不上屏。跳过结算用**写入本步之后**的会话，所以「上一步刚写下的参数」当场生效。
- 加载期校验：`param` 必须已声明且 `kind: flag`（number / points 没有字符串值可比）。
- 守卫：`test/unit/opening-when.test.ts`（4 例：跳过不占步、写入后立刻成立、连跳到底即结束、
  schema 与交叉校验分层）。

### D4 · 术式池拆三段

```
天赋 → 传承（仅旁支）─┬─ inherited → 家传池（十影 / 赤血 / 无下限）
                      └─ broken    → 通用池
       非旁支 ─────────────────────→ 通用池
```

- 家传池**不含** originTag 偏置：能走到那里的人已经付过 34% 的运气。
- 通用池**移除**御三家的三条（以前靠 `originTag` 0 基偏置挡住，现在结构上就进不去）。
- 诅咒师世家 / 平民直接进通用池（咒灵操术 / 御厨子 / 刍灵 / 雷电 / 咒言 + 九系原创）。
- 守卫：`jjk2006-dag.test.ts`「御三家先转传承」扫 160 seed，三条分支都断言到。

### D5 · 六眼（伪）· 观空

- 私设状态 `six-eyes-pseudo`：`attributeModifiers` 与真六眼**完全一致**
  （咒力 +20 / 敏捷 +10 / 智力 +10，combat 三项同值）——它本来就是「同一双眼睛的残影」；
  差别在身份与上限：不入六眼之数、不解锁无量空处、**不能单独**换来天赋无下限。
- 品级 `mythic`（静态彩，不占唯一动虹）；真六眼仍是 `mythic-unique`。
- 进体质池 `b-six-eyes-pseudo`：`base 0` ⇒ 非旁支永不出货；旁支 +4，**抽到无下限 +10**
  （4 → 14，约 4% → 13%）。数值是**一个可调的旋钮**，写在 `opening.yaml` 的 `weightByParam`。
- 六眼描述同时改写（用户给的《长阿含经》引文），宿命线（天元 / 星浆体）写进正文。

### D6 · 无下限要主动开（五条削弱 + 玩家同规则）

- 新技能 `sk-limitless`（无下限）：`target: self`，给自己挂 `limitless-active`
  （`kind: battle`，`evade: 1`，`rounds: 3`），冷却 3 回合。
- **五条悟开局不再带 `infinity`**：`skills: [sk-limitless, sk-gojo-blue, sk-basic-strike]`。
  2006 年他做不到常时展开 —— 这是「削弱」的全部内容，不是改数值。
- 怀玉之后（`scheduledFacts` · 260 天）`fact-gojo-growth` 给他 `sk-reverse-heal` /
  `sk-gojo-red`（赫）/ `sk-gojo-hollow-purple`（茈）/ `infinity`（天赋无下限）。无量空处留到 0 卷。
- 玩家走同一条路：`t-limitless` 只给 `[sk-limitless, sk-gojo-blue]`；赫与茈靠池事件
  `ev-pool-limitless-red`（无下限术式 + 反转术式）；**再加六眼（伪）**才走
  `ev-pool-limitless-void`，多拿 `infinity`。
- 两条事件用 `status: six-eyes-pseudo, present: true|false` 互斥 —— 效果 DSL 没有
  「有某状态才给某效果」的写法，只能拆成两条池事件（这也是为什么条件写在 trigger 上）。
- 木桩新增 `right.statuses` 覆盖：量「有没有某个状态」的差别不该只能回去改模板。
  `test/unit/sim.test.ts` 的两条无下限验收因此显式把 `infinity` 挂回五条。

### 不做

- **投射咒法 / 无为转变等 7 条术式**：本期不做，但不代表以后不做（缺的是枚举 + 状态 + 技能三件套）。
- **六眼本体仍不进池**：会和五条 / 天元的因果冲突；伪六眼是给玩家的那条缝。
- **0 卷的无量空处**：模板只有 2006 单章，等那一章开工再给。

## 第三波（2026-11-23 下午）：输入节点 `input`（唯一一个玩家写字符串的格子）

> 需求：御三家在加点上方给一个「重新命名」的输入框，姓预填；非御三家也生成名字；
> 写了就原样/接在姓后面，没写就随机一个。要求引擎通用（预填 / 说明 / 校验），不是改名特例。

### D7 · 协议

节点（`mode: "input"`，此时不能有 `options`）：

```yaml
- node: n-name
  title: 姓名
  text: ...
  mode: input
  input:
    param: nick            # 必填：写哪个参数（kind: name | flag）
    flag: note             # kind: flag 时必填：写到哪个旗标 id
    prefill:               # string（单候选）或候选数组（按序，第一个命中的胜出）
      - when: [{ param: originTag, in: [clan-branch] }]   # 与节点前置同一套
        require: [playerName]                              # 这些参数必须非空
        text: "{surname}{playerName}"                      # {paramId} 插值
      - text: "{surname}{pick}"                            # {pick}：从 suggestions 抽一个
    suggestions: [透, 恵, 澪, ...]   # {pick} 的池（≤64），按本节点派生的 seed 取，不吃主流
    placeholder: 输入名字
    hint: 姓已经填好；不想用就整段改掉        # 填写说明（引擎不解释）
    minLength: 1
    maxLength: 12                     # 按**码点**数，中文一字算一
    pattern: "^[^<>]{1,12}$"          # 正则源码；加载期编译，运行期整串匹配
    defaultValue: 无名氏               # 空提交兜底（再兜到 prefill；仍空 ⇒ 拒）
```

语义：

- **落点由参数 kind 决定**：`name` ⇒ 裸字符串（写 `player.name`）；`flag` ⇒ `{ id, value }`。
  `attribute` **刻意不支持**：枚举属性只认声明过的选项 id、数值属性不收字符串，
  自由文本写进去就是坏档（要「按选项填」应该用 choose）。
- **预填在 `describeNode` 里结算完**再下发给客户端：候选、`when`、`require`、`{paramId}`、
  `{pick}` 全部变成**一个字符串**。客户端不认识模板语法，也不需要知道候选的存在。
- `{paramId}` 未落定 ⇒ 空串，所以「姓 + 名」这种拼接不需要额外语法。
- `{pick}` 用 `deriveOpeningSeed(seed, openingId, "<node>#pick")` —— 同 seed 同结果，
  **不消耗世界 RNG 主流**（与所有开局 roll 同一条纪律）。
- 校验顺序：trim → 空值兜底（`defaultValue` → prefill）→ `minLength` / `maxLength` / `pattern`。
  失败抛 `opening_input_required | _too_short | _too_long | _pattern`（服务端 400，本地 EngineError）。

会话新增 `initial`：**宿主注入的初始参数**，`resolveParamMap` 以它为底、DAG 结果覆盖它。
服务端与本地向导都把「向导里填的名字」塞成 `{ playerName }`（保留 token），
所以模板可以写 `{playerName}` 而不必让引擎知道「名字」这件业务。

加载期校验（`validateOpeningDag`）：`param` 已声明且 kind ∈ {name, flag}；flag 参数必须给 `flag`；
`pattern` 必须可编译；`minLength ≤ maxLength`；用了 `{pick}` 必须给 `suggestions`；
`{token}` 必须是已声明参数或保留字（`pick` / `playerName`）。

### 模板侧（jjk-2006）

- 新增 `n-surname`：所有人转一次姓（8 个常见姓，御三家不在池里）；
  `when: [heritage in [broken, none]]` ⇒ **传承没断的旁支跳过它**，姓由家传术式覆盖成
  禅院 / 加茂 / 五条。
- 新增 `n-name`（输入格），位置在**加点之前**：御三家 = `姓 + 你写的名字`（没写就转一个）；
  其它出身 = `你写了就原样`，没写就 `姓 + 转一个`。
- 为了让姓氏格能判断「这条路径有没有家传术式」，`n-heritage` 的两个选项**不再 goto**
  （否则会把姓氏格整格跳过去），改由数组顺序 + 节点前置决定跑不跑。
- 天与咒缚整段跳过姓氏与术式（`goto: n-body`）⇒ 只有名没有姓；设定上说得通（族谱上没有这个人）。

### 顺带修的一处假 warn

`openingParamOverwrites` 以前只看结构可达性，不知道节点前置，于是「御三家才跑的那一格」
会被算成与平民的写入冲突（`heritage` / `surname` 各报一条假 warn）。现在把写入拆成
**守卫**（`when`）与**事实**（`set` 里的字符串 flag）：只有「守卫 vs 守卫 / 守卫 vs 事实」
矛盾才算互斥；**事实 vs 事实不算** —— 同一路径上先后写同一个 flag 的两个值，正是要报的覆盖。
守卫用例 `admin-opening-params.test.ts` 两条都还在（真覆盖要报、分叉不报）。

### 自查：这是通用规则，不是世界专属

- 引擎里没有「名字 / 姓 / 姓名池」这些词：只有 `param`、`prefill`、`suggestions`、
  `{token}`、长度与正则。换一个字段（称号、契约名、组织代号）只改 `input.param`。
- `{playerName}` 是**宿主语义**（向导里那一格），不是世界语义；`initial` 本身是任意参数表。
- 姓氏表、名字池、御三家的禅院/加茂/五条全部写在 `opening.yaml`，引擎不认。
- `{pick}` 的随机性与开局 roll 同源（按节点派生），所以「随机一个名字」不会扰动战斗骰。

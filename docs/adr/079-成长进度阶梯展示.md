# 079 · 成长进度的展示：按阶梯，不按上限

> 状态：**已实现**（2026-11-24）。前置：ADR-075 §7（成长型天赋）。

---

## 0. 规则

成长型天赋的进度**不显示 `当前/上限`**（例如 `34/100`），而是按**阶梯**显示：

| 进度 | 显示 |
|---|---|
| 1 | `1/4` |
| 5 | `5/8` |
| 8（最后一阶） | `8/8 已完成` |
| 23（还会继续涨） | `8/8 已完成` |

分子是**当前进度**（到顶后夹在最后一阶的 `at`），分母是**下一阶的门槛**（到顶后等于分子）。

理由：玩家关心的是「离下一阶还差多少」，而 `progress.max` 是一个可能永远到不了的抽象上限 ——
把它当分母，前期永远停在个位数百分比，读起来像没有进展。

## 1. 契约

```ts
// StatusView.progress（ADR-075 的扩展）
{ label: string; value: number; current: number; target: number; done: boolean }
```

- `value`：原始进度，保留给需要精确值的消费者（战评、脚本）；
- `current` / `target`：展示用的阶梯对；
- `done`：已经在最高阶。

投影期算：`current = min(value, 最后一阶.at)`、`target = 下一阶?.at ?? 最后一阶.at`、`done = value >= 最后一阶.at`。
没有 `tiers` 的天赋不产生 `progress`（它本来就没有阶梯可展示）。

## 2. 哪里显示

| 位置 | 显示 |
|---|---|
| **战斗芯片** | **不显示** —— 战中是「现在有什么效果」的时刻，进度是养成数据 |
| 个人页状态芯片 | `黑闪 1/4`（到顶 `黑闪 8/8 已完成`） |
| 状态详情浮层 | 一条进度条 + 同一行文本，`已完成` 时满格 |

战斗里去掉的那一份，是因为它会挤掉真正要看的东西（层数 `×2`、剩余回合），
而这些是**这一刻就要用**的信息。

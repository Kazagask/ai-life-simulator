> 原始记录：`archive/ADR-008-…`、`archive/ADR-012-…`、`archive/ADR-013-…`、`archive/ADR-014-…`、`archive/ADR-016-…`。

**这一层的不变量**

- **一个回合 = 玩家一次行动**：`skill` / `item` / `flee` / `pass`。
- **战斗内的世界时间是常量**：一场战斗不推进 `worldTime`（状态时长因此不会被战斗吃掉，见 ADR-009 D4）。
- **确定性**：同一状态 + 同一指令 + 同一 `rng` 流 ⇒ 同一结果。任何新逻辑都**不许额外掷骰**，
  否则所有后续判定的序列都会平移（ADR-014/016 都是为这条让步的）。
- **战斗状态整体丢弃**：`battle` 结束即丢，所以「下一场满状态」不需要任何重置代码。

## ADR-008 · 命中是两道门，必中是一个词

### D1 闪避是**独立的第二道门**

```
hitCheck（技能命中率，夹 0.05–0.95） → 命中后再掷 evade（1−Π(1−x)，多源合并） → 伤害
```

- `evade` **只挡攻击**，不挡治疗 / 增益 / 施加。
- 多源闪避按独立事件合并（1 − Π(1−x)），不是相加 —— 两个 50% 是 75% 而不是 100%。
- `combat.evade` 与 `hitChance` 是**两个数**，展示层不许合并成一行。

### D2 必中 = `hit: "guaranteed"`

一层词，跳过两道门（命中与闪避都不掷）。天逆鉾靠这一条破「无下限」（`evade: 1`）。

### D3 「忽略对方增益」**不**做成通用词条

只做「必中」。理由：忽略增益要读对方的状态栈，是第二个判定的入口，
而所有已知诉求（天逆鉾、狱门疆）都只需要「这一下一定能打进去」。

### D4 阵营状态把本轮伤害擦掉（已修）

结算顺序曾是「先写伤害、再叠阵营状态」，导致本轮的 `damageDealt` 修正对当回合无效。
现在是「先算修正后伤害，再落地」。

### D5 魔虚罗「做不了」的评估（已被 ADR-012/013/014 兑现）

当年列的四件缺件（第三方阵营 / 战斗内加单位 / 每层适应 / 打不死的判定）现在都在，
只是「打不死」没用开关，而是**回血 + 减免曲线**自然涌现（ADR-014 D3）。

## ADR-012 · 战斗面补齐

### D1 召唤：技能声明，单位从**角色卡**建

`skill.summon: { ref, count, tier, levelScale?, faction?, onSummonerDown? }`。单位经 `buildUnit` 实例化 ——
与开场单位**同源**，不是另一张小数值表。

**技能只定「一次几只」和「这批多强」**（`count` / `levelScale`）；
**场上最多几只由档位规则定**（minion 3 / hero 1，唯一出口 `SUMMON_TIER_LIMITS`）。
技能里再写 `limit` 会被 schema `.strict()` 拒载 —— 上限与召唤数各写一处曾经对不上，
而玩家没有任何办法从界面上看出该信哪个（2026-11-20 用户裁决）。

### D1b 技能目标词表（唯一来源 `SkillTargetSchema`）

| id | 含义 |
|---|---|
| `enemy` | 单个敌人（点谁打谁，缺省敌方首位） |
| `ally` | **单个**友军（缺省自己） |
| `all_allies` | 全体友军 |
| `all_enemies` | 全体敌人 |
| `self` | 自身 |
| `none` | **无目标**：不进目标循环，只跑技能自己声明的部分 |

`none` 不是「对自己施法」：召唤不指定任何人，写成 `self` 会让面板显示「目标：自身」，
读起来像在给自己加状态。

**收灵是 `ally`（单个友军）**：玩家点哪只召唤物就收哪只（`targetInstanceId` 直达
`performRecall`）；不点则按入场顺序收最早的。

### D1c 合法目标（`legalTarget`）：先选目标，再放技能

目标枚举只说明**收件人形态**，不说明「这一发对面前这个人成不成立」。成立与否由
`legalTarget` 声明，**不合法就不能放**（不是「放了没效果」）：

```yaml
target: ally
legalTarget: { summonedBy: self, disableReason: 你只能选中自己的召唤物 }
```

| 字段 | 含义 |
|---|---|
| `summonedBy: self` | 只接受**施放者自己的**召唤物 |
| `disableReason` | 选到非法目标时的解释（UI 作悬停提示，按钮上固定写「不是合法目标」） |

判据是两条，**同一个函数** `legalTargetIdsOf`：
1. **阵营**：`enemy` 只能落在 `hostile`，`ally` 只能落在 `friendly`；
2. 技能声明的 `legalTarget` 谓词。

单一是要害：`canUseSkill`（面板置灰）、`performBattleAction`（服务端兜底）、
投影下发的 `legalTargets`（UI 只做 `includes`）全部走这一份，否则
「面板说能选、引擎拒」或反过来迟早出现。

**没点选 ≠ 非法**：`targetInstanceId` 缺省时，无规则的技能照旧走各自缺省目标（AI、旧调用不受影响）；
有规则的技能要求「至少存在一个合法目标」，否则直接拒。

### D1d 中立对目标判定与敌方同侧

`campsOf` 把 `neutrals` 并进**双方**的 `hostile`：

- 敌方的单体 / 全体技能都能选中并命中它（AOE 也一样）；
- 友方的单体 / 全体治疗或增益**选不中**它（它不在 `friendly` 里）；
- 它自己打全场其余所有人；
- 它不在 `enemies` 数组里 ⇒ 打死它不送胜利。

这是「暴走的东西站在中间抽两边」的唯一实现：没有特判，`legalTargets` 与 `resolveTargets`
都读同一个 `campsOf`。

**召唤参数属于技能，名额属于世界**：`count` / `levelScale` 写在技能行
（`召唤 1 名 · 强度 ×1.0`），名额写 `名额：英雄档共用 1 个位置`；
两者都**不进召唤物面板** —— 面板只回答「它是谁、会什么、带着什么状态」。

战斗 AI 的 `includeTargets / excludeTargets` 直接复用这张表，避免「AI 认识、引擎不认识」。

### D2 两级单位：`minion`（小框）与 `hero`（整行）

名额按**档**统计，不按 `ref` —— 所以「三只杂兵可混编」；更要紧的是**同档共用**：
所有英雄档召唤物一起抢 `hero` 个位置（玉犬站着时召円鹿 = 顶掉玉犬，不是各占一格）。
名额本身是**世界维度**的规则（`world.summonLimits: { minion, hero }`，缺省 3 / 1），
不是每个召唤物一份 —— 技能里写 `limit` 已被 schema 拒载。
档位只是展示与名额，不是数值差异。

### D3 中途加入：`reinforcements`

判定点在 **`roundEnd` 末尾**（`battle.round` 已 +1、新回合尚未开始），所以 `atRound: 3` = 「第 3 回合开始时到场」。
进度存 `battle.reinforcementFires: Record<id, number>`（键缺省用声明下标 `#0`），旧档缺省空表 ⇒ 不重放。
未写 `everyRounds` ⇒ 只来一次；写了则按间隔重复，受 `maxAlive` 限制。
与召唤的区别：**召唤是玩家花资源换兵，中途加入是剧本按回合投放**。

### D4 胜负条件：可声明，缺省逐字节不变

```yaml
victory: [{ kind: unit_down, ref: npc-geto }]
defeat:  [{ kind: unit_down, ref: npc-riko }, { kind: player_down }]
```

| kind | 含义 |
|---|---|
| `all_enemies` | 敌方数组全灭（**胜利缺省**） |
| `unit_down` | 指定角色的**全部实例**倒下（含其召唤物） |
| `survive_rounds` | `battle.round > rounds` |
| `all_allies_down` | 友军全灭 |
| `player_down` | 玩家 `hp ≤ 1`（**失败缺省**） |

任一条为真即成立；**先判胜、后判负**（保留「hp 恰好为 1」的边界行为）。
不写 ⇒ 完全走老的两条 `if`，所以旧事件零漂移。`over` 仍是 `victory | defeat | flee`。

### D5 中立单位：第三方阵营，对所有人敌对

`settle.combat.neutrals[]` → `battle.neutrals`；`campsOf` 把中立并进**双方**的 `hostile`，
它自己的 `hostile` 是全场其余人 ⇒ 三方混战。**不参与胜负**（缺省判据只数 `enemies`）。

### D6 状态层数：`stacksPerLayer`

缺省 `false`（定值口径）。为真时 `damageDealt / damageTaken / hitChance` 乘 `stacks`，
`evade` 走 `1 − (1−v)^stacks`（N 层独立门，而不是 `v × N` 直接捅到 1）。
**只有「每层适应」这类该开**；毒、眩晕这类「层数只影响时长」的保持缺省。

### D7 装备授予技能：`grantsSkill`

`items.yaml` 的装备可声明 `grantsSkill`，加载期校验技能存在。
技能集唯一入口 `playerSkills(state, lookup)` = 角色自带 ∪ 装备授予 ——
`canUseSkill`、投影技能列表、模拟器挑招三处同源（各写一遍就会长出「拿在手上却没有那一招」）。
没有换装指令 ⇒ 不需要运行时卸下路径；下一场自然重算。

### D8 施放消耗修正：`combat.mpCostMultiplier`

累加后 `cost = ceil(base × max(0, 1 + Σ))`。**必须 ceil 不能 round**：
`18 × 0.1 = 1.8 → 2`，用 round 会让某些折扣漂移成「-96%」。
唯一出口 `effectiveCostOf`（够不够 / 扣多少 / AI / 面板价四处同源）。
**不把消耗修正做成属性** —— 它不该被别的效果放大。

### D9 专属资源条（角色级 `resources`）

`characters[].resources{ value, max, label }`，不进 `world.resources`。
`adjustResourceValue` 与战斗道具都认它（上限先问 `holder.resourceMax[key]`）。
上屏要**单独补**：`resourceViews` 只扫 `statusBar` 与 `template.resources`，专属池靠遍历
`player.resourceMax` 的键追加，标签取角色声明的 `label`。

> 原 ADR-012 D9 里的「咒灵数量池」已被 ADR-013 推翻（杂兵改无限）；**能力本身保留**。

## ADR-013 · 召唤协议简化：技能点名 + 英雄永久损失

**没有池子、没有账本。** 这条是整份 ADR 的核心 —— 早先的 `curses` 池是「没法维护几百只咒灵」
的规模压缩，不是通用召唤模型；一旦杂兵无限，稀缺性就由场上 `limit` 表达，池子就没有存在理由。

### D1 协议唯一入口：技能里 `summon` 点名

```yaml
summon: { ref: shiki-gyokuken, tier: hero, count: 1, levelScale: 1.0 }
```

不新增指令、不新增事件效果。**消耗也不写**（只有 `cost` 的 MP）。

### D2 杂兵 = 兵力，不是库存

召唤只花 MP；阵亡 / 献祭都**不回补**；稀缺性只由**按档共享名额**表达（世界规则，不是技能参数）。
名额语义是「同档所有召唤物合计最多几只」；`count: 3` 在站着两只时**补满**第三只（不是拒绝）。

### D3 英雄 = 个体，死了就是没了

阵亡或被献祭 ⇒ `state.lostSummons` 记 `ref`，**本局**不可再召。
`summonLost(state, spec)` 是唯一判定（引擎拒绝 / 面板封印 / 模拟器挑招都走它）。
面板上**照常列出并封印**、写明原因（ADR-015 D3 推翻了早期的「直接不显示」：

> 灰着点不动比没有更让人怀疑 —— 但**说明白**就不一样了，技能页要能回答「我为什么用不了」。

### D4 回收架 `battle.bench`：收回 ≠ 阵亡

收回把单位连同 `hp` / 状态 / 冷却 / `enteredRound` 一起存进 `battle.bench`，同场重召**原样搬回**；
认亲靠 `summonRef + summonedBy`（不是 `instanceId`）。战斗结束整个丢弃 ⇒ 下一场自动满状态。

### D5 献祭：烧场上单位换伤害

`sacrifice: { count: all | N, perTier: { minion, hero } }`：先杂兵、后英雄，**伤害之前结算**，
无祭品 ⇒ `sacrifice_empty`。被献祭的**不进回收架** —— 这是它与召回的唯一区别。
祭品池只含**施放者同阵营**的单位（ADR-016 D3 补：不能拿不受控的魔虚罗当燃料）。

### D6 顺带修掉的真 bug

召唤实例 id 原用 `allUnits().length` 起算 —— 阵亡 / 收回会让长度变短 ⇒ 撞名 ⇒
`writeBack` 把伤害写到别人身上。改为 `battle.summonSeq` 单调计数。

### D7 模板迁移（`jjk-2006/3.0.0`）

夏油 = 献祭流（`sk-summon-curse` 三只杂兵 + `sk-summon-dragon` 虹龙 + `sk-uzumaki` 烧场上单位）；
惠 = 召唤流（`sk-ten-rabbits` 三只脱兔 + 七只英雄式神共享一个英雄位 + `sk-ten-recall` 换手）。
**十影没有 `sacrifice`** —— 它不烧，只换。脱兔用 `sk-shiki-nibble`（fixed 3）而不是
`sk-basic-strike`（fixed 8）：三只兔子不是三个武术家。

## ADR-014 · 未调伏的魔虚罗：中立召唤与适应

### D1 `summon.faction: "summoner" | "neutral"`（缺省 summoner）

neutral ⇒ 进 `battle.neutrals`。敌我不分**不用任何新代码**（D5 的 `campsOf` 已经这么规定），
但**选目标要单独管**（见 ADR-016 D1）。上限统计按**落点阵营**，与召唤者阵营无关（ADR-016 D3）。

### D2 每层适应：不加字段，用 `onRoundEnd` 叠层

- `mahoraga-wheel`：`combat.onRoundEnd` 每回合 `heal: fixed 25` + `applyStatus: mahoraga-adapt`（收件人恒为携带者）；
- `mahoraga-adapt`：`damageTaken: -0.15` + `stacksPerLayer: true` ⇒ 5 层 −75%、7 层归零。

### D3 打不死：同样是数据，不是开关

没有 `unkillable` 标记。不可杀 = **HP 上限 × 减免曲线 × 每回合回血**三者相乘的结果。

### D4 未调伏 ⇒ 不进 `lostSummons`

`markSummonLost` 跳过中立单位：未调伏的它本来不在名册里（调伏才是名册机制）。
记进去等于让惠用一次「同归于尽」就永远少一张底牌 —— 而原作里这一手每次都是再赌一次。

### D5 召回只收同阵营

`recall_empty` 闸门与 `performRecall` 同口径：暴走的式神没有「收回」这个动作，
而「收得回来」正是调伏与否的分界线。

## ADR-016 · 登场即行动 + 满员替换 + 中立选敌

### D1 中立单位从「两边」里挑最该打的那个

`resolveTargets` 不传 id 时取 `hostile[0]`，而 `hostile = [玩家, ...友军, ...敌军]` ⇒ 中立**恒打玩家**。
新增 `aiHostileTarget`：**只对 neutral 生效**，挑血量**比例**最低者。
**不掷骰**（rng 是全场共用一条流，多掷一次所有后续判定都变）。
敌方 / 友军 AI 的 `hostile[0]` 行为一字未动 —— 改了会静默改掉所有既有战斗的手感。

### D2 召唤物在登场的那一回合就行动

`aiTurn` 的「入场当回合不行动」加例外：`summonRef !== undefined`（技能点名召来的才例外）。
**判据取「有没有被点名」而不是「谁加的」** —— 援军没有 `summonRef`，仍旧「到场不动」
（进场即出手会被读成两次行动）。**召回仍然花掉一个回合的行动权**：一进一出正好是「换手要付一次钱」。

### D3 满员是替换，不是拒绝；名额按**落点阵营**算

- `canUseSkill` 删掉 `summon_limit` 闸门，`seal.ts` 对应文案一并删除（「已经站满了」不再是用不了的理由）。
- 还有空位就照旧补满；**一只都塞不下**才替换：最早上场的同档 → `battle.bench`
  （不阵亡、不写 `lostSummons`），新的一批顶上。刚被挤下场的不参与回收架认亲，
  否则满员重召 = 「挪进架子再原样搬回来」（花 MP，场上零变化）。
- **名额与替换池都按 `team = faction === "neutral" ? "neutral" : caster.team` 算**。
  写成 `caster.team` 会让召中立魔虚罗时把它算进「我的英雄档」⇒ 把玉犬顶进回收架
  （用户 02:26 实测）。中立项与友军项各数各的，互不占名额、互不顶替。
- 献祭池、`sacrifice_empty` 闸门、`recall` 闸门同口径（都看落点 / 施放者阵营）。

### 战斗日志与投影的约定

- `battle.log` 是**玩家可见文本**，也是测试的主要断言面（「谁打了谁、掉多少」）；
  新增行为若没有日志，就和「什么都没发生」无法区分。
- 投影只下发**玩家视角**：`combatHints`、敌方 `secrets`、`hidden` 角色永不出现。
- 技能用不了要能被解释：`skillSealOf` / `battleSealOf`（ADR-015 D3），
  **冷却不算封印**（面板已有「冷却 N」）。

## ADR-018 战斗侧 · 驱散范围与战后收尾

### 驱散只看本域

- 战斗域 `cureStatus`（含「清除一切异常 / 增益」）候选集只有 `kind: battle`，
  按 `polarity` 过滤；`neutral` 两个词都不动。
- `talent` / `modifier` **不在候选集**——不是「免疫」，是根本没进名单。
  这也是不加 `invincible` 字段的原因。
- 战斗**不能**删 `modifier`（解咒）：战斗一旦能删世界状态，收场就不再是「丢掉镜像」。
  要表达解咒就在战斗里施加一条 `battle` 中和态，真移除等世界处理。

### 战后：镜像丢弃 + 单向折算 + NPC 回写

`finishBattle` 不再判断「哪些要留」：

1. **玩家**：`state.player.statuses` 战斗期间没被动过（战斗只操作镜像），所以不写回；
2. **战斗态**：随镜像整体丢弃；
3. **折算**：对每个还活着的单位，遍历其战斗态，按定义上的 `toModifier` 兑换
   `duration = timePerRound × max(1, roundsHeld)`，施加到同一演员（`stacks` 沿用）；
4. **NPC 回写**（本轮新增）：`enemies / allies / neutrals` 中，跳过 `summonedBy`（召唤物
   不是世界演员）、跳过 `state.npcs` 找不到实例的（`enemy-*` 这类纯定义永不实例化）、
   跳过非 `alive`；回写 `hp = max(1, hp)`、`mp`、已声明资源。

**死活不写**：`setNpcLifecycle` 仍是唯一入口。打到 0 血 ≠ 剧本要他死（留活口 / 抓活的 /
打成重伤都合法），自动写死会让这些表达不出来，两处写同一件事也必然打架。

### 已退场名册只列英雄档（2026-11-20）

`battle.fallen` 数据层仍然记录所有退场单位（献祭 / 连带消散，供战报与排查），
但**投影只发英雄档**：杂兵是兵力，夏油一场献祭三只就是三张 108/108 的卡片，
把「谁真的没了」淹掉；它们的去向战报里已有「XX 被献祭了」。
英雄档必须留（本局不可再召），且带原因。

### 跳过回合常显 + 名册按阵营上色（2026-11-20）

- **跳过回合常显**：`{ type: "pass" }` 引擎一直支持（不花 MP / 道具 / 冷却，只推进一个回合），
  但过去只在 `cannot_act` 覆盖层里露一个入口。技能全灰、道具被禁、退路封死时，
  面板上就没有任何能点的东西 —— 那不是难，是卡死。现在它与「逃跑」并排常显。
- **已退场名册按单位自己的阵营上色**：名册是混合列表，`BattleEnemy.side`
  （建场 / 召唤 / 援军时写入）随快照进 VM；前端以前写死 `kind="ally"`，
  于是敌方献祭的咒灵是蓝框、中立也是蓝框。缺省（旧档）按中立兜底，不再冒充友军。


### 战斗内**不改属性**（2026-11-20 修正）

一度把 `adjustAttribute` 加进战斗道具白名单（「淬体药：体魄 +1」在战斗里喝下去要生效）。
**已回退**：战斗内调属性会牵动伤害 / 命中 / 血量上限 / 治疗量一大串结算，
不是「+1 就完事」的写入，而且会让同一场战斗前后半段的数值口径不一致。

现在的白名单只有 `adjustResource / cureStatus / adjustMood / applyStatus`；
`adjustAttribute` 的道具在战斗里会被诊断拒绝（`item_effect_unsupported_in_battle`），
模板侧应当把这类道具标成 `usableInBattle: false`。

真正缺的那件事是**世界内加点**（加点组件从没在游戏里用过）——见 ADR-019（`40-属性资源与状态.md`）。

### 原生暴击与钩子（ADR-073，2026-11-23）

战斗现在有第五、第六条随机流：`crit`（暴击）与 `hook`（钩子内掷骰），
它们与 `resolve / ai / target` 一样从每回合根流 fork —— `resolve` 的消费序列一个字节都没变。
数字仍然走 `combat` 的乘区；只有「改流程」的能力（取消、锁血、驱散、暴击后的二次判定）
才写成 `hooks`。三个边界别再踩：

- **`beforeCost` 不存在**：费用判定是 `canUseSkill`（投影/AI）与执行器共用的纯函数，
  钩子带状态与随机，塞进去就会出现两套真相。免费施法用 `costMultiplier: { mp: -1 }`。
- **`hp <= 1` 仍然是败北**：给玩家写 `setHpFloor: 1` 的「不屈」没有意义。
- **天赋不可驱散**：`cureStatus` 的选择器写得再宽也只清 `battle` / `modifier`。

# 40 · 属性、资源与状态

> 覆盖 ADR-003（属性类型与自定义资源）、ADR-009（状态时长）、ADR-011（层数收敛与仪器）、
> ADR-006 D1（施加目标）、**ADR-018（状态三类：talent / battle / modifier）**。
> 原始记录：`archive/ADR-003-…`、`archive/ADR-009-…`、`archive/ADR-011-…`、`archive/ADR-006-…`。
> 展示口径（「战斗中每回合」这类文案）在 `60-表现层与仪器.md`。

**词表（2026-11-20 统一，别再混用）**

| 词 | 代码 | 含义 |
|---|---|---|
| **状态** | `status` / `StatusEffect` / `statuses[]` | 总称：挂在角色身上、持续生效的东西 |
| **天赋** | `kind: talent` | 世界授予与收回；无时钟、不叠层、不可驱散 |
| **修正** | `kind: modifier` | 世界授予与收回；世界时间、可叠、不可驱散（旧称「补正」） |
| **战斗状态** | `kind: battle` | 战斗内授予与收回；回合时钟、可叠、可驱散 |
| **合计** | `PlayerVM.modifiers` | 所有状态对数值的贡献之和（原「状态总值」） |

> 旧文档里的「补正」= 现在的「状态」（总称）；`modifier` 这一档叫「修正」。
> 文件名 `40-属性资源与状态.md` 是历史坐标（原 `…与补正`），不按编号找文档。

**这一层的不变量**

- **属性是「量」**：有效值下限 0，上限只由 `caps` 夹。
- **状态定义不带时长**，时长只在**施加点**；定义只描述效果。
- **`kind` 决定生命周期**：天赋无时钟、战斗态只在战斗里、状态走世界时间（ADR-018）。
- **层数与时长是两件事**：层数由 `stacking` 决定，时长只有一条（`max` 推进）。

## ADR-003 · 属性类型与自定义资源

### D1 属性值 `number | string`，类型由模板声明

### D2 四种 `kind`

| kind | 语义 | 备注 |
|---|---|---|
| `number` | 数值 | 公式 / 条件 / caps 的主力 |
| `enum` | 文本，值是**选项 id** | 展示词与样式归模板（D3） |
| `ladder` | 阶梯 | 两种模式，见 D4 |
| `composite` | 复合，只做展示派生 | 优先序规则表，见 D5 |

### D3 文本属性存选项 id，不存展示词

改文案不动存档；未知 id 在运行期可诊断（不静默写坏档），加载期拒载。

### D4 阶梯两种模式（用户裁决「两种都要」）

```yaml
mode: cumulative   # 缺省：tiers[].at 是累计阈值；升档不减数值
mode: reset        # tiers[].at 是本档升到下一档所需；升档扣掉本档所需、档位 +1（可连升）
```

- `cumulative`：当前档 = 最后一个 `at <= value`；进度 `(value - at) / (next.at - at)`。
- `reset`：**当前档必须落存档**（`state.player.attributeTiers[id]`）—— 同一个数值在不同档位
  含义不同（20/80 与 20/200 无法只靠数值区分）。
- 两种都展示 `value / 本档需求`；最后一档没有下一档时不显示进度条（有 `caps` 则用它当分母）。
- 收获结算：cumulative 用数值差分；reset 升档时展示**档位变化**，不展示被扣掉的数值
  （否则玩家读到「-90」）。

### D5 复合属性 = 优先序规则表

`sources` 必须是数值属性；`cases` 按声明顺序**首个全匹配**生效；`fallback` 必填。
**只做展示派生**，不进条件 / 效果 / 公式（要判就判 `sources`）。

### D6 `hidden` 属性

仍进 state、仍可被效果与条件使用，但**不进属性面板**（`attributeViews` 过滤）。
用于「恶名 / 善名」这种只作复合输入的轴；复合视图带 `sources` 供详情展示。

### D7 数值面只接受数值属性（加载期 fail-fast）

`attributes.caps` / `resources.*.perAttribute` / `mood.bands[].attributeModifiers` /
`statuses[].simulation.attributeModifiers` 引用文本或复合属性 ⇒ 拒载。

### D8 自定义资源

```yaml
resources:
  beans: { base: 5, perLevel: 0, cap: 5, label: 决意 }
```

- 与 `hp` / `mp` 同构：`computeMax` 读**基础属性**；
- `adjustResource` 按 `[0, max]` 夹；技能 `cost` 可引用（D9 ⇒ `not_enough_resource:<key>`）；
- 角色级专属池 `characters[].resources` 不进 `world.resources`（战斗见 ADR-012 D9）。

### D9 技能消耗可引用自定义资源

`cost: { beans: 3 }`；不足 ⇒ `not_enough_resource:beans`，**不扣资源、不进冷却判定**。

### D10 资源条只显示模板声明的段（`statusBar`）

### D11 版本与兼容

新增属性 / 资源都是**可选字段**，不升 `schemaVersion`；旧档直载。

### D12 战斗内每回合回复

按 `base + Σ coef × 基础属性`，结果四舍五入；只写战斗镜像，结束才回写权威资源。

## ADR-006 D1 · 施加点必须自带收件人

`applyStatus` 只写「状态 + 概率」时，收件人靠隐式约定（缺省 = 技能目标 / `onSelf` = 施放者），
两个坑：**推不出来**（领域展开给自己、压制给敌人，两档读不出这件事）；
**`onSelf` 在目标循环里执行**（打三个敌人就给自己叠三层；全闪开时自己那层反而挂不上）。

`StatusApplicationSchema.target` 四档，缺省 `skill`：

| 值 | 收件人 | 走命中？ |
|---|---|---|
| `skill`（缺省） | 技能目标逐个结算 | 是（目标闪开 ⇒ 不施加） |
| `self` | 施放者本人 | 否，只走 `chance` |
| `all_enemies` | 施放者视角全场敌方 | 否，只走 `chance` |
| `all_allies` | 施放者视角全场我方 | 否，只走 `chance` |

`onSelf` 保留为 `self` 的等价旧写法；两者同时出现且指向不同收件人 ⇒ 拒载（不猜优先级）。
`applyTargetOf` 是唯一口径，`applyTargetLabel` 与它同构。
**`combat.onRoundEnd.applyStatus` 只能指向携带者自己**（回合末没有施放者），
加载期拒掉全阵营目标。

已知缺口：「打中了才给自己挂」没有独立表达（写成 `target: skill` 且目标是自己即可，现有模板不需要）。

## ADR-009 · 状态时长

### D1 定义侧不带任何时长

`statuses.yaml` 只描述效果；时长写在**施加点**（`applyStatus.duration` / 技能的 `{rounds}`）。

### D2 模拟域 = 世界时间，实例存**绝对到期点**

`{ value, unit }` ⇒ 施加时换算成 `expiresAt`（分钟），到期靠比较，**不需要 tick**。

**为什么不能数「轮次」**：`turns` 数的其实是「指针推进了几次」，而事件 `advanceTo` 可以一跳 4752 天
（`events.yaml` 里 22 处 `advanceTo` 全在 518–4752 天）—— 一格状态都不缩水。这是本 ADR 从
「搬字段」升级为「换单位」的真正原因。

### D3 两类东西必须分开

**有时长的状态** vs **挂载式身份**（`untilCured` / 一次性授予）。后者「挂载即永久」（D5）。

### D4 战斗域用战斗回合

因为**战斗中世界时间不动**：`{ rounds }` ⇒ `roundsLeft`，每回合末减一。
同一个技能打一场只花一回合的仗，不该让「还剩 2 天」的状态少两天。

### D5 挂载即永久

`untilCured` / 无时长 ⇒ 永久。已永久的实例**不会被有期施加降级**（身份不是「一次施加」）。

### D6 `finishBattle` 只清 `battleOnly`

`battleOnly` 是「谁来清理」的标记，不是时长。战斗结束清掉它，其余状态活到战后。

### D7 `cureConditions.restTurns` → `restDays`

休息的计量单位跟着世界时间（`turnIndex` 不是时间）。

### 再施加的两条规则（ADR-011 D1，与时长强相关）

- **层数**：`stack` 累加 / `unique` 恒定（重复中毒不变成双倍毒伤，只是续期）。
- **时长**：只有一条 `expiresAt`，**数值取 `max`**（只增不减）；形态听这一次
  （带时长 ⇒ 有时钟；挂载 ⇒ 没有）；已永久的不被有期降级。
  取 `max` 而不是「最后一次说了算」：否则一次轻施加会把长状态缩短（`grief` 剩 5 天，
  再施加 3 天 ⇒ 砍到 3）。想缩短只能用 `cureStatus`。
- 战斗域同构：`roundsLeft` / `expiresAt` 各自取 `max`，切换时钟时旧字段删掉。
  迟到的一击必须能把「还剩 1 回合」推回「还剩 3 回合」。

## ADR-011 · 层数收敛与其他

### D1 层数只有两档

见上（`stack` / `unique`，`refresh` 退役）。顺带修掉一处两域不一致：`unique` 的层数，
模拟域锁在首次施加的值、战斗域曾可被更高层数抬上去 —— 现统一为前者。

### D2 数值属性有效值下限 0

状态可以写 `-8`（表达「拿走」），但负数不该进命中骰与伤害公式。
上限仍由 `caps` 管，下限**不开放给模板配置**（没有第二个合理取值）。

### D3 咒力上限只由咒力属性决定

`resources.mp` 从 `{ base: 40 }` 改成 `{ base: 0, perLevel: 5, perAttribute: { cursedEnergy: 2 } }`。
**不做 `cursedEnergy: -999`**：`computeMax` 读基础属性，基础 0 ⇒ 上限 0 已经成立；
而 -999 会顺带打穿 HP（`hp = 75 + 5 × 基础咒力` ⇒ 夹到 1）。

### D4 战斗数值仪器 `pnpm inspect sim`

**不复写任何战斗规则**：只做「建世界 / 摆对手 / 每回合挑技能」，然后交给真实的
`performBattleAction`。所以报告里的数字就是玩家会遇到的数字。
`--as` / `--vs` / `--dummy hp=…` / `--skills a,b,c` / `--stance damage|coverage` /
`--repeat` / `--max-rounds` / `--seed`。实现在 `apps/server/src/admin/sim.ts`。

### D5 世界事实有自己的上屏出口：`tidings`

`tidings` 玩家可见，`note` 不上屏 —— 「NPC 自己长大了」这类事实不该挤进叙事正文。

### D6 范围外（后续那轮已做完）

召唤 / 中途加入 / 胜负条件 / 每层状态 ⇒ ADR-012 补齐，见 `30-战斗.md`。

## ADR-018 · 状态三类（2026-11-20）

> 取代 ADR-009 D4/D6 的「`duration` 一种字段两种时钟」与 `battleOnly` 判据。
> 战斗侧落地（驱散范围 / 战后折算）另见 `30-战斗.md`；面板见 `60-表现层与仪器.md`。

### D1 `kind` 决定谁拥有生命周期

| kind | 中文 | 授予 | 收回 | 时钟 | 可驱散 | 可叠层 | 谁能创建 |
|---|---|---|---|---|---|---|---|
| `talent` | 天赋 | 世界（挂载 / 事件） | 世界（显式收回） | 无 | 否 | 否 | 只有世界 |
| `battle` | 战斗状态 | 战斗（技能 / 回合末 / 召唤配置） | 战斗（回合耗尽 / 驱散 / 收场） | 战斗回合 | 是 | 是 | 只有战斗 |
| `modifier` | 修正 | 世界 | 世界（治愈 / 到期） | 世界时间 | 否 | 是 | 世界 + 战后折算 |

`kind` **必填**。缺省会让「这是天赋还是临时状态」靠猜，而猜错的代价是存档里多一条永远
不会被清的状态。

### D2 `attributeModifiers` 在定义层，不在 `simulation` 面

`effectiveAttributes()` 是模拟与战斗**共用**的入口（`buildUnit` 也走它），属性状态一直
在影响战斗，只是名字写着 simulation。更硬的理由：`battle` 档禁止 simulation 面，
不上提的话「战斗中敏捷 -3」根本没有地方放。

顺带：「至少其一」的范围是 `attributeModifiers / simulation / combat / toModifier`
——天与咒缚这种纯属性状态可以一个面都不写。

### D3 消耗修正按资源，不写死 mp

`combat.costMultiplier: Record<resourceKey, number>`，`cost[key] = ceil(base[key] × max(0, 1 + Σ[key]))`。
key 必须是已声明资源（加载期校验）。旧字段 `mpCostMultiplier` 退役。

### D4 战斗 → 模拟是**单向**折算，写在定义上

```yaml
kind: battle
toModifier: { id: cursed-burn, timePerRound: { value: 1, unit: day } }
```

战后按 `roundsHeld`（实例上的单调计数，回合末 +1）折算：`duration = timePerRound × max(1, held)`，
`stacks` 沿用。**不做世界级转换表、不做 `when`/`chance`**：兑换规则属于这条状态自己，
而胜负不影响结算（败北时玩家也活着）。`roundsLeft` 到期的战斗态不折算（它已经不在身上）。

### D5 时长只剩两种写法

| kind | 施加点 | 实例 |
|---|---|---|
| `talent` | 不许写 `duration`（拒载） | 无时钟 |
| `battle` | `{ rounds: n }`；省略 = 整场 | `roundsLeft` 或不设 |
| `modifier` | `{ value, unit }`（必填） | `expiresAt` |

退役令牌：`{ untilCured }`、`{ untilBattleEnd }`、战斗域的 `{ value, unit }`。
`modifier` **必须**写时长：模拟域没有自然边界，静默默认付过学费；
「永久」这一类由 `talent` 表达。

**自增益的写法陷阱（2026-11-21）**：`roundsLeft` 在**每个回合末**减一，包括施加它的那一回合。
所以「下一击生效」的自身 buff 写 `{ rounds: 1 }` 等于**当回合末就消失**（投影在结算之后，
面板上根本看不到，下一击也吃不到）。要覆盖到下一次行动，必须写 `{ rounds: 2 }`
（本回合末 2→1、下一回合行动时仍在、那回合末 1→0）。
反之，`stun` 这类**当回合就要生效**的 debuff 写 1 是对的 —— 不要为此改引擎的递减时机，
那会让所有控制多封一回合。实例：`sk-black-flash`。

### D6 施加点与 kind 必须同域（加载期）

- 世界 `applyStatus` / `cureStatus`：只能 `talent`（只允许显式 id）/ `modifier`；
- 战斗 `applyStatus` / `cureStatus`：只能 `battle`；
- 挂载（`characters[].statuses` / 开局参数）：只能 `talent` / `modifier`；
- 聚合词（清除一切异常 / 增益）：按域过滤，跨域**静默跳过**（天赋永远不在候选集）。

显式 id 写错域 = 加载期 error；聚合词跨战斗/世界 = 运行期跳过。

### D7 叠层按 kind

`talent` **禁止写 `stacking`**（不是写 `unique`）：再授予同一 id 是幂等，`stacks` 恒 1，
`stacksPerLayer` 也禁写（乘 1 是死配置）。`battle` / `modifier` 必填 `stack|unique`。

### D8 合计：一张账本，一个出口

`modifierLedgerOf(state, lookup, actor)` 产出 `ModifierChannelVM[]`，投影期算好随 `PlayerVM.modifiers`
下发。三条硬规矩：

1. **账本必须就是结算用的那个数**：属性通道的 `total` 取 `effectiveAttributes − 基础值`，
   与战斗/自由行动同一次合成；
2. **含装备与心情**：它们的贡献用「总值 − 状态合计」的**残差**表达（来源名「装备 / 心情」），
   不重算（重算等于把 `equipment.ts` 的条件求值抄第二遍）；
3. **不下发零值通道**，也不下发引擎不认的通道（`simulation.actionEfficiency` /
   `eventConditionTag` 尚未实现，只在协议里保留 + 注释，不上屏）。

### D9 品级是一等字段

状态的品级写 `quality`（阶梯 id），`tags` 由引擎按阶梯自动生成（`tagIdsOf`），
模板不再手写 `tags: [mythic-unique, buff]`。`tags` 机制保留（协议、`ui.tags`、解析都在），
但状态数据已不再使用——语义标签（`buff` / `abnormal`）自 `polarity` 落地后就不再影响任何行为。

### D10 迁移

`jjk-2006/3.0.0` 52 条状态全部加 `kind`（31 天赋 / 12 战斗 / 8 状态，另加 4 条战斗态用于折算）；
16 处战斗域「世界时间」施加改为 `{ rounds }` + 定义上的 `toModifier`；
`toModifier` 的 `timePerRound: 1 天` 让「打两回合留两天」与旧的固定值同量级。
改模板即换指纹，旧档拒载。

## ADR-019 · 世界内加点（2026-11-20）

> 补齐 BACKLOG B-06 的「游戏内触发点」：`PointsAllocator` 此前只在开局用过。
> 开局侧见 `10-开局与角色.md` 的 ADR-004。

### D1 只挂「请求」，不预扣属性

`grantAllocation` 效果往 `state.pendingAllocation` 写一条请求（id / budget / targets / reason），
**一个属性都不改**。属性由玩家在面板里选完、走轮外端点一次写入。

直接 `adjustAttribute` 看起来更省事，但它等于替玩家做了选择，而且绕过了
「这次分几点」的边界 —— 与开局 `allocate` 节点会立刻变成两套语义。

### D2 校验器只有一份

`normalizeAllocation(input, { budget, targets })`（`game-core/v2/allocation.ts`）：
目标白名单 → 非负整数 → 逐项 `min`/`max` → 总和不超预算。开局 `allocate` 节点与
`POST /api/worlds/:id/allocation` 都调它。

两条口径写在这里：**允许放弃余额**（只分一部分是合法选择，二次确认是 UI 的事）；
**`min`/`max` 限制的是这次分到的点数**，不是属性终值（后者是 `attributes.caps`）。

### D3 轮外端点，不推进回合

`POST /api/worlds/:id/allocation` 只写属性、清请求、回快照：世界时间、事件队列、
转盘、冷却都不动。理由：加点是「给自己分配」，与「做了什么」无关；让它推进回合
会把一次加点变成一次行动，玩家要为它付出时间。

请求里必须带 `allocationId`：两笔请求不会同时存在，但玩家可能开着旧页面，
不带 id 就无法判断「这个提交属于哪一笔」。

### D4 同一时刻只挂一条；**同 id 幂等**

不同 id 的第二条 `grantAllocation` 直接抛错（两笔同时挂着时，「点确定」只能靠猜）。
**同一个 id 再来一次直接跳过**：日常池里的事件会反复命中（每次切磋都给 `alloc-spar`），
抛错会让整轮失败，而玩家手里那一笔本来就还没花掉。

### D5 落点是基础属性（叠加，不覆盖）

与开局同口径（ADR-004 D5）：`attributes[attr] += n`，上限按模板 `attributes.caps` 夹。
世界里**不保存**「剩余点数」——提交即结清，留一个余额字段迟早没人对账。

### D6 战斗中拒绝（2026-11-21）

`battle.over === null` 时端点回 `409 allocation_in_battle`，界面在「加点」页签里
只显示一句说明、不渲染分配器。

判据是**快照**而不是"加点有没有用"：战斗单位在开打那一刻就把属性写进 `Combatant`
（`buildUnit`），之后改 `state.player.attributes` 对**这一场**没有任何作用 ——
面板上写着「体质 +2」而血条不动，比直接说「打完再分」更糟。与「战斗中不能换装」
同一条纪律：养成类操作都发生在战斗之外。`over` 非空（已判胜负、尚未清场）允许加点。

`POST /api/worlds/:id/allocation` 同时并入 `withWorldLock`：它与战斗指令都会写
`state.player`，不排队就可能"一边结算战斗、一边改基础属性"。

## ADR-020 · 装备词条：多条、战斗轴、必中（2026-11-20）

> 起因：装备只能挂**一条属性**词条，且**加不出必中**。想给一把刀加「必中」，只能在
> `grantsSkill` 里造一条带 `hit: guaranteed` 的技能 —— 代价是玩家技能栏里凭空多一个招式，
> 而它本质上是这把刀的特性。

### D1 `dynamicModifier` → `dynamicModifiers[]`

一件装备可以有多条词条，属性与战斗轴可混排。旧字段名保留一条**可诊断拒绝**
（`dynamicModifier` → 提示改成数组），不静默丢弃。

### D2 两条词条支线

```yaml
dynamicModifiers:
  - label: 咒力回路                  # 词条名（新）—— 面板上不再只有数字
    attribute: cursedEnergy
    preset: scaled
    params: { base: 4, scaleBy: cursedEnergy, multiplier: 0.2 }
  - label: 贯穿
    combat: { guaranteedHit: true }  # 战斗轴（新）
```

战斗轴字段：`hitChance` / `evade` / `damageDealt` / `damageTaken` / `guaranteedHit`。

### D3 战斗轴与状态走**同一批乘区**

`multiplierOf` / `evadeOf` / 命中判定各自把「状态贡献」与「装备贡献」相加，不是两套公式：

- `hitChance` 加进命中率，最终仍夹 `[0.05, 0.95]`（所以「+100% 命中」到不了必中）；
- `evade` 与状态闪避同一公式（多门 `1-Π(1-x)`）；
- `damageDealt` / `damageTaken` 加进对应乘区；
- `guaranteedHit` **跳过命中骰与闪避门** —— 这才是必中，不能用「命中率 +∞」表达。

### D4 烘进单位快照，整场不变

`equipmentCombatOf` 在 `buildUnit` / 玩家镜像构建时算一次，写进 `BattleEnemy.gear` /
`Combatant.gear`：战斗中不能换装，所以它和有效属性一样是「建场时的一次求值」。
存档里带 `gear`（可选，旧档缺省 ⇒ 空），重载不重算 —— 重算就会和当场打出的伤害对不上。

### D5 类别也有显示名

`equipment.categories: [{ id, label }]`：`category` 是**判定用**的词（槽位
`allowedCategories` 按它匹配），面板不该出现 `cursed-tool`。投影下发 `categoryLabel`，
缺省回退 id。

### 仍缺的（**2026-11-20 裁定冻结**）

> 用户裁定：现有剧本一件装备都用不到这些，**按「先模板后上提」不进内核**。
> **归属已定（2026-11-20 追加）：这些是「养成」不是「事实」，将来做成 `extensions/blacksmith`
> （铁匠），见 `docs/BACKLOG.md` B-23 —— 负重 / 耐久 / 叠层 / 增幅 / 镶嵌 / 附魔。**
> 解冻条件 = 至少一个真实剧本需求（例如咒具耐久影响战斗、被动触发式咒具），先立 ADR 再动协议。

| 缺什么 | 说明 |
|---|---|
| 耐久 / 层数 | `EquipmentInstance.durability/stacks` 字段在，但**没有任何规则读它们**（不掉耐久、不按层数加成） |
| 触发式词条 | 「命中时施加 X」「回合末回血」这类要挂在事件钩子上，现在词条只会改数 |
| `costMultiplier` 词条 | 装备改不了技能价格（状态能）；要做得先把 `effectiveCost` 的来源从「状态」扩成「状态 + 装备」 |
| 套装 / 镶嵌 / 升级 | 需要新的定义层，属产品设计 |
| 战斗中换装 | 现在建场即定死（`gear` 烘进快照），换装要重算整场 |
| 装备授予状态 | `grantsSkill` 有，`grantsStatus` 没有（「戴上就中毒」「戴上就六眼」表达不了） |
| 负重 / 件数限制 | 槽位限件数，但没有重量与总负载 |

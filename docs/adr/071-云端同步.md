# 71 · 云端同步（本地优先的落点）

> 上游：`docs/adr/70-本地化与离线.md`（第三期「去服务化」）。
> 本卷只回答一件事：**本地已经能独立玩了，云端负责什么、怎么负责。**

## 不变量

1. **本地永远是权威**：`WorldStateV2` 在 IndexedDB，云端只是副本。同步失败不影响任何一步玩法。
2. **默认不上传**：只有玩家在档案页显式打开「云端自动同步」才后台上行；手动上传是当次显式动作，
   不经过这个开关（2026-11-22 裁决）。
3. **只在发布域启用**：客户端用 `isSyncOrigin` 收口（实测数据库路径不校验 Origin，但仍按发布域
   收口，避免把会话带到任意源）。未登录不同步。
4. **只有三类东西上云**：模板（同步）、存档（备份）、trace（上报）。其余一律不出本机。

## 分工

| 数据 | 落点 | 说明 |
|---|---|---|
| 模板包 | Postgres `templates.payload` | 整包一格（14 文件 ≈ 235KB）；`publish_template` 做信封校验 + 原子 upsert |
| 存档正文 | Postgres `world_saves.payload` | 与索引**同一行、同一事务**；S3 不存存档 |
| 存档索引 | `world_saves` 的信封列 | worldId / 模板版本 / 指纹 / savedAt / **turn_index** / status / 名字 / 哈希 |
| trace | Postgres `trace_events` | append-only；`save_id` + `save_sha256` 锚到具体那一版存档 |
| 资源（立绘/音频） | 对象存储 | 只放二进制；模板包里的 `assets/manifest.yaml` 只带 id + sha256 |

`world_saves` / `trace_events` / `templates` 都开了 RLS，策略 `visibility = 'public' or owner_id = auth.uid()`
管读、`owner_id = auth.uid()` 管写；`owner_id` 由 `DEFAULT auth.uid()` 填，前端**不发送**该列。

## 客户端

`apps/web/src/cloudSync.ts`：

- `syncAvailability()` → `ok | origin | signed-out`；非 ok 时整条链空转。
- `createSyncQueue`：同键只留最后一条，单条失败不阻断后续。
- `pushSave` 返回 `saveId + sha256` ⇒ trace 上报用它们锚定版本（顺序：先存后报）。
- `listSaves` 只取一等字段（**不下载 payload**）；`pullSave` 才取整档。

`apps/web/src/local/saveList.ts`：本地 + 云端索引的合并与冲突判据。

- 两边都有且 `turnIndex` 不同 ⇒ 冲突，文案「本地与云存档不一致，本地 X 轮，云 Y 轮」；
- 轮次相同 ⇒ 视为已同步（不拿哈希逼用户选）；
- 谁覆盖谁由玩家点，**引擎不自动裁决**。

接线点：

- 模板校验通过 → `pushTemplate`（模板不是存档，不受自动同步开关影响）；
- 本地写档 → `onPersist` → 仅当 `isAutoSyncEnabled()` 才入队；
- 入队发送成功 → `flushTraces(session, { saveId, sha256 })`。

## 档案页（2026-11-22）

登录后的「档案」页多一张**存档**卡片：

- 本地无、云端有 ⇒ 显示云存档（轮次/时间来自 `world_saves`），点「同步到本地」写入 IndexedDB 并直接打开；
- 两边都有且轮次不同 ⇒ 冲突两选一（用本地覆盖云 / 用云覆盖本地）；
- 进行中的档（`status = running`）也能手动上传，不再只限已结束的人生档案。

# 077 · 战斗收尾与战评（停在战场 / 战评面板 / 黑闪成长）

> 状态：**已实现**（2026-11-24）。前置：ADR-075（战评 / 死亡路由 / 成长天赋）、ADR-076（战斗表现层）。
> 本文管三件事：**什么时候离开战斗界面**、**战评在哪看**、**黑闪打出来之后留下什么**。

---

## 0. 不变量

1. **世界不在「最后一击」的那个动作里前移**。判定出 `over` 只算战评并停住，
   玩家点「继续」才收场 / 结算槽位 / 跑死亡路由。
2. **战评只算一次**。`over` 那一刻算好并落盘；`leave` 时直接交给 `finishBattle`，
   不再跑第二遍钩子（否则天赋 / 旗标会重复发放）。
3. **只有真的战败才进死亡路由**。`defeatState` 描述的是「这场战斗的败北形态」，
   死斗里它永远是 `dead` —— 光看它会把「赢下来的死斗」也判死。
4. **黑闪的触发是世界规则，成长才是天赋**。没天赋也能打出来；打出来之后由战评
   创建 / 推进天赋。天赋不再放行任何一击。
5. **黑闪层数不设上限**。一场闪几次就记几点；跨阶的加点合并成一笔。

## 1. 停在战场：`over` → `evaluation` → `leave`

### 1.1 之前发生了什么

`battleActionV2` 判定出 `over` 后，在**同一个请求**里连着做完了：
战评 → `finishBattle` → `state.battle = null` → 结算槽位 → 死亡路由 → `nextTurn`。

于是前端拿到的快照里 `battle` 已经是 `null`：最后一击的轨迹刚起手，整块战斗界面就被
换成了叙事 —— 玩家既看不到收尾，也看不到战评，只看到一行「战斗胜利」。

### 1.2 现在

| 时机 | 做什么 |
|---|---|
| 打出 `over` 的那一下 | `evaluateBattle` 存进 `battle.evaluation`；返回快照，**世界静止** |
| 玩家点「继续」(`{type:"leave"}`) | 战评已有 ⇒ `finishBattle(state, lookup, battle.evaluation)`；槽位结算、死亡路由、`nextTurn` |
| 结束态下别的命令 | 抛 `battle_over`（技能 / 道具 / 空过一律拒绝） |

- `BattleState.evaluation?: BattleResult`：结束瞬间的战果，**持久化**（读档 / 刷新不会丢），
  `leave` 时不再重算。
- `BattleCommandSchema` 新增 `{ type: "leave" }`：**只在 `over` 非空时合法**。
- `BattleView.evaluation` → `BattleVM.evaluation`（复用 `BattleResultSchema`）：前端据此
  把技能区换成战评。

### 1.3 顺手修掉的判定 bug

`applyDeathBoundaryInPlace` 原来的判据是 `battle?.defeatState === "dead"`。
`defeatState` 来自赌注（`deaths` ⇒ `dead`），**胜利时它也是 `dead`** —— 一场死斗赢下来
会被送进死亡路由。现在要求同时满足 `outcome === "defeat"`。

## 2. 战评面板（前端）

`BattleBoard` 在 `b.over` 时不再画技能区，改为 `<section className="battle-eval">`：

- 标题 + 结果（胜利 / 败北 / 撤离）+ 评级（模板声明了 `grades` 才有）；
- 一行数字：回合 / 造成伤害 / 承受伤害 / 暴击 / 击破；
- 逐个敌人的「已击破 · 输出 N」；
- 底部一个**虚线框**的「继续」—— 与「结束这一生」同一套视觉（次要按钮，不是主色 CTA）。

虚线框的语义是「这一屏已经结束了，你随时可以走」，而不是「快点下一步」。

> 战评目前只有这些数：评级体系（打分）还没做，模板也没写 `grades`。
> 面板按「有什么显示什么」实现 —— 加了新字段不用改前端结构。

## 3. 黑闪的成长（数据 + 引擎）

### 3.1 谁放行、谁记录

- **放行**：`world.combat.hooks.black-flash`（世界规则，任何人暴击后按
  `cursedEnergyControl × 0.3%` 掷第二道骰）。
- **记录**：`world.combat.evaluation.hooks.black-flash-growth`：

```yaml
- type: advanceTalent
  talent: t-black-flash
  amount: { metric: statusStacks, status: black-flash }   # 不再夹 max: 3
  create: true                                            # 没天赋的人也能拿到
```

`create: true` 是「没有可成长天赋也能在本战之后获得它」的唯一入口：
第一次打出黑闪时天赋被建出来，阶 1 立刻结算（加点 + 属性面）。

### 3.2 属性面：越闪越容易闪

`t-black-flash` 的三个阶都写 `attributeModifiers.cursedEnergyControl`（4 / 9 / 15，
**累计值**，按面覆盖）。触发率 = 操作 × 0.3%，所以每一阶都在给下一次铺路。

用补正面而不是 `adjustAttribute`：`cursedEnergyControl` 是**派生属性**
（= 总量 × 0.4），派生键不接受直接写值（ADR-074）；阶的 `attributeModifiers`
在公式之后叠加，正好是这条路。

### 3.3 跨阶加点合并

层数不再夹上限之后，一场连闪四下会一次跨过 1 / 4 / 8 三阶。逐阶发
`grantAllocation` 会在单条 `pendingAllocation` 上撞车（`bf-1` 还没分完又来 `bf-4`）。

`advanceTalent` 现在把**本次跨过的所有阶的 `grant` 合并**后只发一次：
`budget` 相加、`targets` 按属性去重、`id` 取最后一阶。
语义上它们本来就是一回事 ——「这一场涨了三阶，一共给你 6 点」。

## 4. 契约变更一览

| 位置 | 变更 |
|---|---|
| `BattleCommandSchema` | + `{ type: "leave" }` |
| `BattleState` / 存档 zod | + `evaluation?: BattleResult` |
| `BattleView` / `BattleVM` | + `evaluation?: BattleResult` |
| `battleActionV2` | `over` 时只算战评并返回；`leave` 才收场 |
| `applyDeathBoundaryInPlace` | 死亡判据加 `outcome === "defeat"` |
| `advanceTalent` | 跨阶 `grant` 合并（加点不再冲突） |
| `t-black-flash` | 阶加 `attributeModifiers.cursedEnergyControl` |
| `black-flash-growth` | 去掉 `amount.max` |

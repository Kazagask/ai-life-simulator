# 078 · 战斗表现的 DSL：样式属于模板，引擎只认积木

> 状态：**已实现**（2026-11-24）。取代 ADR-076 §3.1 / §3.5 里「轨迹 / 受击闭集」的一节。
> 前置：ADR-076（四层 + 级联）、ADR-077（战评）。

---

## 0. 为什么改

ADR-076 把「苍的引力起手 / 黑闪的雷弧 / 十影的法阵」写成了前端 `switch (preset)` 的分支。
后果很直接：**换一个世界就要改前端代码** —— 新写一个世界，它的术式只能长得像咒术回战。

这违反项目的那条老规矩：内核不认识任何具体作品；世界事实只从模板来。表现样式也是世界事实。

所以：**引擎只实现几何，样式由模板用 DSL 拼。**

---

## 1. 分层

| 谁 | 有什么 |
|---|---|
| 引擎（`packages/rpg-ui/src/fx/engine.ts`） | **图元**：环 / 影池 / 光柱 / 射线 / 粒子 / 火花 / 雷弧 / 球 / 弧光 / 割口 / 六边形 / 闪屏 / 遮幅 / 菱形；以及**锚点**（self/hand/ground/target/targetGround/mid/board） |
| 模板（`ui.yaml.presentation.effects`） | 由图元拼出来的**具体样式**：`converge` / `repulse` / `collapse` / `mandala` / `ultimate` / `precision` / `slash` / `lightning` / `cuts` / `shield` |
| 引擎内置的少数几何 | `arrow`（直线箭头）/ `fan`（群体扇刃）/ `updraft`（上升气流）/ `burst`（火花）/ `arrive` / `depart` / `dissolve` / `none` —— 全部**不表达世界观** |

模板可以用**同名 id 覆盖**任何内置项（`effects.burst: ...`），不需要改引擎。

## 2. DSL 形状

```yaml
presentation:
  effects:
    converge:
      kind: cast                # 自检用：cast / trace / impact
      durationMs: 520           # 段的时长（层可以各自覆盖）
      layers:
        - { shape: ring, at: hand, r: 46, width: 2.2, dash: [7, 7], spin: -1 }
        - { shape: rays, at: hand, count: 10, inner: 20, outer: 40, width: 1.6, from: 0 }
        - { shape: motes, at: hand, count: 8, radius: 48, dir: in }
```

- **锚点**全部相对卡片，不写绝对坐标 —— 竖屏 / 横屏 / 管理端的宽度都不一样；
- **时间就是延迟**：`delayMs` 让「先对撞、再出核」这种两拍不需要额外的相位概念；
- **颜色**：层没写就用这一层的语义色（施法色 / 轨迹色 / 伤害色），写了就覆盖；
- **渐变** `gradient: [a] / [a, b] / [a, b, c]`，最多三色（第三色是「亮核」）。
  **方向由图元决定**（环沿直径、柱沿高度、球 / 光晕 / 扇沿半径），模板不写角度 ——
  写角度等于把排版搬进 yaml，换个分辨率就歪。轨迹上的 `[a]` 表示「尾部固定、头部跟随语义色」；
- **两种旋转**：`spin` 只让**虚线流动**（`stroke-dashoffset`），`turns` 转的是**几何**
  （三角 / 扇形 / 刻度）。法阵要「转起来」用 `turns`，地面压扁的圈只能用 `spin`
  —— 椭圆转几何会像盘子翻倒；
- **引用校验**：`preset` 要么是内置 id，要么在 `effects` 里定义过，否则**加载期拒载**。

### 图元一览

| shape | 关键参数 | 用来画 |
|---|---|---|
| `ring` | `r` `ry` `width` `dash` `spin` `gradient` | 光环 / 法阵圈 / 地面椭圆圈 |
| `pool` | `rx` `ry` `blur` `gradient` | 地面影池 |
| `pillar` | `w` `h` `blur` `rise` `core` `gradient` | 上升光柱（`core` = 亮芯占比） |

## 3. 契约变更

| 位置 | 变更 |
|---|---|
| `ui.presentation.effects` | 新增：`id → { kind?, durationMs?, color?, layers[] }` |
| `trace/impact.preset` | 从**闭集枚举**改成**开放 id**（先查 `effects`，再查内置） |
| `FxPresentationSchema` | `superRefine` 校验所有引用（defaults / units / skills / hooks / events） |
| `BattleFxCast.cast/trace`、`BattleFxHit` | 新增 `def?: FxEffect`：投影期把模板定义挂到段上，前端不再查表 |
| 渲染层 | `drawCast / drawTrace / drawImpact` 的 `switch (preset)` 全部删除，只剩「查 def → 逐层画」+ 内置几何 |

`def` 跟着快照走，所以：**前端不需要知道模板长什么样，也不需要认识任何 id**。

---

## 4. 语义仍然在引擎里

搬走的只有「长什么样」。「有没有」和「什么时候」还是引擎的：

- 未命中 ⇒ 轨迹在 62% 处断掉 + 渐隐点，**不画受击**；
- 免疫 ⇒ 轨迹变金线撞向目标；
- 召唤 / 收回 / 献祭 ⇒ 引擎决定用 `arrive` / `depart` / `dissolve`（模板可覆盖同名 id）；
- 施法段「有轨迹就只占前半程、没轨迹就演完整段」的时序仍在 `playCast`。

这三条不是样式，是**语义**：样式可以换，打空了不能画成打中了。

## 5. 视觉质量的三条硬规则（2026-11-24 二改）

第一版的积木能画对形状，但**看着不如设计稿**。差的不是形状，是三件事：

1. **纯色不成光**。环 / 球 / 柱 / 池一律给 2–3 个色标：白核 → 本色 → 暗边。
   纯色圆看起来是贴纸，有渐变才像发光体。`glow` 就是为此存在的（一团没有边缘的柔光）。
2. **环要带散光**。2px 的线在深色卡片上只是「一根线」。引擎给每条 `ring` / `polygon`
   自动叠一层「加粗 3 倍 + `blur(4px)` + 0.34 不透明度」的同形光晕 ——
   加粗会糊掉细节，加光晕不会。这一层是**引擎行为**，模板不用写。
3. **主次分明**。12 根一样粗的光条 = 蒲公英；4 根粗的 + 8 根细的 = 日轮。
   设计稿里每个术式都只有 1–2 个「主体」，其余是陪衬。

另外补了两类**过渡**：`polygon`（法阵的三角骨架）和 `fan`（扇形扫光）。
召唤落地因此有了设计稿的「转出来」：光柱保留，外加两片 180° 对置的扇形边转边亮。
扇光要绕**卡片中心**转，绕脚下会变成两盏探照灯，直接打到下一张卡上。

## 6. 位置纪律：一条线由三个点决定（2026-11-24 三改）

一次改错的教训：**别动轨迹，动两端**。

| 症状 | 根因 | 规则 |
|---|---|---|
| 施法画在卡面中间，轨迹却从右下角冒出来 | 起手改到了 `self`，轨迹起点仍是 `hand` | 起手锚点跟轨迹起点写在**同一处**（`hand`）。想换起手位置，就连轨迹锚点一起换 —— 只换一头就是断开 |
| 轨迹被改短、整条线塌成一小截 | 把落点从「宽度 30%」改成了卡面中心 | 落点决定**跨度**：`rect.x + rect.w * 0.3`、垂直居中。中心点只在正方形小卡上凑巧一样长 |
| 刃插在 A 处、爆点在 B 处 | 轨迹终点用 30%，受击图元用 `at: target` → 卡面中心 | 受击点与轨迹终点**用同一个算式**，通过 `FxAnchors.impact` 传下去；`rect` 仍是整张卡（割口、登场光环要真实宽度） |
| 黑闪「手上炸一次、身上炸一次」 | 起手与受击的星芒长得太像，数量还一样 | 起手**可以保留**（那是「蓄」的一瞬），但受击层要更重（星芒 + 雷弧 + 光环 + 闪屏），两处一眼能分清主次 |

`castOriginOf` 那版实现（轨迹跟着 cast 锚点走）已经删掉：它让模板改一个 `at` 就悄悄改掉
整条轨迹的跨度，属于「参数在别处生效」—— 比它解决的问题更麻烦。

## 7. 语义色是一张表，不是「红绿两人转」（2026-11-24 四改）

以前只有两档：治疗绿、其余红（增益借用伤害红）。收灵落到「其余」里，被染成
**伤害红** —— 这不是配色偏好，是把「收回自己的东西」显示成「打了他一下」。

现在的表（`SEMANTIC`，`presentation/fx.ts`）：

| 事件 | 色 | 说明 |
|---|---|---|
| 伤害 | `#FF6B7F` | |
| 治疗 | `#58E3A7` | |
| 增益（正向） | `#FF6B7F` | 用户 2026-11-23 裁决：与伤害同色，靠符号区分 |
| 减益（负向） | `#B387FF` | |
| **献祭** | `#B387FF` | 烧自己人换伤害 |
| **收灵 / 召唤 / 其它** | `#6FA8FF` | **兜底蓝**：既不是伤害也不是治疗也不是增益 |
| 未命中 | `#A0A8B8` | |
| 免疫 | `#E6C97A` | |

配套两条数据修正：

- `depart`（收灵）以前 `trace = none`（和召唤一样「登场即到达」），所以收灵**没有轨迹**。
  现在它有箭头，并且带 `reverse: true` —— 方向是**目标 → 施法者**，因为它是「把东西拉回来」。
- 收灵的受击用 `cage`（铁栅栏）：横梁先定位，竖条一根根砸下来。收灵不是「打一下」，
  是「关起来」，`rays` 表达不了横梁和节奏。

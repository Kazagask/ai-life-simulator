# ADR-001：前实例化开局与 self 完整切换

- **日期**：2026-11-18
- **状态**：**接受**（2026-11-18 用户裁决 D-1..D-5，见本节末「裁决结果」）
- **关联**：`specs/iteration-2026-11-18-random-opening/`
- **背景**：旧 `docs/DECISIONS.md` 已整体归档到 `archive/2026-11-16-pre-rewrite/`；本 ADR 是新体系第一份。

## 背景

现行开局有两处硬伤，都是"开局发生在世界实例化之后"造成的：

1. **身份与实例同时就位**：`createWorldV2` 一开始就定 `player.name`、性别、年龄，NPC/关系/时间锚
   全部实例化；13 步创建是 `events.yaml` 里的普通 `source: chain` 事件，每步 `choose` 推进
   `turnIndex`。等身份定完，世界已经跑了一段。
2. **名字与角色不一致**：存档列表直接显示建局时填的 `playerName`。新宿剧本选"扮演五条悟"后
   玩家仍能自己起名，`setIdentity` 又没有 `name` 字段——结构上就不可能让开局改名字。
   而 `selfId` 指针目前只接了关系面（`actors.ts` 明确写"玩家存储没有切换"），投影末尾仍用
   `state.player` 覆盖 self 条目，战斗也写死 `state.player`。

用户诉求：开局像转盘一样多次 roll、可混合选项、复用 branch(DAG) 形状、**前实例化**，
名字可空可后改；并明确"能前实例化最好，不能就要打一堆补丁（NPC 生成、事件冻结）"。

## 决策

### D1 开局是世界的生成参数，不是世界内的事件

开局在一套**前实例化会话**里跑：一段连续的 branch DAG，节点为 roll / choose / allocate。
`commit` 之前不存在 `WorldStateV2` / NPC / delayQueue / 事件槽；`commit` 一次建世界并写入结果。
`turnIndex` 全程为 0，不存在"进游戏后又拿到开局天赋"。

### D2 不引入 Draft，不重放 effect DSL

会话只记 `results`（`{ nodeId, optionId?, rollIndex? }`），不记中间世界状态、不需要单独的
Draft schema 或 zod 校验空引用。`commit` 时一次 `createWorldV2`，再按参数表的落点直接写状态。
好处：绕开"27 种 effect 变体作用在完整世界上"的复杂度，也不怕效果引用还不存在的 NPC。

### D3 引擎持有封闭参数表；参数分基本 / 附加两类

- 参数类型与落点注册在 core，模板只声明用哪些、约束、展示提示。值形状扁平（否决 ActorRef
  式 `who` 嵌套）——"参数越简单越好，引擎做推理"。
- **基本属性**（name/gender/age/基础属性 set）：定义"你是谁"。self 复用已有人物路径时
  **整组取自该角色、不读开局参数**；self 为新建时才从开局参数读。
- **附加属性**（status/skill/item/relation/flag/points/属性 add/sub）：在基线上加减，两种 self 都叠加。
  `status` 的值可为 `statusId` / `statusId[]` / `{ id, stacks? }`，commit 时一次性写入 self actor，
  沿用模板里的 `duration` / `stacking` 定义。**`mood` 不入闭集**：原 13 步的 `adjustMood` 在模板重写时
  移除，心情继续由世界默认档位决定。
- `time`（值 `{ value, unit }`）是**开局时间锚**：替代旧 13 步的 `advanceTo`，由模板声明、
  引擎用时间适配器换算并一次写入 `worldTime`。它不是世界内 effect DSL，也不参与轮次推进。
- v1 闭集：`self / name / gender / age / attribute / status / skill / item / relation / flag / time / points`，
  另设 `extensions` 保留字段给 RPG 扩展。移除 `character` 与 `npcSpawn`（新人物固定实例化、
  不进刷新规则）。
- 术语统一为**基本属性**（不是"自身属性"）。

### D4 self 完整切换

`selfId` 可指向任意角色；扮演剧本人物时，基本属性取自该角色实例，不再由建局请求的名字覆盖。
`state.player` 作为 **self 的唯一权威实体**（`id = selfId`），被复用角色不重复进 `npcs`——
这样投影、战斗、关系图都跟着 self 走，且没有双份状态需要同步补丁（实施说明见本节末）。
这是 D3"基本属性按 self 推理"与本轮前置 `as` 角色分派（`selfIs` 条件）生效的前提。

**角色分派的正确形状（2026-11-18 用户纠正）**：`as` 是 **branch 的 node 级语法**，不是 option 级。
同一 `node` 别名写多份、各带不同 `as` ⇒ **同一节点按当前 self 呈现不同正文与整套选项**，天然互斥。
初版误做成"某些选项只对某些角色可见"（option 级 `as`），那用条件 DSL 就能表达，不是本需求；
已返工为 node 级变体。多变体必须有兜底变体；加载期展开变体事件，as 变体带 `selfIs`、兜底带一组
`selfIsNot`（逐条 AND），并给 `goto` 与外部入边生成同形选项的 self 门控，玩家仍只看到一条、不额外占轮次。
**首节点也允许 `as`**（2026-11-18 追加裁决：共用触发器、首节点就不一样，彻底 close 不留遗留）：
多变体首节点共用父 trigger，兜底沿用父 id（外部引用零改动）；random/combat 的 nextEventId 指多变体
首节点 ⇒ 加载期拒载。LLM 侧不开放 `as`。

### D5 名字可空、开局后可改

建局请求 `playerName` 改可选；`setIdentity` 加 `name?`；提供玩家改名端点。
留空显示占位 **"无名氏"**（本轮统一口径）。

### D6 随机源按节点派生，不消耗主流

开局 roll 用 `derive(seed, openingId, nodeId)` 纯派生，不推进世界 RNG 游标；建世界仍用原 seed。
同 seed + 同选择序列 ⇒ 同一世界；中间插删步骤不挪动后续骰子。延续"抽到即认、不可重抽"。

### D7 明确不做

- 不新增第四种 `settle kind`（世界内加点另走轮外操作端点，复用同一 AllocationSpec 校验器）。
- 不重建 `taskDag`，不新增阶段/生命周期状态机。
- LLM 不参与开局决策；`submitBranch` 不开放 opening 参数与 `as` 字段。
- 不引入"放弃转盘 / 重抽"入口。

## 后果

### 正面

- 开局效果与进世界后的规则彻底切开：不需要 NPC 生成补丁、事件冻结补丁。
- 扮演剧本人物时身份一致：存档名 = 角色名，改名走显式入口。
- 前实例化让"开局参数"成为一等概念，未来的加点、自定义开局、跨模板验证都挂在同一机制上。

### 负面 / 代价

- **破坏性**：self 存储切换是核心数据模型变更，字段语义改变；D-3 裁决**升 `schemaVersion = 5`**，
  v1–v4 旧档一律拒载，须如实告知用户。这是本项目"默认发线上"策略下的一次明确代价。
- 改动面跨 shared / game-core / server / web / 模板五层，是大工程；必须逐任务（T1..T6）推进。
- 会话是新的 server 资源类型，需要持久化与清理策略（超时/孤儿会话）——本 ADR 只定方向，
  细节留 T4。

### 风险与缓解

- 投影里 self 覆盖逻辑（`projection.ts:419-434`）与战斗 HP/MP 来源（`battle.ts:44-56`）是
  写死点，切换时逐一改读 `actorOf(selfId)`；用定向用例锁定"默认 selfId 逐字段不变"。
- 关系边 `to: player` 的归一化已统一到 `selfId`（`turn.ts:225-230`），此项风险低。
- `as` 语法在 T2 之前运行时无效（selfId 恒为 `"player"`）——T2 已完成（见下「实施说明」），
  现在 `selfIs` 随 self 移动生效，模板可以放心写角色分派。

### 实施说明（2026-11-18，T0/T2 已落地）

- **T0 返工 1**：node 级 `as` 变体取代 option 级 `as`（见 D4），只改加载期展开与 `selfIs` 原语，
  不动运行时调度；本次修正**记在 ADR-001 内，不另开 ADR-002**。
- **T0 返工 2（首节点 as）**：放开首节点 `as`；新增对称原语 `selfIsNot` 供兜底变体排除所有 as
  （chain 出队终判若不排除会与 as 变体同时成立）；外部 `nextEventId` 指向多变体首节点父 id 时
  在加载期展开为 self 门控入边，random/combat 入边拒载。运行期语义在 `test/unit/self-gate.test.ts` 锁定。
- **T2 落点修正**：原计划"玩家进 `npcs[selfId]`、`state.player` 退化为别名"会引入 130+ 处读取点
  与双份状态的同步风险。实际实现改为：`state.player` 继续是唯一权威 self 实体，`id = selfId`；
  `createWorldV2({ self: { kind: "reuse", characterId } })` 用角色模板的身份/属性/技能初始化它，
  并把该角色从 `npcs` 中排除（不重复实例化）。效果等价且没有补丁：`selfIs`、投影、战斗、关系
  图都指向同一个 actor。`schemaVersion = 5` 照裁决执行。

## 裁决结果（2026-11-18 用户拍板）

1. **D-1**：self 完整切换是**第一步实施**，先做好才做后面。
2. **D-2**：本轮只做开局重构；另加**天内理子短线**验证原著人物新 branch 语法（两个 badend、
   必然活不到十二年后）。主线 chain 不改。
3. **D-3**：**schemaVersion 升 5**，v1–v4 旧档拒载（发布时如实告知代价）。
4. **D-4**：**不支持 `weightBy`**。开局期未实例化 ⇒ 补正/最终面板无法计算，世界属性加权复用不了；
   后续需要以新增开局字段扩展 + 保留位方式增加，**落 backlog**。
5. **D-5**：允许开始时没有名字，本轮一律按 **"无名氏"** 处理。
